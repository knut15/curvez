## preemie-calc

> 출처: `apps/preemie-calc/docs/SPEC.md` (확정, 버전 6, 갱신 2026-10-02) §2 F1~F8·F10·F13~F18, §6 비기능 요구. `apps/preemie-calc/docs/PRD.md` (확정, 버전 4, 갱신 2026-10-02) 머리말·§2·§4·§5·§7·§8·§9.
> 이 절은 SPEC 을 옮기기만 했다. 새 요구는 없다. SPEC 과 이 절이 다르면 SPEC 이 맞다.
> 수용 기준 예시는 모두 같은 아이다. 출생일 2026-03-01, 출산 예정일 2026-04-26, 재태기간 32주 0일 (SPEC 머리말).

### 목표

출생일과 출산 예정일을 한 번만 입력하면 성장, 발달, 예방접종, 검진, 지원 제도를 모두 "출생 기준 / 교정 기준"으로 나란히 보여준다 (PRD §2 원문).
버전 3 에서 프로필 없이 검색으로 들어온 사람이 읽을 공개 가이드(F16 질문형 가이드 6쪽, F17 가이드 목록 페이지, F18 "어느 나이를 쓰나" 공개판)가 더해졌다 (PRD 버전 3 머리말).
이번 범위는 1단계(F1~F8, F10, F13~F18)다. 1단계는 아래 수용 기준이 모두 통과하면 끝난다 (PRD §7).

### 사용자 흐름

PRD §4 핵심 흐름을 옮겼다. PRD 버전 3·4 에서 §4 는 바뀌지 않았다.

1. 부모: 검색이나 카카오톡 공유 링크로 들어온다.
2. 부모: 첫 화면에서 출생일, 출산 예정일, 성별을 입력한다. 출산 예정일을 모르면 출생 주수+일로 바꿔 입력한다.
3. 시스템: 가입 없이 10초 안에 대시보드를 보여준다. 오늘 생후 ○일·○개월과 교정 ○일·○개월이 나란히 나온다.
4. 부모: 대시보드에서 "어느 나이를 쓰나" 안내, 영유아검진 도우미, 본인부담 경감 종료일로 이동한다. 시스템은 각 결과 옆에 어느 기준을 썼는지 적는다.
5. 부모: 프로필을 기기에 저장한다. 다음에 들어오면 시스템이 입력 없이 오늘 기준 값을 보여준다.
6. 부모: 결과를 카드로 만들어 카카오톡으로 가족에게 보낸다. 가족(조부모 등)은 받은 카드를 본다.

공개 가이드(F16~F18)로 들어오는 흐름은 PRD §4 에 따로 적혀 있지 않다. 동작은 아래 F16~F18 의 SPEC 원문(프로필 없이 읽힘, 계산기로 연결)이 정본이다.

### 수용 기준

표 읽는 법:

- `SPEC 원문` 칸은 SPEC §2 의 문장을 그대로 옮겼다. 숫자·날짜·따옴표 문구를 바꾸지 않았다. SPEC 파일에 `\~` 처럼 마크다운 이스케이프로 적힌 글자도 그대로 두었다.
- `확인 방법` 칸은 SPEC 의 "확인 방법" 줄을 AC 별로 나눠 적었다. SPEC 이 종류를 정하지 않은 곳은 "자동 테스트" 로만 적었다.
- 예외는 `PC-F<번호>-EX<번호>` 로 따로 모았다. SPEC 은 예외별 확인 방법을 정하지 않았다.
- 개수 확인: AC 는 `grep -cE '^\| PC-F[0-9]+-AC[0-9]+ \|'` 로 71건, 예외는 `grep -cE '^\| PC-F[0-9]+-EX[0-9]+ \|'` 로 14건, 비기능은 `grep -cE '^\| PC-NF-[A-Z0-9]+-[0-9]+ \|'` 로 11건이 나와야 한다.
- SPEC 버전 3 과 다시 대조한 결과, 버전 2 에서 옮긴 AC 55건·예외 13건은 문장이 하나도 바뀌지 않았다. 버전 3 에서 새로 생긴 것은 F16·F17·F18 뿐이다.
- SPEC 버전 5 와 다시 대조한 결과, 버전 4 에서 PC-F1-AC7 이 새로 생겼고, 버전 5 에서 F18 "무엇을 하는가" 의 5개 항목이 바뀌었다(PC-F18-AC1 이 가리키는 목록). 나머지 AC 68건·예외 14건은 문장이 바뀌지 않았다.
- SPEC 버전 6 과 다시 대조한 결과, F5 에 PC-F5-AC6·AC7 이 새로 생겼고 F5 의 확인 방법 줄이 바뀌었다. 나머지 AC 69건·예외 14건은 문장이 바뀌지 않았다(PC-F8-AC3 포함). AC6·AC7 의 근거는 PRD 버전 4 §9 결정 표의 "미결 2 경감 구간 경계" 정정이다 (아래 "PRD 미결 연결" 참고).

#### 비기능 (SPEC §6 중 모바일·프라이버시·의료 면책·접근성)

`SPEC §6 원문` 칸은 §6 표의 한 칸을 요구 하나씩 나눠 옮겼다. SPEC §6 에는 확인 방법이 없다. 그래서 `확인 방법` 칸은 "제안" 으로 적었고, `curvez-qa` 가 바꿔도 된다. 수용 기준과 같은 요구는 `같은 요구` 칸에 적었다.

### 범위 밖

- F9(2단계), F11·F12(3단계)는 이번 범위가 아니다 (SPEC §1 단계 칸, PRD §5).
- SPEC §6 의 성능·첫 결과·신뢰·광고 요구는 이 절에 옮기지 않았다. 버전 2 라운드 지시가 모바일·프라이버시·의료 면책·접근성만 옮기라고 했고, 버전 3 라운드도 비기능은 기존 11개 ID 를 대조만 했다. 요구 자체는 SPEC §6 에 그대로 있다.
- SPEC §6 의 레이아웃 행(글 영역 최대 폭 720px 한 열)과 PRD §9 결정 표의 "본문 폭" 행은 옮기지 않았다. 버전 2 라운드 지시가 요구가 아니라 디자인 결정으로 보고 옮기지 말라고 했다. 요구 자체는 SPEC §6·PRD §6 에 그대로 있다.
- F13 조합 페이지의 접종 안내는 넣지 않는다 (PC-F13-EX1, PRD §8 가정).
- PRD §5 "이번에 만들지 않는다" 의 kid1004 나머지 기능(월령가이드, 발달체크, 수면, 질환·대처, 병원·약국, 기질검사, 선물추천, 문장 검색)은 이번 범위가 아니다 (PRD §5 원문).

### PRD 미결 연결

PRD §9 미결 중 1단계 기능에 걸린 것과 2026-09-30 결정을 옮겼다. 해석하지 않았고, 정본은 PRD §9 다.
`표기` 칸은 이 문서와 코드가 이미 쓰는 번호(PRD 버전 1 §9 행 순서)다. 버전 2 에서 버전 1 의 4번 행(28주 미만 백분위)이 결정돼 빠졌으므로 PRD 버전 2 §9 표의 행 순서와는 5번부터 하나씩 어긋난다. 그래서 `PRD v2 행` 칸을 따로 두었다. 버전 2 에 새로 생긴 두 행은 번호 대신 이름으로 적었다.
