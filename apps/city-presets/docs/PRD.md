# PRD — 도시 필터 : 사진 한 장을 열두 가지 무드로

> 이 문서가 제품 정의의 정본이다. 실행 계획은 [GOAL.md](GOAL.md) 가 정본이다.
> 처음 쓴 날 2026-09-11. Obsidian 볼트(`Studio-Curvez/아이디어/`)에도 같은 글이 있지만,
> 앞으로는 이 파일을 고치고 볼트는 읽기용으로 둔다.

사진 한 장에 열두 가지 색을 거는 프리셋 묶음이다. 도시 이름은 **찍을 장소가 아니라 색의 이름**이다. 삿포로는 삿포로에서 찍은 사진이 아니라, 어디서 찍었든 겨울 맑은 날의 공기로 보이게 만드는 색이다.

사용자가 하고 싶은 일은 하나다. **자기가 찍은 사진을 그날의 기분에 맞는 무드로 바꾸는 것.** 여행을 다녀오는 것이 아니다.

## 0. 목표와 성공 기준

|             |                                                                                                |
| ----------- | ---------------------------------------------------------------------------------------------- |
| 푸는 문제   | 찍어 둔 사진을 그날 기분에 맞는 무드로 바꾸고 싶은데, 색을 직접 만질 줄 모르거나 만지기 귀찮다 |
| 사용자      | 자기 사진을 인스타에 올리는 사람. 사진이 취미지 직업은 아니다                                  |
| 목표        | 사진 한 장에 걸어 보고 고르기만 하면 되는 색 열두 개                                           |
| 성공 기준 1 | 기준 사진에 열두 개를 걸었을 때 두 장씩 나란히 놓고 **이름을 맞출 수 있다**                    |
| 성공 기준 2 | 무료 여섯만으로 사계절·흐린 날·저녁이 커버된다                                                 |
| 성공 기준 3 | 미리보기에서 본 그림이 구매자 사진에서도 재현된다                                              |
| 성공 기준 4 | 사진 아래에 찍힌 값이 실제 적용값과 한 군데도 어긋나지 않는다                                  |
| 성공 기준 5 | **사진이 사용자 기기 밖으로 나가지 않는다.** 폰에서도 마찬가지다                               |

**돈을 많이 버는 것은 목표가 아니다.** 직접 만들어 보는 것과 예쁘고 깨끗하게 나오는 것이 목표다. 그래서 매출 지표를 성공 기준에 넣지 않는다.

## 1. 무엇을 파는가

**프리셋 파일 묶음이 아니라 도구다.** 사용자가 하는 일은 넷뿐이다.

1. 사진 하나를 고른다
2. 도시 하나를 고른다 — 예를 들어 도쿄
3. 색이 걸린다
4. 받아서 저장한다. 끝

라이트룸을 깔 필요도, 프리셋 파일을 가져올 필요도, 값을 옮겨 적을 필요도 없다. 그 셋을 없애려고 만든 도구다.

|           |                                                         |
| --------- | ------------------------------------------------------- |
| 물건      | 브라우저에서 도는 색 보정 도구. 색 열두 개를 담고 있다  |
| 이름 규칙 | 도시 이름. 각 도시가 특정 날씨와 시간대의 빛을 가리킨다 |
| 받는 것   | 색이 걸린 사진 한 장. 원본 해상도 그대로                |
| 무료·유료 | 절반은 무료, 절반은 유료                                |

도시 이름을 쓰는 이유는 색을 말로 설명하지 않아도 되기 때문이다. "청회색 저대비"라고 하면 아무도 모르지만 "오슬로 새벽"이라고 하면 그림이 그려진다. 열두 개를 모으면 필터 묶음이 아니라 여행지 목록처럼 읽힌다.

## 2. 무엇이 아닌가

**도시에 가서 찍는 것이 아니다.** 처음 정리할 때 이 지점을 잘못 잡아 도시 열두 곳의 풍경 사진을 만들었다. 전부 쓸 데가 없었다 — 사용자는 그 장소에 가지 않는다.

**장소 사진은 레퍼런스로도 약하다.** 열두 장이 각각 다른 장면이면 색이 다른 건지 장면이 다른 건지 구분되지 않는다. 색만 비교하려면 장면이 같아야 한다.

## 3. 열두 가지

| #   | 이름       | 무드             | 색이 하는 일                                         | 이런 사진에서 산다                |
| --- | ---------- | ---------------- | ---------------------------------------------------- | --------------------------------- |
| 1   | 오슬로     | 새벽 · 겨울      | 어둡게 내리고 짙은 청색을 넣는다                     | 그림자가 넓은 사진, 새벽, 흐린 날 |
| 2   | 삿포로     | 한낮 · 겨울 눈   | 밝게 올리고 흰색을 중성으로 세운다                   | 흰 면이 큰 사진, 설경             |
| 3   | 서울       | 한낮 · 맑은 가을 | 하늘의 파랑을 깊게, 노랑만 살리고 전체 채도를 내린다 | 하늘이 들어간 야외 사진           |
| 4   | 도쿄       | 한낮 · 봄        | 분홍을 연하게 얹고 하이라이트를 부드럽게 굴린다      | 밝은 인물, 연한 배경              |
| 5   | 산토리니   | 한낮 · 여름 쨍함 | 시안을 진하게, 흰색을 깨끗하게, 노랑을 죽인다        | 강한 햇빛, 파랑·흰색이 있는 사진  |

| 7   | 하바나     | 오후 · 강한 햇빛 | 검정을 들어 올리고 청록과 주황으로 바랜다            | 색이 많은 사진, 낡은 질감         |

| 9   | 파리       | 해질녘           | 하늘을 라벤더로 돌리고 고운 입자를 얹는다            | 역광 인물, 노을                   |
| 10  | 마라케시   | 해질녘 · 건조    | 모래빛 주황을 깔고 검정을 내린다                     | 실루엣, 저녁 야외                 |
| 11  | 홍콩       | 밤               | 마젠타와 청록을 갈라 넣고 하이라이트를 번지게 한다   | 야경, 조명 있는 실내              |
| 12  | 레이캬비크 | 흐림 · 겨울      | 어둡고 완전히 중립인 회색으로 만든다                 | 무채색에 가까운 사진, 바다·바위   |

**"이런 사진에서 산다" 칸은 장소가 아니라 사진의 성질이다.** 밝은지 어두운지, 하늘이 있는지, 피부가 있는지. 이 칸을 팔 때 같이 적어야 환불이 줄어든다 — 프리셋은 사진을 고치는 것이 아니라 고르는 것이고 잘못 찍은 사진은 어떤 색을 걸어도 살아나지 않는다.

## 4. 어디서 도는가 — 브라우저 안에서만

**사진은 사용자 기기 밖으로 나가지 않는다.** 서버로 올리지 않고 브라우저 안에서 계산한다. 폰에서 쓸 때도 같다.

개인 사진을 다루는 도구라 이 하나가 신뢰의 전부다. 서버 비용이 0 이라는 것은 부수적인 이득이다.

그 대가로 따라오는 것이 둘이다.

**첫째, 지금 파이썬 코드를 그대로 쓸 수 없다.** 값은 그대로 두고 연산만 옮겨야 하는데, 세 군데가 언어를 건너면 달라진다. 리스본 한 장으로 재 본 값이다.

| 갈리는 곳     | 왜                                                                             | 안 맞췄을 때 차이                               |
| ------------- | ------------------------------------------------------------------------------ | ----------------------------------------------- |
| 가우시안 블러 | 명료도와 블룸에 쓴다. 브라우저 기본 `filter: blur()` 는 박스 3회 근사라 다르다 | 평균 0.432 · 최대 23 · 픽셀 7.14% 가 1레벨 초과 |
| 난수          | 그레인이 numpy 시드를 쓴다. 자바스크립트에 같은 스트림이 없다                  | 평균 2.81 · 픽셀 71.7% 가 다름                  |
| HSV 변환      | 색상별 채도에서 정수 0–255 색상환을 쓴다. 브라우저는 실수로 계산한다           | 미세하게 다름                                   |

셋 다 막는 문제가 아니라 정하면 되는 문제다. 커널을 직접 구현하고, 그레인을 **양쪽 다 같은 해시 기반 노이즈로 바꾸고**, 파이썬 쪽도 실수 HSV 로 맞춘다.

비트 깊이는 문제가 아니다. 입력을 8비트로 깎아 돌려 봤더니 평균 차이 0.000 · 최대 0 이었다.

**같은지는 측정으로 판정한다.** 같은 사진을 양쪽으로 돌려 픽셀 차이를 재고 기준을 넘으면 실패로 친다. 기준은 평균 절대차 0.5레벨 미만, 1레벨 초과 픽셀 1% 미만이다. 블러와 그레인을 안 쓰는 프리셋은 지금도 두 번 돌리면 평균 0.000 으로 완전히 결정적이라, 그런 것부터 옮기면 검증이 쉽다.

**둘째, WebGL 로 가야 한다.** 폰 사진이 1,200만 화소라 자바스크립트 메인 스레드로 돌리면 수 초간 화면이 멈춘다. 셰이더로 가면 즉시다. 이것은 정확도와는 별개 결정이다.

## 5. 값을 지키지 않는다

브라우저에서 다 도는 이상 프리셋 값은 사용자 기기 안에 있다. **마음먹은 사람은 읽어 갈 수 있고, 그것을 막지 않는다.**

난독화도, 값을 쪼개 숨기는 설계도 하지 않는다. 서버로 안 보내기로 했으니 원리상 막을 수 없다. 막으려 들면 코드만 복잡해지고 정작 쓰는 사람이 느려진다.

## 6. 값의 정본

curvez 모노레포의 `apps/city-presets` 다. 아래 경로는 그 아래의 `presets/` 를 기준으로 한다.

| 파일       | 무엇                                                           |
| ---------- | -------------------------------------------------------------- |
| `grade.py` | **열두 개의 실제 값과 적용 순서.** 여기가 정본이다             |
| `frame.py` | 흰 테두리와 값 스트립을 붙인다                                 |
| `hero.py`  | 팔레트마다 짝지은 사진에 그 프리셋만 걸어 대표 이미지를 만든다 |
| `base/`    | 검수용 기준 사진 6장                                           |
| `hero/`    | 판매용 대표 사진 12장                                          |

**슬라이더 어휘는 아이폰 사진 앱 편집기를 기준으로 삼되 거기 없는 것까지 쓴다.** 아이폰을 기준으로 삼은 이유는 사용자가 이미 아는 낱말이기 때문이지 거기 맞추려는 것이 아니다.

| 구분            | 항목                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| 익숙한 슬라이더 | EXP · BRIL · HIGH · SHAD · CONT · BRGT · BLACK · SAT · VIB · WARM · TINT · DEF · VIGN. 전부 −100~+100  |
| 그 너머         | SPLIT·S / SPLIT·H(그림자와 하이라이트에 각각 다른 색상 각도와 강도) · GRAIN · BLOOM · HSL(색상별 채도) |

**그 너머 항목이 제품의 근거다.** 하이라이트에 45도 금색을, 그림자에 220도 파랑을 나눠 넣는 조작은 휴대폰 기본 편집기로 할 수 없다. 리스본과 홍콩과 파리는 그 조작이 없으면 다른 색과 붙어 버린다.

적용 순서는 라이트룸과 같게 둔다. 노출과 화이트밸런스는 선형에서, 커브와 색조는 sRGB 에서 계산한다.

**생성물은 저장소에 넣지 않는다.** 넣는 것은 입력(`base/`·`hero/`)과 코드뿐이다. 생성 모델은 같은 프롬프트로 같은 그림을 다시 주지 않으므로 입력은 보관하고 계산으로 나오는 것은 보관하지 않는다.

## 7. 기준 사진 여섯 장 — 검수용

한 장으로는 열두 개를 다 판정할 수 없다. 사진마다 없는 것이 있고 **없는 것은 검사되지 않는다.**

| 파일               | 무엇을 검사하나                                              |
| ------------------ | ------------------------------------------------------------ |
| `01-base-outdoor`  | 지상 승강장, 맑은 날. 하늘·자연광·초록. **주 기준**          |
| `00-base`          | 지하 승강장, 형광등. 인공광 화이트밸런스와 깊은 그림자       |
| `02-base-cafe`     | 카페 테이블. 실내 따뜻한 빛, 흰 도자기, 피부                 |
| `03-base-cat`      | 고양이 근접. 털 질감과 역광. 원본 채도 27.9 로 가장 낮다     |
| `04-base-flowers`  | 꽃 시장. 원본 채도 88.4. **색상별 조작은 여기서만 드러난다** |
| `05-base-platform` | 클래식 승강장. 붉은 벽돌과 초록 주철, 흐린 날                |

기준 사진은 여섯 가지를 갖춰야 한다. 중성 회색이나 흰 면, 피부, 넓은 단색 면, 어두운 곳과 밝은 곳, 낮은 원본 채도, 정확한 노출.

> ⚠️ **대가**: 이 조건을 다 만족하는 사진은 대체로 밋밋하다. 그래서 **검수용과 판매용을 나눈다.**

## 8. 대표 사진 열두 장 — 판매용

`hero/<프리셋이름>.png` 이 입력이고 파일 이름이 어느 프리셋을 걸지를 정한다. 기준 사진이 열두 개를 **전부** 드러내는 한 장이라면, 대표 사진은 **그 프리셋 하나가 가장 잘 사는** 사진이다.

고르는 기준이 둘이다.

**첫째, 프리셋이 할 일이 남아 있는 사진을 고른다.** 삿포로에 처음 서리 결정 접사를 썼는데 원본이 이미 희고 채도가 낮아 채도를 빼는 프리셋이 할 일이 없었다. 적용 전후가 거의 같아서 "가장 어울리는 사진" 과 "무엇을 하는지 보이는 사진" 이 어긋났다. 자작나무 숲으로 바꾸니 갈색 나무껍질과 마른 잎이 빠지고 눈이 중성 흰색으로 서면서 밝기 +9.8 · 채도 −13.7 의 변화가 생겼다.

**둘째, 유적지와 글자를 넣지 않는다.** 생성 모델이 특정 건축물과 한글 간판을 정확히 그리지 못해 엉뚱한 나라의 글자가 섞인다. 얼굴도 알아볼 수 있게 넣지 않는다.

결은 셋을 섞는다 — 내셔널 지오그래픽 다큐·풍경, 아마추어 스냅, 전문 접사.

## 9. 열두 개가 정말 열두 개인지 검사한다

같은 사진에 걸었을 때 두 개가 비슷하면 그것은 열두 개가 아니라 열 개다.

**눈으로 보는 검사가 먼저다.** 기준 사진에 열두 개를 걸고 두 장씩 나란히 놓고 이름을 맞춰 본다.

**수치 검사가 그 뒤를 받친다.** 열두 개에서 나오는 짝은 66개다. 각 결과의 R−B 차·G−B 차·평균 채도·평균 밝기 네 값으로 짝마다 거리를 재면 붙은 짝이 목록 맨 위로 올라온다.

이 검사로 세 번 고쳤다.

| 붙은 짝                  | 어떻게 갈랐나                                                                                                           |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 삿포로 · 시애틀          | 첫 판정에서 붙었다. 삿포로를 더 밝고 깨끗한 중성 흰색으로, 시애틀을 더 어둡고 파랗게 밀어 갈랐다                        |
| 오슬로 · 시애틀          | 그다음 세 원본에서 모두 최소거리 1위였다. 오슬로를 해 뜨기 전으로 내리고 시애틀을 비 온 낮으로 올려 110~120 으로 벌렸다 |
| 시애틀 · 레이캬비크      | 시애틀은 밝고 파랑, 레이캬비크는 어둡고 완전 중립으로 나눴다                                                            |
| 서울 · 산토리니 · 리스본 | 서울이 순환에 걸렸다. 노랑을 키우면 리스본과, 파랑을 키우면 산토리니와 붙는다. 채도 축으로 빼냈다                       |

지금 수치는 여섯 원본 전부에서 **최소거리 20.8 이상, 중앙값 61.9~83.3** 이다. 20 아래로 떨어지는 짝이 없다.

> 📌 **수치는 보수적이다**: 평균 기반이라 색의 방향이 반대인 짝도 가깝게 나온다. 20 근처인 짝은 눈으로 다시 본다.

## 10. 사진 아래에 값을 찍는다

흰 테두리를 두르고 아래에 도시 이름과 **적용된 값 전부**를 작게 찍는다. 형태는 카메라 데이터 블록처럼 보이지만 내용은 다르다.

**찍는 숫자는 지어낸 것이 아니라 실제 적용값이다.** `frame.py` 가 `grade.py` 에서 그대로 읽어 온다. 값을 고치면 스트립도 따라 바뀐다.

이렇게 하는 이유가 둘이다. 첫째, 이 제품이 파는 주장은 "이만큼 정밀하게 만진다" 인데 그것을 같은 자리에서 증명한다. 지어낸 ISO 는 아무것도 증명하지 못한다. 둘째, 값과 화면이 어긋날 수가 없다. 사람이 옮겨 적으면 언젠가 어긋난다.

촬영 정보(ISO·렌즈·셔터)는 넣지 않는다. 실제로 그렇게 찍은 것이 아니기 때문이다. 형식상 그 칸이 필요하면 `GRAIN 14 ≈ISO 800` 처럼 "상당" 으로 적어 형식은 지키고 사실과 어긋나지 않게 한다.

서체는 도시 이름을 획 대비가 큰 세리프로 자간을 벌려 찍고 값은 고정폭으로 찍는다. 글자색은 순백이 아니라 크림이고 종이색도 살짝 따뜻하다. 손글씨안도 만들어 비교했지만 값을 읽기 어려워 쓰지 않는다.

**기본으로 받아 가는 것은 사진 한 장이다.** 테두리와 값이 붙은 버전은 원하는 사람만 더 받는다. 대부분은 색만 바꿔 바로 올리려고 오기 때문이다.

> ⚠️ **주의**: 값 줄이 사진 폭을 넘으면 오른쪽이 잘린다. **잘린 값은 틀린 값이다.** `frame.py` 는 폭에 맞을 때까지 글자를 줄이고 그래도 넘치면 멈춘다.

## 11. 상품 이미지는 before/after 다

프리셋 판매에서 구매를 만드는 것은 무드 사진이 아니라 **"내 사진이 이렇게 바뀐다"는 증거**다. 판매 글의 본체는 원본과 적용본을 나란히 둔 비교 컷이다.

**미리보기를 과하게 보정하면 클릭은 늘고 환불도 는다.** 구매자가 자기 사진에 걸었을 때 그 그림이 안 나오기 때문이다. 미리보기는 실제로 재현되는 수준으로 만든다.

## 12. 무료와 유료

**무료 여섯만으로 일 년이 돌아가야 한다.** 사계절과 흐린 날과 저녁이 무료 안에 다 있어야 한다는 뜻이다. 무료가 반쪽이면 사람들은 유료로 넘어오지 않고 그냥 떠난다.

- 무료 — 삿포로(겨울) · 도쿄(봄) · 산토리니(여름) · 서울(가을) · 시애틀(흐림) · 파리(저녁)
- 유료 — 오슬로 · 리스본 · 하바나 · 마라케시 · 홍콩 · 레이캬비크

유료 쪽은 성격이 세고 상황이 특정된다. 새벽에 카메라를 드는 사람, 야경을 찍는 사람, 사막에 가는 사람의 몫이다.

## 13. 아직 정하지 않은 것

- **유료 여섯 개를 어떻게 가르나** — 결제 후에 값을 내려줄지, 워터마크를 씌울지, 아니면 전부 열지. 값을 지키지 않기로 했으므로 어느 쪽이든 기술적 방어는 아니다
- **묶음 이름** — 값 스트립에는 임시로 `CITY FILTER 12` 가 들어가 있다
- **가격** — 시장에서 열 개 남짓 묶음은 대체로 $15~47 선이다
- **하바나** — 실내 따뜻한 빛에서 창틀과 흰 면이 초록으로 돈다. 의도 범위 안이지만 병색으로 읽힌다. 더 줄이면 도쿄와 붙는다
- **산토리니** — 하늘의 시안이 세다. 필터 티가 난다고 볼 수도 있다

## 14. 범위 밖

- **도시에 가서 찍는 것** — 이 제품은 색이지 여행이 아니다
- **필름 카메라·현상 재현** — 특정 필름의 이름을 쓰지 않는다. 상표 문제도 있고 검증도 못 한다
- **자동 보정·AI 보정** — 사용자가 고르는 것이 이 제품의 핵심이다. 자동으로 골라 주면 열두 개를 만들 이유가 없다
- **인스타그램 앱 내 필터** — Meta 가 Spark AR 을 닫아서 새로 만들 수 없다
