## 1. 무엇을 그렸나

curvez 를 쓰는 사람이 읽을 사용 설명서다. 에이전트 12종 · 스킬 15종 · 실행기 8종 · 훅 3종 · 문서 11편을 다루고, 설치 · 첫 시작 · 말로 부르기 · 명령어 · 에이전트 · `.curvez/` · 팀 실행 · 직접 확장 · 훅 · 아직 없는 것 열 절로 되어 있다.

스킬 15종은 트리거 발화와 함께 표로 적었다. "커밋해줘" 로 `commit` 이, "와이어프레임" 으로 `wireframe-spec` 이, "검증해줘" 로 `quality-gate` 가 걸리는 식이다.

## 2. 어떤 제약이 있었나

첫 시작 네 단계는 건너뛸 수 없다. 뒤가 앞의 산출물을 읽기 때문이고, 특히 구현 에이전트는 `.curvez/architecture.md` 의 `## 금지 import` 표를 위반 판정의 유일한 근거로 쓴다. 그 파일이 없으면 `blocked` 로 멈춘다.

경로도 추측하지 않는다. `profile.json` 에 없는 키는 "검사 없음"으로 다루고 스택별 필수 키가 없으면 `blocked` 로 보고한다 — 에이전트마다 다른 폴백을 두면 모노레포에서 둘이 같은 디렉터리를 소유하고, 병렬 실행에서 나중에 쓴 쪽이 앞선 쪽을 조용히 지운다.

`doctor` 의 검사 7종은 A · B 두 등급으로 갈라 놓았다. 실행기 둘이 없는 상태에서 "검사 3종 전부 정상"이 나왔고 그 출력이 완료 근거로 쓰인 적이 있어서, 정적 규약만 exit code 를 좌우하고 런타임 완비는 참고 정보로 내렸다.

## 3. 무엇이 남았나

"아직 없는 것" 절에 네 항목을 적어 두었다. 실제 `/plugin install` 미검증, 멀티에이전트 e2e 왕복 미검증, `run_id`/`round_id` 같은 실행 상관관계 ID 없음, bare React Native 는 `expo.sdkVersion` 이 필수라 `blocked`.

가드가 못 막는 것도 밝혀 두었다. `gh pr merge` 는 원격 이력을 바꾸는데 가드에 걸리지 않으므로, 배포 브랜치 머지 금지는 가드가 아니라 정의와 스킬로만 지켜진다.

가장 자주 나온 실패 유형은 하나로 묶었다. 검사가 안 돌았는데 통과로 보이는 것 — 새 검사를 만들면 0건이 나왔을 때 통과가 아니라 검사가 안 걸린 것을 먼저 의심한다.
