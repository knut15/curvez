## 1. 작업 소개

파트타임 근무자의 출퇴근 기록과 급여를 관리하는 웹 앱이다. 쓰는 사람은 두 역할로 나뉜다.

| 역할 | 하는 일 |
| --- | --- |
| 사장(마스터) | 매장을 만들고 초대 코드로 알바생을 부른다. 멤버별 시급·근무 요일·출퇴근 시각을 정하고 수정 요청·휴가·대타를 승인한다. 대시보드와 근무 달력으로 전체 근무를 본다 |
| 알바생(멤버) | 휴대폰 브라우저로 출퇴근을 찍는다. 매장 50m 안에 들어오면 출근 알림을 받고 이번 주·이번 달 급여를 본다. 잘못 찍은 기록은 사장에게 수정을 요청한다 |

표 1. 두 역할이 앱에서 하는 일

급여는 시급으로 받는 기본급에 주휴수당과 연장근로 가산을 더해 계산한다. 주휴수당은 주 15시간 이상 일하기로 한 사람이 그 주에 약속한 날을 다 나오면 하루치를 더 주는 수당이다.

## 2. 구현 과정과 선택 기준

작업은 2026-09-25 하루 동안 이어졌다. 사용자가 요청을 한 줄씩 보냈고 요청 하나가 끝나면 다음 요청이 왔다. 히스토리에 번호가 붙은 요청은 저녁의 문서 정리와 성능 검사까지 35건이고 그 사이 기능 PRD(무엇을 만들지 적은 요구사항 문서)가 01번부터 13번까지 쌓였다.

| 시각 | 무엇 |
| --- | --- |
| 13:34 이전 | 출퇴근·급여·50m 알림 PRD 01~04, 저장은 브라우저 localStorage 로 웹만 먼저 배포 |
| 13:34 | 로그인·매장·초대·사장 대시보드(PRD 05~07), API 서버와 Neon DB 연결 |
| 14:33 | 기록 수정 요청, 휴가·대타(PRD 08·09), 쿠키 세션 로그인 |
| 15:02~15:54 | 근무 달력(PRD 10), 컴포넌트 가이드 `/guide`, 매장 로고(PRD 11), 초대 문자, Pretendard 글꼴 |
| 16:40 | 멤버 오늘 근무 대시보드(PRD 12), 퇴근한 날은 다시 출근 못 하게 |
| 17:39 | 근무 시간표와 날짜별 변경(PRD 13), 조건 수정 모달, 스켈레톤, 버튼, 브레드크럼 |

표 2. 하루 동안 기능이 붙은 순서 (저장소 히스토리와 PR 기준)

방향을 정한 선택은 대부분 사용자가 했다. 에이전트가 범위를 좁혀 물으면 사용자가 골랐고 그 결과는 `docs/decisions.md` 한 목록에 문서 링크와 함께 모았다.

**급여 규칙은 공식 출처로 확정했다.** 첫 요청부터 "주휴수당(공식 페이지 확인)" 이 들어 있었다. 2026년 최저임금 10,320원은 최저임금위원회, 주휴 요건과 계산식은 찾기쉬운 생활법령정보와 고용노동부 1350 상담에서 가져와 PRD 02 에 링크로 남겼다. 5인 미만 사업장의 가산 제외 조문은 원문을 확인하지 못해 PRD 에 "확인 불가" 로 적어 두었다.

**로그인은 직접 구현했다.** 인증 서비스를 쓰지 않고 JWT 로 만드는 쪽을 사용자가 골랐다. 인프라는 Neon(서버리스 Postgres)과 Vercel 로 정했다. 요청 6 에서 "로그인이 계속 유지되었으면 좋겠어" 라는 말이 나왔다. 액세스 토큰까지 HttpOnly 쿠키에 담아 마지막 사용 뒤 30일 동안 유지하는 방식으로 바꿨다. 자바스크립트가 토큰을 읽지 못하는 대신 쿠키로 오는 모든 변경 요청에 CSRF(다른 사이트가 몰래 요청을 보내는 공격) 검사를 붙였다.

**API 계약은 서버의 스키마 하나에서 시작한다.** `server/src/contract.ts` 의 zod 스키마가 요청을 검증하고 같은 스키마에서 `docs/api/openapi.json` 을 뽑는다. 웹은 그 파일로 타입을 만든다. 서버가 계약을 바꾸면 웹의 타입 검사가 깨지는 자리가 곧 고칠 자리가 된다.

**화면 규칙도 사용자가 정했다.** 불러오는 중에는 불러온 뒤와 같은 크기의 스켈레톤을 보여 줘서 화면이 밀리지 않게 한다. 버튼은 "파랑 빨강이 촌스럽다" 는 지적에 따라 주 동작은 검정, 보통은 회색, 지우기는 올렸을 때만 빨강으로 바꿨다. 스크롤 영역·모달·스켈레톤은 shadcn 원본을 들여와 썼고 필요한 패키지는 물어서 설치했다.

하루 동안 히스토리에 적힌 실패는 31건이다. 그중 17건이 배포(10건)와 도구·환경(7건)에서 났다. 첫 웹 배포는 pnpm 이 패키지를 루트에 두는 바람에 업로드 범위에서 빠져 실패했다. API 는 Vercel 이 진입점을 다른 파일로 골라 모든 요청이 500 을 냈다. 실패는 원인과 수정까지 `docs/history/2026-09-25.md` 에 남겼다.

표 3. 2026-09-25 저녁 기준 상태

성능은 운영 주소를 서울에서 쟀다. DB 를 거치지 않는 `/health` 도 중앙값이 214ms 라서 쿼리보다 서버와 DB 가 미국 동부(iad1, us-east-1)에 있다는 거리가 더 크다. 화면은 로그인 확인이 끝나야 데이터를 부르기 때문에 왕복이 두세 번 쌓인다. 리전 이전은 새 DB 와 데이터 이전이 따르는 결정이라 이번에는 재기만 했다.

확인하지 못한 것도 남아 있다.

- 로그인한 사장·멤버의 실제 화면은 자동화로 비밀번호를 넣지 않아 보지 못했다. 가이드 페이지 예시와 390·320px 틀로만 확인했다
- iOS Safari 의 날짜 입력칸은 실기기로 확인하지 않았다
- 휴게시간은 시간표에서 빼지 않았다. 급여 계산이 근무 기록에서도 빼지 않는 것과 맞춘 것이고 사용자 결정을 기다리는 지점이다
- 퇴근 뒤 두 번째 출근은 화면에서만 막는다. 서버는 아직 받는다
