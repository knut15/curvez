# component: SiteHeader

purpose: 모든 화면의 최상단에서 현재 위치와 이동 경로를 주고, 테마 전환을 놓는다

## props

| 이름    | 타입                  | 필수 | 기본값 | 의미                                            |
| ------- | --------------------- | ---- | ------ | ----------------------------------------------- |
| current | home \| cases \| case | X    | home   | 현재 화면. 해당 링크를 aria-current 로 표시한다 |

## states

| state         | 트리거             | 시각 변화                                               |
| ------------- | ------------------ | ------------------------------------------------------- |
| default       | —                  | bg=--brand-canvas, 하단 border=--border 1px             |
| hover         | 링크에 포인터 진입 | 링크 fg=--brand-accent (기본은 --brand-ink)             |
| focus-visible | 키보드 포커스      | outline 2 + offset 2, color=--ring                      |
| pressed       | :active            | 시각 변화 없음                                          |
| disabled      | 없음               | 비활성 상태가 없다. 현재 화면 링크도 클릭 가능하게 둔다 |
| loading       | 없음               | 정적 렌더라 로딩 구간이 없다                            |
| error         | 없음               | 상태를 갖지 않는다                                      |

## a11y

- a11y:label — 로고는 텍스트다. 아이콘 전용이 아니므로 aria-label 을 지정하지 않는다
- a11y:focus — 포커스 순서는 로고 → Works → Cases → Labs → 테마 토글. 스킵 링크를 두지 않는다. 헤더의 포커스 대상이 5개라 본문까지 건너뛸 비용이 크지 않다
- a11y:contrast — 로고 fg=--brand-ink / bg=--brand-canvas (라이트 18.73 · 다크 17.90), 링크 기본 fg=--muted-foreground (라이트 4.74 · 다크 5.86), hover fg=--foreground (라이트 18.73 · 다크 17.90). 렌더 화면에서 잰 값이다(2026-09-14). 값이 이전 판과 다른 이유는 중립 스케일을 [`../tokens.md`](../tokens.md) 의 값으로 바꿨기 때문이다
- a11y:target — 세로 여백을 바가 아니라 링크가 갖는다(`py-2`). 잰 상자는 로고 41x39, Works 37x36 · Cases 36x36 · Labs 28x36, 토글 40x40 으로 최소 24x24 를 넘고 간격은 gap-4(16px) 다. 바에 여백을 몰아 주면 링크의 클릭 영역이 글자 높이(20px)에 머문다
- a11y:role — banner (header 요소). 내부는 navigation 하나

## responsive

- 모든 폭에서 한 줄. 좌측 로고, 우측 링크 2개와 토글. 항목이 4개라 모바일 메뉴를 만들지 않는다. 좌우 여백 `px-5 md:px-8` — 홈과 서브가 같은 값이어야 한다
- **`apps and notes` 태그라인은 640px 미만에서 접는다(`hidden sm:inline`).** 펼친 상태의 최소 한 줄 폭은 410px, 접으면 310px 다(재서 확인했다). 375px 에서는 펼친 폭이 들어가지 않으므로 접어야 한다
- **접는 기준이 필요한 폭보다 넉넉하다.** 410px 부터 들어가는데 640px(`sm`)에서 접는다. Tailwind 기본 브레이크포인트를 쓰느라 생긴 여유이고, 410\~640px 구간에서 태그라인을 보이려면 `hidden min-[420px]:inline` 으로 바꾸면 된다. 지금은 기본값을 쓰는 쪽을 골랐다
- 375 · 639 · 640px 에서 바 높이가 모두 61px 로 한 줄이고 가로 스크롤이 없다(iframe 으로 재서 확인했다)
- **`title` 을 받으면 제목 바가 딸려 온다.** 상세 화면에서 큰 `<h1>` 이 화면 위로 지나가면 바가 **헤더 뒤에서 아래로 밀려 나온다.** 별도 컴포넌트였던 `StickyTitle` 을 여기로 합쳤다 — 헤더가 같은 순간에 높이를 줄여야 해서 둘이 상태를 나눠 가질 수 없다
  - 미는 방식: 제목 바를 `top-full` 로 헤더 바로 아래 붙여 두고 평소에는 `-translate-y-[calc(100%+1px)]` 로 헤더와 겹쳐 둔다. 헤더가 불투명해서 그동안 안 보인다. 그래서 제목 바의 `z` 가 헤더보다 **낮아야** 한다(헤더 10 · 바 0)
  - `100%` 가 아니라 `calc(100% + 1px)` 인 이유: 제목 바도 아래에 1px 선을 갖는데, 딱 100% 만 올리면 그 선이 헤더의 선과 반 픽셀 어긋나 맨 위에서 경계가 **2px 로 보인다**
  - **들어가는 쪽이 나오는 쪽보다 느리다** — 나올 때 200ms, 들어갈 때 380ms. 헤더 높이 전환은 양쪽 다 200ms 라, 되돌아갈 때는 헤더가 먼저 제 높이를 찾고 그 뒤로 바가 마저 올라간다
  - 글자는 **사라질 때만** 흐려진다(나올 때 75ms · 들어갈 때 300ms). 방향마다 다른 전환을 주려고 클래스에 `duration` 을 같이 싣는다
  - 제목은 가운데 정렬이고 넘치면 `truncate` 다. 바 전체가 `aria-hidden` 이고 안에 링크를 두지 않는다 — 같은 제목이 바로 위 `<h1>` 에 이미 있다
  - 판정은 `IntersectionObserver` 다. 눈금은 상세 뷰가 `[data-title-sentinel]` 로 심고 헤더가 찾아 관찰한다. 두 파일이 서로를 import 하지 않고 **붙는 자리만 약속**한다
  - **`rootMargin` 에 `--header-height` 를 그대로 넘기면 안 된다.** 그 값은 `rem` 문자열인데 `rootMargin` 은 px 과 % 만 받아 생성자가 던진다. 헤더 요소에서 `getBoundingClientRect().height` 로 직접 잰다
- **스크롤로 제목 바가 걸리면 헤더가 `--header-height-compact`(48px)로 줄어든다.** 헤더가 내주는 만큼 바가 자리를 받는 것으로 읽힌다
- **`"use client"` 다.** 스크롤 위치를 알아야 답할 수 있는 질문이라 CSS 만으로 판정할 수 없다. 상태는 boolean 하나다
- **전 화면에서 `sticky top-0 z-30` 이다.** 랜딩만 그랬던 것을 컴포넌트 자신의 속성으로 올렸다 — 목록·상세도 스크롤이 길고, 위의 제목 바가 이 바 아래에 붙으려면 고정이어야 한다
- 바 높이는 `--header-height`(3.8125rem = 61px)를 **명시로 갖는다.** 그 아래 붙는 제목 바가 같은 값을 읽으므로, 높이가 내용에 따라 흔들리면 그 바가 어긋난다. 세로 여백은 여전히 링크의 `py-2` 가 만들고 그 합이 61px 이다
- 바 높이 61px. 세로 여백은 링크의 `py-2` 가 만들고 바는 `py-2.5` 만 갖는다
