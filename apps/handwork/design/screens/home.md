route: /
goal: 방문자가 히어로에서 이 사이트가 무엇을 하는 곳인지(슬로건·비전)를 받고, 세 영역 중 하나로 들어간다

## 형태의 출처

**linear.app 의 디자인 언어를 따른다.** 값은 지어내지 않았고 그 사이트의 렌더 화면에서
`getComputedStyle` 로 직접 읽었다. 실제 색·반경은 `src/app/globals.css` 의 오버라이드 블록이
갖는다(라이브러리는 고치지 않는다).

| 항목      | 값                                                                   |
| --------- | -------------------------------------------------------------------- |
| 배경·전경 | `#08090A` / `#F7F8F8` (다크). 라이트는 같은 관계를 뒤집은 값         |
| 카드 면   | `#0F1011` (다크) · `#FBFBFB` (라이트) — 배경과 한 단 차이            |
| 선        | `#23252A` (다크) · `#E6E7E8` (라이트), 1px hairline                  |
| muted     | `#8A8F98` (다크) · `#6B6F76` (라이트)                                |
| 반경      | `--radius: 1rem` (16px). 카드는 `rounded-2xl`, 버튼은 완전 둥근 pill |
| 굵기      | `font-[510]`. Tailwind 의 `font-medium`(500)이 아니라 실측값 그대로  |
| 자간      | 본문 `-0.01em`(`html` 전역) · 헤딩 `-0.022em` · 중간 크기 `-0.015em` |
| 버튼      | 높이 36px · 13px · pill. 주 버튼은 밝은 면 + 어두운 글자             |

**중립을 완전 중립으로 내렸다.** 라이브러리의 중립은 teal 색조를 띠는데(`oklch(… 181.8)`),
사이트 전체가 그 색조 위에 올라가면 브랜드 teal 이 액센트로 읽히지 않는다. 색은
`--brand-accent`(teal)와 `--brand-mark`(코랄) 둘만 갖는다.

## layout

히어로 → 세 영역 → 흐름 → 글쓰기 기준, 네 단이다.

**슬로건은 히어로의 배지, 비전은 히어로의 헤드라인으로 올라가 있다.** 절을 따로 두면
방문자가 같은 말을 두 번 읽는다.

**모션을 두지 않는다.** 스크롤 진입 애니메이션은 기다림을 만들고 `prefers-reduced-motion`
분기를 하나 더 늘리는데, 이 화면이 전할 것은 글이지 움직임이 아니다.

- region: bar
  - role: 상단 바. 좌측 `aster® apps and notes`, 우측 Works · Cases · Labs 와 테마 토글
  - priority: 3
  - **홈·서브가 같은 `SiteHeader` 를 쓴다.** 좌우 여백 `px-5 md:px-8` 이 모든 화면에서 같아야 하고 컴포넌트를 나누면 그 값이 조용히 달라진다
  - 글자는 13px 산세리프 `font-[510]` 이고 **밑줄이 없다.** 모노 대문자에 밑줄을 두던 것을 버렸다 — 랜딩이 위 표의 체계를 따르는데 헤더만 다른 서체 체계로 남아 위아래가 갈렸다. 링크는 평소 muted 이고 hover 에서 전경색으로 올라온다
  - **`sticky top-0 z-30` 이고, 이제 홈만이 아니라 전 화면이 그렇다.** `SiteHeader` 자신이 그 속성을 갖는다(예전에는 홈의 `page.tsx` 가 감싸는 `div` 로 줬다). 상세 화면의 제목 바가 이 바 아래에 붙으려면 헤더가 고정이어야 한다
  - 바 아래 `border-b` 1px
- region: hero
  - role: 배지 · 워드마크 · 슬로건 · 소개 · 버튼 둘. 전부 가운데 정렬

- region: visual
  - role: 히어로 아래 프레임. **사진이 아니라 이 사이트 자신의 화면이다**
  - priority: 2
  - linear.app 이 그 자리에 제품 스크린샷을 놓는 것과 같은 자리이고, aster 의 제품은 기록물이라 케이스 목록이 곧 제품 화면이다
  - **사진을 그만둔 이유:** `public/brand/` 의 다섯 장은 전부 밝은 teal 이라, 중립으로 내린 배경 위에서 혼자 떠올랐다. 다섯 장은 파일로 남아 있고 쓰이는 곳은 0곳이다
  - 안에 든 것: 축소한 상단 바(진짜 헤더와 같은 구성) → `Cases` 라벨 + 건수 → 케이스 카드 **8장**(제목 1줄 · 요약 2줄 · 날짜 + 태그 2개)
  - **8장인 이유:** 16:9 프레임의 마지막 행이 아래 페이드에 걸린다. 6장이면 프레임 아래가 비고 목록이 화면 밖으로 이어지는 것처럼 보이지 않는다
  - **카드 내용은 목업용 더미이고 실제 글 목록이 아니다**(`views/home.tsx` 의 `VISUAL_ROWS`). 건수(`{n} items`)만 실제 값을 받는다 — 그 숫자는 사이트가 자란 만큼 늘어야 맞다
  - **더미는 영어로 적는다.** 한글 제목을 넣으면 장식이 아니라 읽을거리가 되어 헤드라인과 시선을 다툰다. 프레임 전체가 `aria-hidden` 이고 안에서 어디로도 갈 수 없으므로 실제 글과 일대일로 맞을 필요가 없다
  - **전체가 `aria-hidden` 이고 안쪽에 링크가 없다.** 여기 보이는 제목은 아래 세 영역 카드와 `/cases` 목록에 링크로 전부 다시 나오므로, 스크린리더가 같은 목록을 두 번 읽을 이유가 없다. 초점이 들어갔다가 아무 데도 못 가는 자리도 만들지 않는다
  - 비율은 `aspect-[4/3] sm:aspect-[16/9]` 다. 좁은 폭에서 16:9 는 카드 한 줄도 온전히 안 들어간다. 카드 그리드도 `grid-cols-1 sm:grid-cols-2` 로, 375px 에서 2열이면 카드 폭이 134px 까지 줄어 제목도 날짜도 잘렸다
  - 아래 1/3 은 배경색으로 녹인다(`linear-gradient(to top, var(--background), transparent)`)
  - 방문마다 사진을 뽑던 것을 그만뒀으므로 **이 화면은 더 이상 `force-dynamic` 이 아니다.** `pnpm build` 에서 `/` 가 `○ (Static)` 으로 나온다

## states

- state:default — 항상 이 상태다. 히어로는 데이터에 의존하지 않고, 세 영역 카드만 컬렉션 수를 읽는다
- state:loading — 비주얼 한 장에 `priority` 를 준다. 그림이 도착하기 전에는 `ground` 색이 프레임을 채운다. 스켈레톤은 두지 않는다. 콘텐츠는 MDX 라 빌드 시점에 박히고 런타임 로딩이 없다
- state:empty — **세 영역 카드에만 있다.** 컬렉션이 비면 맨 위 한 건 대신 `아직 공개한 기록이 없습니다.` 를 놓고 건수는 `0건` 이 된다. 2026-09 기준 Works 가 이 상태다(`content/works` 에 `_template.mdx` 뿐)
- state:error — 이 화면에는 에러 상태가 없다. 비주얼이 실패해도 히어로의 글과 아래 세 절은 그대로 읽힌다

## responsive

- 세 영역 3열 · 글쓰기 기준 2열 · 흐름 가로 배치는 각각 `md:` · `sm:` · `sm:` 에서 갈라지고 그 아래는 1열이다
- 본문 폭은 다른 화면과 같은 `max-w-5xl`, 좌우 여백도 같은 `px-5 md:px-8` 이다
- **가로 스크롤이 어느 폭에서도 생기지 않는다.** 같은 origin 의 iframe 에 폭을 주고 그 안에서 잰 값이다(창 리사이즈 도구가 먹지 않아 iframe 을 썼다 — iframe 안에서는 미디어쿼리가 iframe 폭으로 평가된다)

## a11y

- focus-order: bar(로고 → Works → Cases → Labs → 테마) → 히어로 버튼 2개 → 세 영역 카드의 영역 링크와 맨 위 글 링크(최대 6개)
- 비주얼 이미지에 alt 를 준다. 장식이 아니라 브랜드가 말하려는 내용이다
- landmark: header(`SiteHeader`) · main · footer(`SiteFooter`). `main` 은 `HomeView` 가 갖는다
- 색 점 · 화살표 `→` · 글로우는 전부 `aria-hidden` 이다. 영역 구분과 순서는 글자와 마크업(`<ol>`)이 갖는다
- **색 점만으로 구분하지 않는다.** 점 옆에 영역 이름이 항상 글자로 있다
- a11y:contrast — 렌더 화면에서 토큰 값을 읽어 쌍으로 쟀다(2026-09-14). **미달 0건.** 전체 표와 재는 방법은 [`../tokens.md`](../tokens.md) 의 `## 대비 검증` 이 갖는다
  - 이 화면에 걸리는 값만 옮기면: 본문/배경 19.93·18.73 · muted/배경 5.05·6.13 · 카드 글자/카드 19.26·17.90 · 주 버튼 19.93·15.83 · 링크 hover 6.15·12.88 (라이트·다크 순)
  - **`--brand-mark`(워드마크의 `a`)만 large text 기준 3:1 로 판정한다.** 라이트 3.45 · 다크 7.07. 라이트 값은 원색 `#ff6b4a`(2.82)가 3:1 에도 못 미쳐 `#f2542d` 로 한 단 내린 결과다. 작은 글자에 이 색을 쓰면 기준이 4.5 로 올라가고 지금 값은 미달이다
