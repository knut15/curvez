화면 제목과 그 아래 설명 문단을 한 벌로 냅니다. **한 화면에 하나만** 둡니다.

<div className="not-prose my-6 rounded-lg border border-border p-6">
  <PageTitle description="어떤 제약에서 무엇을 고르고 무엇을 버렸는지를 씁니다.">
    케이스
  </PageTitle>
</div>

<div className="not-prose my-6 rounded-lg border border-border p-6">
  <PageTitle
    variant="detail"
    description="제약 · 선택 · 버린 것 순서로 읽습니다."
  >
    토큰 저장소의 경쟁 상태를 고치면서 무엇을 버렸나
  </PageTitle>
</div>

## variant 가 바꾸는 것은 둘뿐

| variant  | 추가 클래스                 | 언제                                        |
| -------- | --------------------------- | ------------------------------------------- |
| `index`  | 없음                        | 제목이 한 줄로 끝나는 목록·오류 화면        |
| `detail` | `leading-[1.15] break-keep` | 제목이 문장이라 두 줄 이상이 되는 상세 화면 |

실측이 두 형태뿐입니다. 세 번째를 만들면 어느 화면이 어느 형태인지 화면을 열어 봐야 압니다.

## `level` 을 받지 않는다

항상 `<h1>` 입니다. 레벨을 고를 수 있게 하면 h1 이 둘이거나 없는 화면이 생기고, 그것은
스크린리더의 문서 개요를 망가뜨립니다. h2·h3 는 본문 안에 있고 [Prose](/components/prose) 가
맡습니다.

## 설명 폭을 하나로 통일했다

실측은 `65ch` · `60ch` · 폭 없음 셋으로 갈려 있었습니다. **값은 다른데 의미가 같습니다** —
"제목 밑의 한 문단". 이럴 때는 나누지 않고 하나로 묶습니다.

65ch 를 고른 근거는 최다 사용이 아니라 본문 폭 `68ch` 에 가장 가깝다는 것입니다. 같은 화면에서
두 문단의 줄바꿈 지점이 크게 갈리면 설명과 본문이 다른 문서로 읽힙니다.

## 크기 분기를 넣지 않는다

모든 폭에서 `text-4xl` 고정입니다. 유일한 예외는 브랜드 워드마크인데, 그것은 제목이 아닙니다.
