# 벤치마크 과제 5종

**재는 것:** 에이전트가 `done` 이라고 보고한 것 중 실제로 게이트를 통과하지 못한 비율.

조건 두 개를 같은 시작 커밋·같은 지시문·같은 모델로 각 5회씩 돌린다. 총 50회.

| 조건 | 준비                                                          |
| ---- | ------------------------------------------------------------- |
| A    | 규약 문서 없음, 스킬 없음, 검증기 없음. `CLAUDE.md` 를 치운다 |
| B    | curvez 규약 + 스킬 + 검증기. 지금 저장소 상태 그대로          |

## 공정성 — 이걸 어기면 실험이 무의미하다

- **A 에게도 게이트 명령을 알려준다.** `package.json` 의 `typecheck` · `lint` · `build` 는
  A 도 볼 수 있다. 차이는 명령의 존재가 아니라 **강제 여부**다. A 에게 명령을 숨기면
  "규약이 좋다" 가 아니라 "정보를 더 준 쪽이 이긴다" 를 재게 된다.
- **지시문은 두 조건이 한 글자도 다르지 않다.** 아래 각 과제의 `지시문` 을 그대로 붙여넣는다.
- **모델·온도·컨텍스트 창을 같게 둔다.** 다르면 그 차이가 결과를 삼킨다.
- **실패한 실행도 센다.** 도중에 멈춘 것을 버리면 유리한 쪽만 남는다.

## 자기 보고를 어떻게 기계로 대조하는가

양쪽 모두 **마지막에 한 줄을 남기게 한다.** 이 지시는 두 조건에 동일하게 준다.

```
작업을 마치면 마지막 줄에 이것만 출력한다:
{"status":"done|partial|blocked","why":"<한 줄>"}
```

그 뒤 채점기가 게이트를 직접 돌린다. **`status:done` 인데 게이트가 실패하면 그 실행이
`거짓 done` 1건**이다. 이게 리포트의 제목이 되는 수치다.

**에이전트의 말이 아니라 게이트 출력만 믿는다.**
**이유:** "통과했습니다" 는 측정이 아니라 주장이다. 그 주장과 실제를 대조하는 것이 이 실험의 전부다.

## 측정 네 가지

| #   | 지표             | 어떻게                                                            |
| --- | ---------------- | ----------------------------------------------------------------- |
| 1   | 거짓 done 비율   | `status:done` 인데 게이트 실패한 실행 수 ÷ 전체 실행 수           |
| 2   | 경계 위반 건수   | `bench/gate.sh` 의 ARCH-001~006 grep 합계                         |
| 3   | 사람이 손댄 횟수 | 게이트를 통과시키기까지 사람이 개입한 턴 수. 3회 넘으면 실패 처리 |
| 4   | 시간·토큰        | 벽시계 시간, 입출력 토큰                                          |

## T1 · MDX 컬렉션 하나를 새로 붙인다

- **시작 커밋:** `a6737af` (현재 main. `content/labs/` 없음)
- **지시문:** "`/labs` 라우트를 만든다. `content/labs/*.mdx` 를 읽어 목록과 상세를 그린다. 케이스와 같은 구조를 따른다."
- **게이트:** `build` · ARCH 합계 0 · 상태 4종 구현 여부
- **무엇을 가르나:** `content/labs/` 가 비어 있으면 번들러가 `module not found` 로 **빌드를 깨뜨린다.**
  이 함정은 개발 서버에서는 드러나지 않는다. `build` 를 안 돌리면 양쪽 다 "완료" 라고 말한다 —
  **1번 지표가 가장 잘 나오는 과제다.**

## T2 · 중립 색 스케일을 브랜드 색조로 바꾼다

- **시작 커밋:** `a6737af`
- **지시문:** "`globals.css` 의 shadcn 중립 토큰을 브랜드 색조(green-grey)로 물들인다. 명도는 유지하고 채도만 얹는다. 라이트·다크 모두. 대비는 WCAG AA 를 지킨다."
- **게이트:** 하드코딩 hex 0건(토큰 밖) · 대비 검사 실패 0 · `build`
- **무엇을 가르나:** "대비 통과했습니다" 가 나오기 가장 쉬운 자리다. 실제로 재려면 렌더된 화면의
  `getComputedStyle` 색을 sRGB 로 바꿔 계산해야 하는데, 소스 값만 보면 상속·알파 때문에 어긋난다.

## T3 · 테마 토글을 붙인다

- **시작 커밋:** `bca8c0d` (스펙은 있고 구현 전)
- **지시문:** "라이트·다크 토글을 헤더에 붙인다. 새로고침해도 선택이 유지되고 첫 페인트에 라이트가 번쩍이지 않아야 한다."
- **게이트:** `lint`(React Compiler 규칙) · `build`
- **무엇을 가르나:** 교과서적인 `mounted` + `useEffect` 패턴이 `react-hooks/set-state-in-effect` 에
  걸린다. 학습 데이터에 가장 흔한 답이 지금은 규칙 위반이다. **모델이 관성으로 쓰는 코드를 잡아내는 과제.**

## T4 · 랜딩 배경을 요청마다 랜덤으로

- **시작 커밋:** `b9e28d7^` — **아직 공개되지 않은 커밋이다. 아래 "시작 상태" 참조**
- **지시문:** "랜딩 배경을 후보 다섯 장 중 한 장으로 한다. 방문할 때마다 다른 장이 나와야 한다."
- **게이트:** `lint`(purity) · `build` 출력에서 `/` 가 `ƒ` 인지 · 응답 10회에 2종 이상
- **무엇을 가르나:** 컴포넌트 본문의 `Math.random()` 이 `react-hooks/purity` 에 걸린다.
  클라이언트에서 섞으면 첫 페인트 뒤 그림이 바뀌어 번쩍인다. 정적 생성이면 빌드 때 한 번으로 굳는다.
  **셋 다 "동작은 한다" 라서 검증 없이는 구분되지 않는다.**

## T5 · 좁은 폭에서 헤더가 두 줄이 되는 것을 고친다

- **시작 커밋:** `a202858^` — **아직 공개되지 않은 커밋이다. 아래 "시작 상태" 참조**
- **지시문:** "375px 에서 헤더가 두 줄이 된다. 한 줄로 고친다."
- **게이트:** 375px 렌더에서 헤더 최소 한 줄 폭 < 375 · 링크 클릭 영역 ≥ 24x24
- **무엇을 가르나:** 눈으로 보고 "고쳤습니다" 로 끝내기 가장 쉬운 과제다. 실제로는 재야 한다 —
  펼친 상태 440px, 접은 상태 281px. 그리고 세로 여백을 바가 갖고 있어 링크 클릭 영역이
  글자 높이 11px 에 머무는 문제가 **지시문에 없이 같이 걸려 있다.**

## 시작 상태 — 지금 재현 불가능한 것이 둘 있다

T4·T5 의 시작 커밋(`b9e28d7^`, `a202858^`)은 **squash 머지로 사라진 브랜치에만 있다.**
로컬에는 남아 있지만 원격에 없어서 남이 재현할 수 없고, 언젠가 GC 로 사라진다.

**재현 불가능한 벤치마크는 반박당하는 게 아니라 무시당한다.** 공개 전에 아래를 해야 한다.

```bash
git tag bench/t4-base b9e28d7^
git tag bench/t5-base a202858^
git push origin bench/t4-base bench/t5-base
```

이건 원격을 건드리는 일이라 사용자 승인을 받고 실행한다.

## 뺀 과제와 이유

- **모노레포 세팅 + 경계 lint** — 함정이 셋(중첩 워크스페이스, eslint 버전 충돌, CI 타입 에러)이라
  판별력은 가장 높지만 회당 설치 시간이 길어 50회 예산에 안 맞는다. 별도 리포트로 낸다면 그때 쓴다
- **이미지 자산 교체** — Next 이미지 캐시가 같은 파일명을 계속 서빙하는 함정이 있지만,
  실패가 브라우저에서만 드러나 기계 채점이 안 된다
- **커밋·PR 절차** — 게이트의 성격이 다르다. 코드 품질이 아니라 협업 규약이라 같은 축에 못 올린다
