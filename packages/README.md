# packages

여러 앱이 가져다 쓰는 것을 둔다. 이름은 `@curvez/<이름>` 으로 짓는다.

## 여기 들어오는 것

- 둘 이상의 앱이 쓰거나, 앱 밖(npm)으로 나갈 수 있는 코드
- 설정 자체 — tsconfig, eslint, prettier 프리셋
- 빌드 산출물을 갖는 것. `exports` 필드로 진입점을 명시한다

## 여기 들어오지 않는 것

- 앱 하나만 쓰는 코드 → 그 앱 안에 둔다. 두 번째 사용처가 생길 때 옮긴다
- Claude Code 플러그인 → `plugins/curvez/`. npm 패키지가 아니라 마켓플레이스가 로드한다

**이유:** 사용처가 하나인 것을 패키지로 올리면 버전과 빌드 단계가 생기는데, 그 비용을 치르고
얻는 것이 없다. 옮기는 비용은 나중에도 같지만, 되돌리는 비용은 이미 퍼블리시한 뒤에 오른다.

## 규칙

- **패키지는 앱을 import 하지 않는다.** 의존은 한 방향(앱 → 패키지)이다
- **패키지끼리의 의존은 명시한다.** `workspace:*` 로 적고 암묵적 전역 참조를 만들지 않는다
- 앱에서 쓸 때도 상대 경로가 아니라 패키지 이름으로 부른다
