# component: AspectRatio

purpose: 가로세로 비를 고정한 상자. 안에 들어온 것이 그 비를 따른다

## 근거 — shadcn/ui 의 마크업만 옮겼다

### 1. 출처

| 항목             | 값                                                             |
| ---------------- | -------------------------------------------------------------- |
| 본 곳            | shadcn/ui <https://ui.shadcn.com/docs/components/aspect-ratio> |
| 본 날짜          | **2026-09-12**                                                 |
| 가져온 것        | 쓰는 방식 — 비를 정한 상자가 있고 그 안을 자식이 채운다        |
| 가져오지 않은 것 | Radix 프리미티브, 그리고 비를 숫자로 받는 API(아래 3번)        |
| 의존성           | 없다. `<div>` 하나다                                           |

**이 값들은 화면에서 센 것이 아니다.** 기존 9종의 `## 근거` 에 있는 `파일:줄` 이 이 문서에는 없다.
**handwork 사용처: 0곳.** 어느 화면에도 쓰인 적이 없다.

daisyUI 에는 대응하는 컴포넌트가 없다. 가장 가까운 것이 `mask`(<https://daisyui.com/components/mask/>)
인데 그것은 비를 고정하는 것이 아니라 도형으로 잘라 내는 것이라 **가져오지 않았다.**
**이유:** 잘라 내는 도형은 `clip-path` 값을 열 개 넘게 들여야 하고, 그 값들이
[`../tokens.md`](../tokens.md) 어디에도 근거가 없다.

### 2. Tailwind 의 `aspect-*` 로 된다. 임의값도 인라인 style 도 쓰지 않는다

**확인했다.** 이 저장소의 Tailwind 는 **4.3.3** 이고(`../../package.json` 의 `tailwindcss`),
네 클래스가 모두 유틸리티로 생성된다.

| 클래스          | 생성되는 선언          |
| --------------- | ---------------------- |
| `aspect-square` | `aspect-ratio: 1 / 1`  |
| `aspect-video`  | `aspect-ratio: 16 / 9` |
| `aspect-4/3`    | `aspect-ratio: 4/3`    |
| `aspect-3/2`    | `aspect-ratio: 3/2`    |

재현: Tailwind 의 `compile()` 에 `@import "tailwindcss"` 를 넣고 위 네 이름을 후보로 주면
네 규칙이 모두 나온다. **분수 표기(`aspect-4/3`)가 v4 의 기본 기능이라 임의값(`aspect-[4/3]`)이
필요하지 않다.** [`../tokens.md`](../tokens.md) 가 "임의값을 쓰지 마라" 로 정한 것을 그대로 지킨다.

**인라인 `style={{ aspectRatio }}` 도 쓰지 않는다.**
**이유:** 값을 CSS 가 아니라 JS 가 들고 있게 되어, 어떤 비가 실제로 쓰이는지 스타일시트에서 셀 수 없다.

### 3. 비를 숫자로 받지 않는다

shadcn/ui 는 `ratio={16 / 9}` 처럼 숫자를 받는다. **여기서는 이름 넷 중 하나다.**
**이유:** 숫자를 받으면 클래스를 `aspect-${w}/${h}` 로 만들게 되는데, Tailwind 는 소스 파일의
문자열을 훑어 클래스를 생성하므로 그 조립된 이름을 찾지 못한다. 화면에서 비가 통째로 사라지고,
빌드도 타입 검사도 통과한 채로 그렇게 된다.

**다섯 번째 비가 필요하면 고칠 위치는 둘이다** — `../../src/ui/aspect-ratio.tsx` 의 `RATIO` 와
이 문서의 위 표.

## props

| 이름     | 타입                                          | 필수  | 기본값    | 의미                     |
| -------- | --------------------------------------------- | ----- | --------- | ------------------------ |
| ratio    | `"square"` \| `"video"` \| `"4/3"` \| `"3/2"` | X     | `"video"` | 가로세로 비. 네 개뿐이다 |
| children | `React.ReactNode`                             | **O** | —         | 상자를 채울 것           |

**`cva` 를 쓰지 않는다.** 구분할 축이 `ratio` 하나뿐이라 평범한 객체 하나로 끝난다
(`../../src/ui/aspect-ratio.tsx` 의 `RATIO`).

**기본값이 `video`(16:9)인 이유:** 넷 중 가장 자주 쓰일 자리가 영상·썸네일이고, 정사각이 기본이면
비를 적지 않은 자리가 전부 정사각으로 잘린다. 기본값을 바꾸려면 `RATIO` 옆의 기본 인자 한 곳이다.

**`className` 을 열지 마라.**
**이유:** 이 컴포넌트가 정하는 값은 비 하나뿐이다. 모서리·테두리·잘라내기는 안에 들어오는 것이
갖는다 — 이미지면 `rounded-lg object-cover` 를 그 `<img>` 에 준다.

**안의 요소를 채우는 일을 하지 마라.** `*:size-full` 같은 자식 선택자를 붙이지 않는다.
**이유:** 채우면 안 되는 자식(가운데 놓인 아이콘, 짧은 글자)까지 늘어난다. 채울 자식에게는
부르는 쪽이 `size-full` 과 `object-cover` 를 준다.

### 값 (`../../src/ui/aspect-ratio.tsx`)

| 축   | 값                                       |
| ---- | ---------------------------------------- |
| 폭   | `w-full` — 부모를 채운다                 |
| 높이 | 없다. `aspect-ratio` 가 폭에서 계산한다  |
| 면   | 없다. 배경도 테두리도 반경도 갖지 않는다 |
| 넘침 | `overflow-hidden` 을 주지 않는다         |

**`overflow-hidden` 을 주지 않는 이유:** 안에 `<img class="object-cover">` 가 들어오면 그 이미지가
스스로 잘린다. 상자가 또 자르면 두 곳이 같은 일을 하고, 자르지 말아야 할 자식(모서리에 얹힌
[`Indicator.md`](Indicator.md) 의 표시 같은 것)까지 잘린다.

| empty         | 없다   | `children` 이 필수다. **비어 있으면 이 컴포넌트를 쓰지 마라 — 이유:** 아무것도 없는 자리에 높이만 잡히면 까닭 없는 빈 칸이 생긴다                                                                      |
| error         | 없다   | 상태를 갖지 않아 실패할 동작이 없다. 이미지 로드 실패는 그 `<img>` 의 일이다                                                                                                                           |

**전이를 넣지 마라.** `aspect-ratio.tsx` 에 `transition-*` 이 0건이다.
**이유:** `ratio` 는 렌더할 때 정해지고 그 뒤로 바뀌지 않는다.

## a11y

- a11y:label — 이름을 붙이지 마라. **이유:** 역할 없는 `<div>` 라 낭독기가 이 층을 통과한다. 이름은 안에 들어오는 것이 갖는다 — 이미지면 그 `<img>` 의 `alt` 다. **장식용 이미지면 `alt=""` 를 준다 — 이유:** 비를 고정한 상자가 있다는 사실은 낭독기에 알릴 내용이 아니다
- a11y:focus — 포커스 대상이 **0개다.** 포커스 순서에 끼어들지 않는다. 포커스 순서는 `children` 의 DOM 순서와 같고 이 상자가 끼어들지 않는다
- a11y:contrast — 해당 없다. **자기 색을 갖지 않는다.** 배경도 글자도 없어 계산할 쌍이 없다. 안에 글자를 넣는다면 그 글자의 대비는 그 자리가 갖는 배경에 달렸고, 이미지 위 글자는 고정 쌍으로 계산되지 않는다 — **이미지 위에 글자를 얹지 마라. 이유:** 실제 대비가 이미지마다 달라져 어느 쌍을 검사해야 하는지 정할 수 없다
- a11y:target — 해당 없다. 클릭 대상이 아니다. 이 상자를 눌러야 하면 [`Card.md`](Card.md) 로 감싼다 — 그쪽이 `<Link>` 라 새 탭 열기와 주소 복사가 된다
- a11y:role — 역할을 지정하지 마라. `<div>` 다. **`role="img"` 나 `role="presentation"` 을 붙이지 마라 — 이유:** 전자는 안의 내용을 하나의 그림으로 묶어 버려 안에 있는 글자가 읽히지 않고, 후자는 이미 역할이 없는 요소에 아무것도 더하지 않는다

## responsive

- 브레이크포인트 분기가 **0건**이다. `aspect-ratio.tsx` 전체에 `sm:`·`md:` 가 없다
- **비가 모든 폭에서 같다.** 폭이 375px 이면 높이가 그 비만큼, 1024px 이면 그만큼이다. 이것이 이 컴포넌트의 전부다
- **폭에 따라 비를 바꾸지 마라** — `md:aspect-square` 같은 것. **이유:** 이미지가 잘리는 범위가 768px 을 넘는 순간 달라져, 좁은 화면에서 보이던 부분이 넓은 화면에서 사라진다. 비를 바꿔야 하는 자리면 그것은 이미지가 둘인 자리다
- 격자 안에 넣을 때 `md:grid-cols-2` 를 쓴다 — [`../tokens.md`](../tokens.md) 가 목록 2열로 정한 값이다. 열이 둘이 되면 각 상자의 폭이 절반이 되고 높이도 비에 따라 함께 줄어든다
- **높이를 `h-*` 로 덮지 마라.** 비와 높이 두 값이 싸우면 `aspect-ratio` 가 진다 — 이유: 명시한 높이가 있으면 브라우저는 비를 무시한다

## 상호작용

- 없다. hover / focus-visible / active 대상이 아니다
