# component: ButtonGroup

purpose: 붙어 선 버튼 여럿을 한 덩어리로 묶는다. 맞닿는 모서리를 없애고 테두리를 겹친다

## 근거 — shadcn/ui 의 마크업만 옮겼다

### 1. 출처

| 항목             | 값                                                                     |
| ---------------- | ---------------------------------------------------------------------- |
| 본 곳            | shadcn/ui <https://ui.shadcn.com/docs/components/button-group>         |
| 본 날짜          | **2026-09-12**                                                         |
| 가져온 것        | 마크업 구조 — `role="group"` 하나와 자식 선택자로 주는 모서리·겹침     |
| 가져오지 않은 것 | 클래스, 세로 방향, 그리고 `input`·`select` 를 함께 묶는 규칙(아래 3번) |
| 의존성           | 없다. `<div>` 하나다                                                   |

**이 값들은 화면에서 센 것이 아니다.** 기존 9종의 `## 근거` 에 있는 `파일:줄` 이 이 문서에는 없다.
**handwork 사용처: 0곳.** 어느 화면에도 쓰인 적이 없다.

daisyUI 에는 대응하는 컴포넌트가 `join` 이라는 다른 이름으로 있고 마크업이 같은 꼴이다.
이름은 shadcn/ui 쪽을 따랐다 — 이 라이브러리의 다른 20종이 전부 shadcn 이름을 쓴다.

### 2. 어디에 기대는가 — `Button` 의 값 둘

이 컴포넌트는 [`Button.md`](Button.md) 의 값 둘을 알고 있어야 동작한다.

| 무엇        | 값                     | 여기서 어떻게 쓰나                                    |
| ----------- | ---------------------- | ----------------------------------------------------- |
| 바깥 모서리 | `rounded-md` (8px)     | **손대지 않는다.** 묶음의 양끝 모서리로 그대로 남는다 |
| 높이        | `h-10` (40px) · `px-4` | 높이를 맞출 필요가 없다. 자식이 이미 같은 높이다      |

**안쪽 모서리만 지운다.** 첫 자식의 왼쪽과 마지막 자식의 오른쪽은 건드리지 않으므로,
`Button` 이 반경을 바꾸면 묶음의 양끝도 따라 바뀐다. 두 곳에 값을 적지 않는다.

**`variant="outline"` 을 함께 쓸 때가 이 컴포넌트의 본래 자리다.** 테두리가 있어야 겹칠 선이 있다.
`default`(면만 있는 것)에서도 동작하지만 `-ml-px` 의 1px 겹침이 눈에 보이지 않는다 —
**그 자리에는 묶지 말고 `gap-2` 로 떨어뜨리는 편이 낫다. 이유:** 면이 붙으면 어디까지가 한 버튼인지
경계가 사라진다.

### 3. 세로 묶음을 만들지 않는다

shadcn/ui 는 `orientation="vertical"` 을 연다. **만들지 않는다.**
**이유:** 없앨 모서리(`rounded-t-none`/`rounded-b-none`)도 겹치는 방향(`-mt-px`)도 전부 달라서,
한 컴포넌트 안에 규칙이 두 벌 생긴다. 쓰는 곳이 0곳인 값을 위해 규칙을 두 벌 두면 어느 쪽이
검증된 것인지 판정할 수 없다. 필요해지면 그때 별도 컴포넌트로 연다.

**`input`·`select` 를 함께 묶는 규칙도 가져오지 않았다.**
**이유:** [`Input.md`](Input.md) 와 [`Select.md`](Select.md) 의 높이·반경이 `Button` 과 같다는 것을
확인한 적이 없다. 확인하지 않은 전제 위에 선택자를 쌓지 않는다.

## props

| 이름     | 타입              | 필수  | 기본값 | 의미                                  |
| -------- | ----------------- | ----- | ------ | ------------------------------------- |
| label    | `string`          | **O** | —      | 묶음의 이름. `aria-label` 로 들어간다 |
| children | `React.ReactNode` | **O** | —      | `Button` 둘 이상                      |

**`cva` 를 쓰지 않는다.** 구분할 축이 0개다. 방향도 크기도 하나뿐이다.

**`label` 을 선택으로 만들지 마라.**
**이유:** `role="group"` 은 이름이 있어야 화면 낭독기가 "정렬, 그룹" 처럼 경계를 말한다. 이름이
없으면 버튼 셋이 그냥 이어 읽혀 묶음이라는 사실이 사라지고, 그러면 `role="group"` 을 붙인 값이 없다.

**자식을 하나만 넣지 마라.** 묶을 것이 없다.
**이유:** 자식이 하나면 `:not(:first-child)` 와 `:not(:last-child)` 가 둘 다 걸리지 않아
`Button` 을 그대로 쓴 것과 결과가 같다. 그런데 `role="group"` 만 남아 낭독기가 없는 묶음을 말한다.

**`className` 을 열지 마라.**
**이유:** 묶음의 폭은 자식이 정하고(`inline-flex`) 자리는 부모가 정한다. 여기에 여백을 덧붙이면
같은 묶음이 화면마다 다른 자리에 선다.

### 값 (`../../src/ui/button-group.tsx`)

| 조각        | 값                                                                                 |
| ----------- | ---------------------------------------------------------------------------------- |
| 묶음        | `inline-flex items-stretch` + `role="group"`                                       |
| 안쪽 모서리 | `[&>*:not(:first-child)]:rounded-l-none` · `[&>*:not(:last-child)]:rounded-r-none` |
| 겹침        | `[&>*:not(:first-child)]:-ml-px`                                                   |
| 포커스 층   | `[&>*:focus-visible]:z-10`                                                         |

**`first:`/`last:` 를 자식에 붙이지 않고 묶음 쪽 선택자로 주는 이유:** 자식은 `Button` 이고
그 `className` 은 [`Button.md`](Button.md) 가 "색·크기를 여기서 덮어쓰지 마라" 로 정한 자리다.
바깥에서 쓰는 사람이 버튼마다 모서리 클래스를 적게 하면 하나를 빠뜨렸을 때 그 버튼만 둥글게 남는다.

**구체성이 맞는지 확인했다.** `[&>*:not(:first-child)]:rounded-l-none` 은
`.<클래스> > :not(:first-child)` 로 컴파일되어 클래스 하나 + 의사 클래스 하나 = **(0,2,0)** 이다.
`Button` 의 `.rounded-md` 는 **(0,1,0)** 이라 진다. 순서에 기대지 않는다.

## states

| state         | 트리거               | 시각 변화                                                                                                                                                                                                                                  |
| ------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| default       | —                    | 버튼들이 1px 씩 겹쳐 한 덩어리로 선다. 양끝만 `rounded-md`(8px), 안쪽 모서리는 각지다                                                                                                                                                      |
| hover         | 자식 위 포인터       | 묶음 자신은 바뀌지 않는다. `button-group.tsx` 에 `hover:` 가 0건이다. hover 는 자식 하나가 [`Button.md`](Button.md) 의 규칙대로 갖는다                                                                                                     |
| focus-visible | 자식에 키보드 포커스 | **그 자식의 `z-index` 가 10 이 된다.** 링은 자식의 것이고 묶음은 층만 올린다. 아래 `### 포커스 링` 참고                                                                                                                                    |
| pressed       | 자식을 누름          | 묶음 자신은 바뀌지 않는다. `active:scale-97` 은 [`Button.md`](Button.md) 가 아이콘 버튼에만 쓴다고 정했다 — **묶음 안에서 축소를 쓰지 마라. 이유:** 겹쳐 선 버튼 하나가 줄면 옆 버튼과 사이에 틈이 벌어진다                                |
| disabled      | 자식이 `disabled`    | 묶음에 비활성 개념이 없다. 자식 하나가 `disabled:opacity-50` 으로 흐려지고 묶음의 모양은 그대로다. **묶음 전체를 비활성으로 만드는 prop 을 두지 마라 — 이유:** `fieldset disabled` 가 이미 그 일을 하고, 여기서 다시 하면 두 경로가 생긴다 |
| loading       | 없다                 | 스스로 데이터를 불러오지 않는다. 자식 하나가 기다리면 그 버튼 안에 [`Loading.md`](Loading.md) 를 `size="sm"` 으로 넣는다                                                                                                                   |
| empty         | 없다                 | `children` 이 필수다. 비면 `role="group"` 만 남으므로 **렌더하지 마라.** 조건부 렌더는 부르는 쪽이 한다                                                                                                                                    |
| error         | 없다                 | 상태를 갖지 않아 실패할 동작이 없다                                                                                                                                                                                                        |

**전이를 넣지 마라.** `button-group.tsx` 에 `transition-*` 이 0건이다.
**이유:** 묶음 자신은 상태가 바뀌지 않는다. 전이는 자식인 `Button` 이 이미 갖고 있고
`motion-reduce:transition-none` 짝도 거기에 붙어 있다.

### 포커스 링 — 이웃에 가리지 않게 `z-index` 를 올린다

[`Button.md`](Button.md) 의 링은 `focus-visible:outline-2 outline-offset-2 outline-ring` 이다.
**`outline-offset-2` 라 링이 버튼 **밖** 2px 에 그려진다.** 그런데 이 묶음은 `-ml-px` 로 버튼을
1px 겹쳐 세우므로, 나중에 그려지는 오른쪽 이웃이 그 링의 왼쪽 부분을 자기 배경으로 덮는다.
링이 삼면만 남아 어디에 포커스가 있는지 흐려진다.

**그래서 `[&>*:focus-visible]:z-10` 을 준다.** 포커스를 받은 자식이 층에서 올라와 링 전체가 보인다.

**`position` 을 주지 않아도 되는 이유:** 이 묶음이 `inline-flex` 라 자식이 flex 항목이고,
flex 항목은 `position: static` 이어도 `z-index` 가 먹는다(CSS Flexbox 명세).
`relative` 를 함께 주면 자식마다 stacking context 가 생겨 묶음 안에서 툴팁·팝오버가 갇힌다.

**`z-10` 인 이유:** 형제 사이에서만 이기면 되므로 가장 낮은 단계면 충분하다. 더 올리면 이 묶음이
화면의 다른 층(헤더 바 등)을 넘는다.
**고칠 위치:** `../../src/ui/button-group.tsx` 의 그 클래스 한 곳.

## a11y

- a11y:label — `aria-label={label}` 이다. **필수다.** 눈에 보이는 제목이 옆에 이미 있으면 `aria-labelledby` 로 잇는 편이 낫지만 그 prop 을 열지 않았다 — 이유: 두 경로가 생기면 어느 값이 적용되는지 화면에서만 드러난다. 자식 버튼의 이름은 각자 갖는다. **아이콘만 있는 자식은 `aria-label` 이 필수다** — [`Button.md`](Button.md) 의 `a11y:label` 이 그렇게 정했고, 그 규칙은 묶음 안에서도 그대로다
- a11y:focus — 포커스 대상은 **자식의 개수와 같다.** 묶음 자신은 포커스를 받지 않는다. 화살표 키로 자식 사이를 옮기는 roving tabindex 를 만들지 마라 — 이유: 그것은 `radiogroup`·`toolbar` 의 상호작용이고, 그러려면 상태와 키보드 처리가 들어와 `"use client"` 가 필요해진다. 이 컴포넌트는 탭으로 하나씩 지나간다. **포커스 링이 이웃에 가리는 문제는 `z-index` 로 푼다** — 위 `### 포커스 링` 에 값과 이유가 있다
- a11y:contrast — 묶음은 자기 색을 갖지 않는다. 대비는 자식이 갖고 [`Button.md`](Button.md) 가 정본이다. **겹친 1px 때문에 새로 생기는 쌍은 없다 — 이유:** 겹치는 것은 같은 색의 테두리끼리다. 포커스 링 `--ring` / 바탕 `--background` 는 라이트 **6.02** · 다크 **12.96** 이다([`../tokens.md`](../tokens.md) `## 대비 검증` 의 "링크 hover·강조/캔버스")
- a11y:target — 자식 버튼이 각각 규칙을 받는다. [`Button.md`](Button.md) 의 기본 크기가 `h-10 px-4`(40px 높이)라 24x24 를 넘는다. **`-ml-px` 로 1px 겹쳐도 각 버튼의 클릭 면적이 24px 아래로 내려가지 않는다**
- a11y:role — `group` 이다. **`toolbar` 를 쓰지 마라 — 이유:** 그 역할은 화살표 키 이동을 약속하는데 이 컴포넌트는 그것을 구현하지 않는다. 약속만 하고 지키지 않으면 키보드 사용자가 갇힌다. **`radiogroup` 도 쓰지 마라 — 이유:** 하나만 고르는 상태가 필요한데 이 컴포넌트는 상태를 갖지 않는다. 그 자리는 [`Select.md`](Select.md) 나 별도 컴포넌트다

## responsive

- 브레이크포인트 분기가 **0건**이다. `button-group.tsx` 전체에 `sm:`·`md:` 가 없다
- `inline-flex` 라 **폭이 자식의 합이다.** 부모를 채우지 않는다
- **줄바꿈되지 않는다.** `flex-wrap` 을 주지 않았다 — 이유: 줄이 바뀌면 두 번째 줄 첫 버튼의 왼쪽 모서리가 각진 채로 남아 묶음이 끊어져 보인다. `375px` 화면에서 자식 셋이 넘치면 그 자리는 묶음이 아니다. 글자를 줄이거나 [`Select.md`](Select.md) 로 바꾼다
- **넘치는지 세는 법:** 375px 에서 화면 좌우 여백 `px-5` 두 번을 빼면 335px 이 남는다. `Button` 기본이 `h-10 px-4`(좌우 32px + 글자)이므로 두 글자 버튼 하나가 대략 64px, 셋이면 겹침 2px 을 빼고 약 190px 이다. 넷까지는 들어가고 다섯부터는 글자 길이를 봐야 한다
- 세로로 쌓는 분기(`flex-col`)를 만들지 마라 — 이유: 위 `## 근거` 의 3번이 세로 묶음을 만들지 않기로 정했다. 분기로 넣으면 그 결정이 브레이크포인트 하나로 뒤집힌다

## 상호작용

- 묶음 자신은 hover / focus-visible / active 대상이 아니다
- 묶음이 하는 유일한 상호작용 처리는 **포커스를 받은 자식의 층을 올리는 것** 하나다 (`[&>*:focus-visible]:z-10`)
- 그 밖의 hover · 눌림 · 비활성은 전부 자식 `Button` 의 것이고 [`Button.md`](Button.md) 가 정본이다
