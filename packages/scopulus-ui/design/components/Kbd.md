# component: Kbd

purpose: 눌러야 하는 키 하나를 본문 글자와 구분해 보여 준다. 여러 키를 주면 조합 하나가 된다

## 근거 — daisyUI 와 shadcn 에서 구조만 옮겼다

### 1. 이 값은 화면에서 센 값이 아니다

**handwork 화면 사용처: 0곳.** 화면에 한 번도 나온 적이 없다.
기존 9종의 `## 근거` 에 있는 `파일:줄` 표가 이 문서에는 **없다.** 지어낼 수 없어서 비운 것이다.
값의 출처는 아래 두 벤더와 [`../tokens.md`](../tokens.md) 뿐이다.

| 항목           | 값                                                          |
| -------------- | ----------------------------------------------------------- |
| 참고한 곳 1    | daisyUI Kbd — <https://daisyui.com/components/kbd/>         |
| 참고한 곳 2    | shadcn/ui Kbd — <https://ui.shadcn.com/docs/components/kbd> |
| 옮긴 날짜      | **2026-09-12**                                              |
| 옮긴 것        | 요소 선택(`<kbd>`)과 조합의 표기 방식                       |
| 옮기지 않은 것 | 클래스 이름 전부. `kbd` · `kbd-xs` 같은 이름을 쓰지 않는다  |

**클래스는 우리 토큰으로 다시 썼다.** 키 한 칸은 `--muted` 면 위의 `--muted-foreground` 글자에
`--border` 테두리 1px 이다. 그 색 쌍은 [`../tokens.md`](../tokens.md) 의 `## 대비 검증` 에 이미
있는 쌍이다(칩 글자/칩 배경). **새 대비 쌍을 만들지 않았다.**

### 2. 두 벤더가 다른 곳과 고른 쪽

| 갈래      | daisyUI                           | shadcn/ui                | 우리                              |
| --------- | --------------------------------- | ------------------------ | --------------------------------- |
| 조각 수   | 1개 (`<kbd>`)                     | 2개 (`Kbd` · `KbdGroup`) | **1개**                           |
| 조합 표기 | `<kbd>` 사이에 글자 `+` 를 적는다 | `KbdGroup` 으로 감싼다   | `keys` 배열 하나로 받는다         |
| 구분자    | 본문 글자다 — 읽힌다              | 컴포넌트가 낸다          | **컴포넌트가 내고 `aria-hidden`** |
| 크기 축   | 5단계                             | 없다                     | **없다**                          |

**조각을 둘로 나누지 않았다. 이유:** 묶음을 따로 내보내면 배럴에 이름이 둘 늘고, 부르는 쪽이
`Kbd` 를 `KbdGroup` 없이 여러 개 늘어놓는 길이 열린다. 그 길로 가면 구분자가 다시 본문 글자가
된다. 한 컴포넌트가 두 모양을 다 내면 그 길이 없다.

**daisyUI 처럼 `+` 를 본문 글자로 두지 않았다. 이유:** 화면에서는 같아 보이지만 소리로는
"커맨드 플러스 케이" 가 되어 키가 셋인 것처럼 들린다.

### 3. 조합에 `<kbd>` 를 겹치는 근거

HTML 이 키 조합의 표기를 `<kbd>` 중첩으로 정해 두었다 —
<https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/kbd>.
바깥 `<kbd>` 가 "이 조합을 누른다", 안쪽 `<kbd>` 하나하나가 "이 키" 다.
**바깥을 `<span>` 으로 바꾸지 마라 — 이유:** 조합 전체가 키보드 입력이라는 뜻이 사라지고
안쪽 키 셋이 서로 무관한 세 조각으로 남는다.

## props

**두 모양 중 하나를 고르는 유니온이다.** 둘을 함께 줄 수 없다.

| 이름     | 타입       | 필수        | 기본값 | 의미                                            |
| -------- | ---------- | ----------- | ------ | ----------------------------------------------- |
| children | `string`   | O (키 하나) | —      | 키 이름 하나. `K` · `Esc` · `⌘`                 |
| keys     | `string[]` | O (조합)    | —      | 함께 누르는 키들. 사이의 `+` 는 컴포넌트가 낸다 |

**`children` 이 `string` 이다. `ReactNode` 가 아니다.**
**이유:** 키 이름은 글자 하나짜리 사실이다. 요소를 받으면 아이콘이나 링크가 키 칸 안에 들어오고,
그 순간 "무엇을 누르는가" 가 글자가 아닌 것으로 표현된다.

**구분자를 받는 prop 을 두지 마라.**
**이유:** `-` 나 `then` 으로 바꿀 수 있게 열면 그 값의 `aria-hidden` 여부를 부르는 쪽이 정하게 된다.
`+` 하나로 잠가 두면 숨기는 규칙이 한 곳에만 있다.

**`className` 을 받지 않는다.**
**이유:** 크기도 색도 축이 없다. 열면 두 번째 키 모양이 화면에 들어온다.

### 값 (`../../src/ui/kbd.tsx` 의 `KEY_CLASS`)

| 조각      | 값                                  | 스케일 근거                                               |
| --------- | ----------------------------------- | --------------------------------------------------------- |
| 반경      | `rounded-sm` (6px)                  | [`../tokens.md`](../tokens.md) `## 형태` — 인라인 코드 칸 |
| 안쪽 여백 | `px-2 py-0.5` (좌우 8px · 세로 2px) | 같은 문서의 태그 칩 값(4회)                               |
| 면 / 글자 | `--muted` / `--muted-foreground`    | 칩과 같은 쌍                                              |
| 테두리    | `--border` 1px                      | 칩에는 없다. **이 1px 이 칩과 키를 가르는 유일한 차이다** |
| 글자      | `font-mono` · `text-xs` (12px)      | 같은 문서의 서체 2종 · 크기 8단계 안                      |
| 조합 사이 | `gap-1` (4px)                       | 간격 12단계 안(스텝 1)                                    |

**`font-mono` 에 한글을 넣지 마라.** [`../tokens.md`](../tokens.md) 의 서체 절이 정한 규칙이다 —
Geist Mono 에 한글 글립이 없어 폰트가 대체되고 같은 줄에서 서체가 달라진다. 키 이름은 영문과
기호뿐이라 이 규칙에 걸리지 않는다.
**확인하지 못한 것:** `⌘` `⇧` `⌥` 같은 기호가 Geist Mono 에 있는지는 재지 못했다. 없으면 그
글자만 다른 서체로 대체된다 — 화면에서 확인해야 한다.

## states

| state         | 트리거 | 시각 변화                                                                                                                              |
| ------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| default       | —      | `--muted` 면에 `--border` 1px, `--muted-foreground` 글자. 조합이면 키 칸들이 `gap-1` 로 늘어서고 사이에 `+` 가 선다                    |
| hover         | 없다   | 상호작용 요소가 아니다. `kbd.tsx` 에 `hover:` 가 0건이다. **누르면 무슨 일이 일어나는 것은 이 요소가 아니다** — 실제 키보드다          |
| focus-visible | 없다   | 포커스를 받지 않는다. `tabindex` 를 주지 마라 — 이유: 읽기만 하는 표기가 포커스 순서에 끼면 키보드 이동 횟수만 늘어난다                |
| pressed       | 없다   | **눌린 모양을 만들지 마라.** 이 요소는 지금 눌려 있는 키가 아니라 눌러야 하는 키의 이름이다. 눌림을 표현하면 상태를 가진 것처럼 보인다 |
| disabled      | 없다   | 비활성 개념이 없다. 쓸 수 없는 단축키면 그 문장을 렌더하지 않는다                                                                      |
| loading       | 없다   | 자기 데이터가 없다                                                                                                                     |
| empty         | 없다   | `children` 이 빈 문자열이면 빈 칸만 남는다 — 빈 키 이름으로 부르지 마라. `keys` 가 빈 배열이면 아무것도 그리지 않는다                  |
| error         | 없다   | 상태를 갖지 않아 실패할 동작이 없다                                                                                                    |

**전이를 넣지 마라.** `kbd.tsx` 에 `transition-*` 이 0건이다.
**이유:** 상태가 바뀌지 않는 표시 요소다. 전이할 대상이 없다.

## a11y

- a11y:label — 라벨을 따로 주지 않는다. 키 이름 글자가 그대로 읽힌다. **`aria-label="커맨드"` 같은 것을 붙이지 마라 — 이유:** 보이는 글자(`⌘`)와 읽히는 글자가 달라지고, 그 번역이 맞는지 판정할 근거가 없다. 조합의 `+` 에는 `aria-hidden` 이 붙는다 — 이유: 함께 누른다는 뜻은 한 조합 안에 있다는 사실이 이미 말한다
- a11y:focus — 포커스 대상이 **0개**다. 포커스 순서에 끼지 않는다
- a11y:contrast — fg=`--muted-foreground` / bg=`--muted` 라이트 4.91 · 다크 6.51 ([`../tokens.md`](../tokens.md) `## 대비 검증` 의 대비값, 4.5:1 통과). 테두리 `--border` 는 글자가 아니라 면의 경계라 이 기준을 받지 않는다 — 같은 문서가 카드 테두리에 대해 이미 같은 판단을 내렸다. **새 쌍을 만들지 않았다**
- a11y:target — 클릭 대상이 **아니다.** 24x24 규칙(WCAG 2.5.8)이 걸리지 않는다. 키 칸의 실제 높이는 `text-xs`(12px) + `py-0.5` 두 번(4px) + 테두리 2px 이라 24px 에 못 미치지만, 누를 수 없는 표기라 그 기준의 대상이 아니다
- a11y:role — `<kbd>` 에는 암묵 role 이 없다. 그대로 둔다. **`role` 을 주지 마라 — 이유:** 맞는 role 이 없다. `kbd` 라는 ARIA role 은 존재하지 않고, `img` 나 `text` 를 얹으면 안쪽 글자가 하나의 그림으로 묶여 조합 안의 키 구분이 사라진다

## responsive

- **브레이크포인트 분기 0건.** `kbd.tsx` 에 `sm:` · `md:` 가 하나도 없다. 375px 에서나 1024px 에서나 같은 크기다
- 본문 글 안에 섞일 수 있다. `align-middle` 이 걸려 있어 앞뒤 글자의 가운데에 선다. 한 줄에 들어가지 못하면 조합 전체가 다음 줄로 넘어간다 — 바깥 `<kbd>` 가 `inline-flex` 라 조합 중간에서 끊기지 않는다
- **줄바꿈을 막는 값을 넣지 마라 — 이유:** 좁은 화면에서 긴 문장 안의 조합이 넘치는 대신 가로 스크롤을 만든다

## 상호작용

- 없다. hover / focus-visible / active 대상이 아니다
