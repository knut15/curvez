# component: Label

purpose: 입력의 이름. `<label>` 하나를 내고 `htmlFor` 로 컨트롤에 묶는다

## 근거 — shadcn/ui 의 마크업 구조만 옮겼다

### 1. 출처

**이 컴포넌트는 화면에서 센 값이 아니다.** handwork 화면에 라벨이 쓰인 자리가 **0곳**이다.
`## 근거` 에 `파일:줄` 이 없는 것은 빠뜨린 것이 아니라 셀 화면이 없기 때문이다.

| 항목           | 값                                                                           |
| -------------- | ---------------------------------------------------------------------------- |
| 구조 출처      | shadcn/ui `label` — <https://ui.shadcn.com/docs/components/label>            |
| 옮긴 것        | `<label>` 요소 하나, `htmlFor` 로 묶는 방식, `text-sm font-medium` 글자 단계 |
| 옮기지 않은 것 | 클래스 문자열 전체. 값은 [`../tokens.md`](../tokens.md) 로 다시 썼다         |
| 의존성         | 없다. `@base-ui/react` 도 `cva` 도 쓰지 않는다                               |
| 소스           | [`../../src/ui/label.tsx`](../../src/ui/label.tsx)                           |

**export 1개**

| export  | 태그      |
| ------- | --------- |
| `Label` | `<label>` |

**variant 축이 없다. size 축도 없다.** 구분할 축이 하나도 없어 `cva` 를 쓰지 않는다.

### 2. 값을 어디에 맞췄나

| 축        | 값                                    | 맞춘 곳                                                        |
| --------- | ------------------------------------- | -------------------------------------------------------------- |
| 글자 크기 | `text-sm` = 14px                      | `input.tsx:11` 의 `md:text-sm` 과 같은 단계                    |
| 굵기      | `font-medium`                         | [`../tokens.md`](../tokens.md) `### 굵기` 의 5단계 안          |
| 행간      | `leading-none`                        | 라벨은 한 줄이다. 컨트롤과의 간격은 `Field` 의 `gap-2` 가 준다 |
| 비활성    | `group-has-disabled/field:opacity-50` | `checkbox.tsx:10` 이 이미 쓰는 이름과 같다                     |

**색을 지정하지 않는다.** `--foreground` 를 상속한다.
**이유:** 라벨을 `--muted-foreground` 로 내리면 설명 문단과 같은 단계가 되어 어느 쪽이 이름인지
판정할 수 없다. 이름은 본문과 같은 단계에 두고 설명만 한 단계 내린다.

### 3. 필수 표시(`*`)를 내지 않는다

**결정: 별표를 렌더하지 않는다. `required` prop 도 두지 않는다.**

**이유 둘.**

1. [`Input.md`](Input.md) 의 `a11y:label` 이 이미 정했다 — "`required` 를 준 필드는 라벨 글자에
   필수임을 적는다. **별표 하나만 쓰지 마라.**" 별표는 화면 낭독기가 "별" 로 읽거나 장식으로
   보고 건너뛴다. 어느 쪽이든 필수라는 뜻이 전달되지 않는다
2. 별표를 내려면 색이 필요하고(관례상 `--destructive`), 그러면 **아직 잘못되지 않은 필드에
   오류 색이 먼저 나온다.** 오류 색은 `aria-invalid` 하나에만 쓴다

필수는 라벨 글자로 적는다 — `사례 제목 (필수)`. `<input required>` 는 그대로 준다.

**바꿀 때 고칠 위치:** 이 절과 `../../src/ui/label.tsx` 의 props 타입.

## props

| 이름     | 타입              | 필수 | 기본값 | 의미                      |
| -------- | ----------------- | ---- | ------ | ------------------------- |
| htmlFor  | `string`          | O    | —      | 이름을 붙일 컨트롤의 `id` |
| children | `React.ReactNode` | O    | —      | 라벨 글자                 |

**`htmlFor` 를 선택으로 두지 마라.**
**이유:** 이름 없는 컨트롤은 화면 낭독기에서 "편집" 으로만 읽힌다. 타입이 막지 않으면 그 상태가
화면에 나올 때까지 드러나지 않는다. 스토리의 axe 검사도 컨트롤 쪽 위반(`label`)으로 잡지 라벨
쪽에서는 잡지 못한다.

**컨트롤을 감싸는 쓰임(`<Label><Input/></Label>`)을 열지 않는다.**
**이유:** 감싸는 방식과 `htmlFor` 방식을 둘 다 허용하면 `Field` 가 만든 `id` 를 쓰지 않는 라벨이
생기고, 그때 무엇이 컨트롤의 이름인지 판정할 근거가 사라진다. 감싸는 라벨이 필요한 곳은
[`Radio.md`](Radio.md) 하나이고 그것은 자기 라벨을 스스로 갖는다.

**`className` 을 받지 않는다.**
**이유:** 라벨의 값이 한 벌뿐이고 위치는 부모(`Field` · `InputGroup` 예제의 감싸개)가 정한다.
덧붙일 구멍을 열면 화면마다 라벨 크기가 달라진다.

**`required` prop 을 두지 않는다.** 근거는 위 `### 3` 에 있다.

## states

| state         | 트리거              | 시각 변화                                                                                                                                                                |
| ------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| default       | —                   | `text-sm font-medium leading-none`, 색은 `--foreground` 상속. 배경·테두리 없음                                                                                           |
| hover         | 없음                | `hover:` 가 0건이다. **hover 색을 만들지 마라 — 이유:** 라벨을 누르면 컨트롤에 초점이 가지만 그것은 컨트롤의 사건이고 표시도 컨트롤이 한다                               |
| focus-visible | 없음                | 초점을 받지 않는다. `tabindex` 를 주지 않는다 — 라벨을 누르면 초점은 컨트롤로 간다                                                                                       |
| pressed       | 없음                | 누름 상태가 없다. 누르는 순간 초점이 컨트롤로 옮겨 간다                                                                                                                  |
| disabled      | 컨트롤의 `disabled` | `group-has-disabled/field:opacity-50` — 라벨 자신은 비활성 개념이 없고, `group/field` 안에 `:disabled` 인 컨트롤이 있을 때 함께 흐려진다                                 |
| loading       | 없음                | 자기 데이터가 없다. 저장 중은 컨트롤이 `disabled` 로 표시하고 라벨은 위 disabled 규칙을 따른다                                                                           |
| empty         | 없음                | `children` 이 필수다. 빈 라벨을 렌더하지 마라 — 이유: 이름 없는 이름표가 남아 컨트롤이 이름을 가진 것처럼 보인다                                                         |
| error         | 없음                | 오류 색을 라벨에 쓰지 않는다. **이유:** 오류 표시는 컨트롤의 `aria-invalid` 와 `Field` 의 오류 문구 둘이 맡는다. 라벨까지 붉히면 무엇이 잘못인지가 세 곳에 나뉘어 읽힌다 |

**전이를 넣지 않는다.** 색이 바뀌는 상태가 없어 `transition-*` 이 0건이고,
그래서 `motion-reduce:transition-none` 도 필요 없다.
[`../tokens.md`](../tokens.md) 의 1:1 규칙은 전이가 있는 줄에만 적용된다.

## a11y

- a11y:label — 이 컴포넌트가 곧 다른 요소의 이름이다. `htmlFor` 가 가리키는 `id` 가 실제로 존재해야 한다. **`aria-label` 로 대신하지 마라 — 이유:** 보이는 글자가 없으면 라벨을 눌러 초점을 옮기는 동작이 사라지고, 음성 조작 사용자가 말할 대상이 화면에 없게 된다. 라벨을 시각적으로 감춰야 하면 `sr-only` 를 쓴다. Base UI 로 만든 컨트롤(`Checkbox` · `Switch`)도 같은 방식이다 — `id` 가 숨은 `<input>` 에 얹히므로 그 `id` 를 가리키면 `role="checkbox"` 의 이름이 된다
- a11y:focus — 초점 대상이 **0개**다. 라벨을 누르면 브라우저가 초점을 `htmlFor` 의 컨트롤로 옮긴다. `tabindex` 를 주지 마라 — 이유: 탭 순서에 라벨과 컨트롤이 둘 다 들어가 같은 것을 두 번 지나게 된다
- a11y:contrast — fg=`--foreground` / bg=`--background` 라이트 15.82 · 다크 16.13 ([`../tokens.md`](../tokens.md) `## 대비 검증` 의 대비값, 4.5:1 통과). 카드 위에서는 fg=`--foreground` / bg=`--card` 라이트 16.73 · 다크 14.84 로 같은 표에 있다. **비활성일 때의 `opacity-50` 은 미측정이다** — 하한이 **3:1**(WCAG 1.4.11)이고 실제 색은 뒤의 면에 따라 달라져 고정 쌍으로 계산되지 않는다
- a11y:target — 클릭 대상이지만 **크기를 정하지 않는다.** 라벨을 눌러도 값이 바뀌지 않고 초점만 옮겨 가므로 24x24 하한의 대상이 아니다. 다만 글자가 짧으면 누르기 어려우므로 한 낱말짜리 라벨을 만들지 마라
- a11y:role — 암묵 역할이 없다. `<label>` 은 이름을 주는 요소이지 스스로 역할을 갖지 않는다. **`role` 을 지정하지 마라 — 이유:** 역할을 주면 `<label>` 의 암묵 동작(눌렀을 때 초점 이동, 접근 가능한 이름 계산)이 끊긴다

## responsive

- 브레이크포인트 분기가 **0건**이다. 모든 폭에서 `text-sm`(14px) 하나다
- **`text-base md:text-sm` 분기를 넣지 마라. 이유:** 그 분기는 [`Input.md`](Input.md) 의
  `## responsive` 가 적은 대로 **iOS Safari 가 16px 미만 입력 필드에 초점이 가면 화면을 확대하는**
  문제를 피하려는 것이다. 라벨은 초점을 받지 않아 그 문제가 없다. 라벨까지 16px 로 올리면
  375px 화면에서 라벨이 값보다 커 보인다
- 라벨이 길어 두 줄이 되면 그대로 두 줄로 감싼다. `truncate` 를 주지 마라 —
  **이유:** 이름이 잘리면 무엇을 넣는 칸인지 판정할 수 없다
- 컨트롤과의 간격 8px 은 `Field` 의 `gap-2` 가 준다. [`../tokens.md`](../tokens.md) 의
  "카드 안 요소 사이 8px" 과 같은 값이다

## 상호작용

- 없음. hover / focus-visible 대상이 아니다. 누르면 초점이 컨트롤로 옮겨 가고 그 표시는
  컨트롤의 focus-visible 이 낸다
