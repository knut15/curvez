# component: Progress

purpose: 끝을 아는 진행을 0~100 퍼센트 막대로 보인다. 끝을 모르는 기다림은 `Loading` 이 맡는다

## 근거 — daisyUI 와 shadcn/ui 의 마크업만 옮겼다

### 1. 출처

| 항목             | 값                                                                                                              |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| 본 곳            | daisyUI <https://daisyui.com/components/progress/> · shadcn/ui <https://ui.shadcn.com/docs/components/progress> |
| 본 날짜          | **2026-09-12**                                                                                                  |
| 가져온 것        | 마크업 구조 — 홈 하나에 채운 막대 하나                                                                          |
| 가져오지 않은 것 | 클래스. daisyUI 의 `progress` 도 shadcn 의 Radix 프리미티브도 쓰지 않는다                                       |
| 의존성           | 없다. `<div>` 둘이다                                                                                            |

**이 값들은 화면에서 센 것이 아니다.** 기존 9종의 `## 근거` 에 있는 `파일:줄` 이 이 문서에는 없다.
**handwork 사용처: 0곳.** 어느 화면에도 쓰인 적이 없다.

### 2. 고른 요소 — `<div role="progressbar">` 다. `<progress>` 가 아니다

daisyUI 는 네이티브 `<progress class="progress">` 를 쓰고 shadcn/ui 는 `<div>` 둘을 쓴다.
**`<div>` 쪽을 골랐다. 근거 셋.**

| #   | 근거                                                                                                                                                                                                                                                                                                 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **토큰 색이 닿지 않는다.** `<progress>` 의 홈과 채운 부분은 `::-webkit-progress-bar` · `::-webkit-progress-value` · `::-moz-progress-bar` 로만 잡힌다. Tailwind 유틸리티에 그 의사 요소가 없어 `[&::-webkit-progress-value]:bg-primary` 처럼 임의 선택자를 직접 써야 하고, 엔진마다 한 줄씩 늘어난다 |
| 2   | **`accent-color` 하나로는 안 된다.** 그 속성은 채운 색만 바꾸고 홈 색·높이·반경은 그대로 둔다. 라이트·다크 두 벌을 맞추려면 결국 1번으로 돌아간다                                                                                                                                                    |
| 3   | **얻는 것이 적다.** `<progress>` 가 공짜로 주는 것은 `role`·`aria-valuenow` 매핑뿐이고, 그 셋은 속성 세 개로 직접 쓸 수 있다. 값을 잃지 않는다                                                                                                                                                       |

**`<progress>` 로 되돌릴 조건은 하나다 — 브라우저가 표준 의사 요소로 그 안을 열어 줄 때.**
**고칠 위치:** `../../src/ui/progress.tsx` 와 이 절, 두 곳이다.

### 3. 값이 없는 상태(indeterminate)를 만들지 않는다

daisyUI 는 `<progress class="progress w-56"></progress>` 처럼 `value` 를 빼면 흐르는 막대가 된다.
**만들지 않는다.**
**이유:** 그 자리는 [`Loading.md`](Loading.md) 가 맡는다. 둘 다 두면 값 없는 기다림을 도는 고리와
흐르는 막대 두 모양으로 말하게 되고, 어느 것이 의도인지 화면에서 판정할 수 없다.
그래서 `value` 가 **필수다** — 값이 없으면 이 컴포넌트를 쓰지 않는다.

### 4. `Loading` · `Skeleton` · `Empty` 와의 자리

| 무엇       | 쓰는 때                                   |
| ---------- | ----------------------------------------- |
| `Progress` | **끝을 안다.** 몇 퍼센트인지 말할 수 있다 |
| `Loading`  | 끝을 모른다. 얼마나 남았는지 말할 수 없다 |
| `Skeleton` | 끝을 모르는데 들어올 내용의 크기는 안다   |
| `Empty`    | 기다림이 끝났는데 결과가 0개다            |

## props

| 이름  | 타입     | 필수  | 기본값 | 의미                                     |
| ----- | -------- | ----- | ------ | ---------------------------------------- |
| value | `number` | **O** | —      | 0~100. 범위 밖 값은 양끝으로 잘린다      |
| label | `string` | **O** | —      | 화면 낭독기가 읽는 이름. 무엇의 진행인가 |

**`cva` 를 쓰지 않는다.** 구분할 축이 0개다. variant 도 size 도 없다.

**`max` 를 받지 마라.**
**이유:** 퍼센트 하나로 받으면 부르는 쪽이 나눗셈을 한 번 하고 끝난다. `max` 를 열면 `value=7 max=9`
같은 쌍이 들어오고, `aria-valuenow` 와 막대 폭 두 곳에서 같은 나눗셈을 다시 하게 된다.

**`label` 을 선택으로 만들지 마라.**
**이유:** `role="progressbar"` 는 이름이 없으면 "진행률 표시줄, 60%" 까지만 읽힌다. 무엇이 60% 인지
화면을 보지 않고는 알 수 없다.

**색(`variant`)을 받지 마라.** 채움은 `--primary` 하나다.
**이유:** 성공·경고를 색으로 가르려면 색이 둘 더 필요하고, [`../tokens.md`](../tokens.md) 가
"강조색을 하나만 쓴다" 로 정했다. 실패는 막대가 아니라 [`Alert.md`](Alert.md) 가 말한다.

**`className` 을 열지 마라.**
**이유:** 막대가 `w-full` 이라 폭은 부모가 이미 정한다. 높이·반경·색을 바깥에서 덮으면
같은 진행이 화면마다 다른 모양이 된다.

### 값 (`../../src/ui/progress.tsx`)

| 조각    | 값                                                                             |
| ------- | ------------------------------------------------------------------------------ |
| 홈      | `h-2`(8px) · `w-full` · `rounded-full` · bg=`--muted` · `overflow-hidden`      |
| 채움    | `h-full w-full` · `rounded-full` · bg=`--primary`                              |
| 채움 폭 | 인라인 `style={{ transform: 'translateX(-N%)' }}` — N = 100 - 퍼센트           |
| 전이    | `transition-transform duration-150 ease-out` + `motion-reduce:transition-none` |

**폭만 인라인 `style` 이다.** 퍼센트는 데이터에서 오므로 값마다 클래스를 만들 수 없다.
Tailwind 가 소스를 훑어 클래스를 생성하는데, `w-[${pct}%]` 는 훑을 때 존재하지 않는 문자열이라
스타일이 통째로 사라진다. **이 한 값 말고 다른 것을 `style` 로 주지 마라.**

**폭 대신 `translateX` 로 미는 이유:** 홈이 `rounded-full` 이라 채움도 `rounded-full` 인데,
폭을 줄이면 양끝 반원이 함께 눌려 막대가 짧을수록 모서리 모양이 달라진다. 통째로 밀면 모양이
그대로 남고 홈의 `overflow-hidden` 이 왼쪽을 잘라 준다.

## states

| state         | 트리거          | 시각 변화                                                                                                                                                                                          |
| ------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| default       | —               | 홈 bg=`--muted`, 채움 bg=`--primary`. 채움이 `value` 퍼센트만큼 보인다                                                                                                                             |
| hover         | 없다            | 상호작용 요소가 아니다. `progress.tsx` 에 `hover:` 가 0건이다. **만들지 마라 — 이유:** 읽기만 하는 막대가 눌리는 것처럼 보인다                                                                     |
| focus-visible | 없다            | 포커스를 받지 않는다. `tabindex` 를 주지 마라 — 이유: 값을 바꿀 수 없는 요소가 포커스 순서에 끼면 키보드 이동 횟수만 늘어난다. 값을 바꾸는 막대는 `<input type="range">` 이고 이 컴포넌트가 아니다 |
| pressed       | 없다            | 누를 수 없다                                                                                                                                                                                       |
| disabled      | 없다            | 비활성 개념이 없다. 진행이 멈췄다면 그것은 `value` 가 더 오르지 않는 것이지 다른 상태가 아니다                                                                                                     |
| loading       | **이것 자체다** | 진행 중이 곧 이 컴포넌트다. **값을 모르는 동안에는 이것을 0% 로 두지 마라 — 이유:** 0% 막대는 "시작했는데 아무것도 안 됐다" 로 읽힌다. 그 자리는 [`Loading.md`](Loading.md) 다                     |
| empty         | 없다            | `value` 가 필수라 값이 빈 경우가 없다. 0 은 빈 값이 아니라 "0% 진행" 이다                                                                                                                          |
| error         | 없다            | 실패를 말하지 않는다. **실패하면 이 자리를 `Alert variant="destructive"` 로 바꿔 낀다 — 이유:** 60% 에 멈춘 막대는 아직 진행 중으로 읽힌다                                                         |

**전이에 `motion-reduce:transition-none` 짝이 붙는다** (`../../src/ui/progress.tsx`).
[`../tokens.md`](../tokens.md) 의 `## 상태` 가 화면에 나온 8:8 로 그 짝을 1:1 로 정했다.
동작 줄이기를 켜면 막대가 부드럽게 늘지 않고 새 값으로 즉시 바뀐다 — 값은 그대로 보인다.

## a11y

- a11y:label — `aria-label={label}` 이 이름이다. **필수다.** 눈에 보이는 제목이 이미 옆에 있으면 그 제목의 `id` 를 `aria-labelledby` 로 잇는 편이 낫지만, 이 컴포넌트는 그 prop 을 열지 않았다 — 이유: 두 경로가 생기면 어느 값이 적용되는지 화면에서만 드러난다. 필요해지면 `label` 을 `ReactNode` 로 넓히지 말고 `aria-labelledby` prop 을 따로 연다
- a11y:focus — 포커스 대상이 **0개다.** 포커스 순서에 끼어들지 않는다. 값이 바뀔 때 포커스가 움직이지 않는다
- a11y:contrast — 채움 `--primary` / 홈 `--muted` 는 라이트 **14.69** · 다크 **13.17** 이다. WCAG 1.4.11 의 **3:1**(그래픽 하한)을 넘는다. **이 수치는 렌더된 화면에서 잰 값이 아니다** — [`../tokens.md`](../tokens.md) 의 `## 색` 표에 있는 hex(라이트 `#14201E`/`#EDF1F0`, 다크 `#E6EDEA`/`#1D2523`)를 이 저장소의 `../../scripts/lib/tokens.mjs` 의 `contrast()` 로 계산한 값이다. **`## 대비 검증` 목록에 넣지 않았다 — 이유:** 그 파일은 이 작업의 담당이 아니다. 목록에 실을 때는 렌더 화면에서 `getComputedStyle` 로 다시 재서 같은 형식의 한 줄로 넣는다
- a11y:target — 해당 없다. 클릭 대상이 아니라 24x24 규칙이 걸리지 않는다. 막대 높이 8px 은 표시 전용이라 이 규칙과 무관하다
- a11y:role — `progressbar` 다. `aria-valuenow` · `aria-valuemin=0` · `aria-valuemax=100` 을 함께 준다. **`aria-valuemin`·`aria-valuemax` 는 ARIA 기본값이 0·100 이라 생략해도 되지만 적는다 — 이유:** 나중에 `max` prop 을 열려는 사람이 이 두 줄을 보고 거기가 고칠 자리임을 안다. **`aria-valuetext` 를 붙이지 마라 — 이유:** 퍼센트를 그대로 읽는 것이 기본 동작이고, 덮어쓰면 "3분 남음" 처럼 값이 아닌 말이 들어와 실제 진행과 어긋난다. **`role="status"` 를 함께 붙이지 마라 — 이유:** live region 이 되어 값이 1% 오를 때마다 낭독기가 읽는다

## responsive

- 브레이크포인트 분기가 **0건**이다. `progress.tsx` 전체에 `sm:`·`md:` 가 없다
- 폭이 `w-full` 이라 **모든 폭에서 부모를 채운다.** `max-w-*` 를 이 컴포넌트에 걸지 마라 — 이유: 페이지 폭은 [`PageShell.md`](PageShell.md) 가 정하고, 두 곳이 폭을 정하면 어느 값이 적용되는지 화면에서만 드러난다
- 높이 `h-2`(8px)가 모든 폭에서 같다. 375px 에서도 바뀌지 않는다 — 이유: 막대의 뜻은 길이가 아니라 채운 비율이고, 비율은 폭이 좁아져도 그대로 읽힌다
- **좁은 화면에서 퍼센트 글자를 막대 안에 넣지 마라.** 이 컴포넌트는 글자를 갖지 않는다 — 숫자를 보여야 하면 막대 위나 옆에 별도 글자로 둔다. 이유: 8px 높이에 글자가 들어갈 자리가 없다

## 상호작용

- 없다. hover / focus-visible / active 대상이 아니다
- 유일한 변화는 `value` 가 바뀔 때의 `transition-transform`(150ms)이고, 동작 줄이기에서는 그것도 멈춰 즉시 바뀐다
