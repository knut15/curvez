# component: Range

purpose: 연속된 값에서 하나를 집는다. 정확한 숫자를 받아야 하면 `Input` 을 쓴다

## 근거 — daisyUI 와 shadcn/ui 에서 각각 한 조각씩 옮겼다

### 2. `accent-color` 를 골랐다 — 벤더 가상 요소를 쓰지 않는다

**결정: `accent-primary` 한 줄. `::-webkit-slider-thumb` 와 `::-moz-range-thumb` 를 쓰지 않는다.**

두 가상 요소를 쓰면 트랙 두께와 손잡이 크기·색을 우리가 정할 수 있다. 그래도 쓰지 않았다.

**이유 셋.**

1. **두 벌을 손으로 맞춰야 한다.** 두 선택자는 하나로 묶을 수 없다 —
   `::-webkit-slider-thumb, ::-moz-range-thumb { }` 처럼 쉼표로 묶으면 **선택자 하나를 모르는
   엔진이 규칙 전체를 버린다.** 따로 쓰면 한쪽만 고쳐지는 자리가 생기고, 그 어긋남은 그 엔진에서만
   드러난다
2. **토큰 이름이 문자열 안으로 숨는다.** Tailwind 로는 `[&::-webkit-slider-thumb]:bg-primary`
   같은 임의 변형이 되고, [`../tokens.md`](../tokens.md) 가 "임의값을 쓰지 마라" 를 이미 정했다
3. **검증할 방법이 없다.** 이 저장소의 스토리 테스트는 chromium 한 엔진에서만 돈다
   (`vitest.config.mts` 의 `instances: [{ browser: "chromium" }]`). Firefox 쪽 규칙은 쓰더라도
   여기서 통과 여부를 판정할 수 없다

`accent-primary` 는 두 엔진이 각자 자기 슬라이더를 그리고 **채운 쪽 색만 `--primary` 로 바꾼다.**
`Checkbox` · `Switch` 의 켜진 면과 같은 토큰이라 같은 폼 안에서 색이 맞는다.

**대신 잃는 것 — 트랙 두께와 손잡이 크기가 엔진 기본값이다.** 우리가 정하는 것은 바깥 상자의
높이(`h-8`)와 폭(`w-full`)과 초점 링뿐이다. 그 세 값이 [`Input.md`](Input.md) 과 같아서
같은 폼에서 줄이 맞는다.

**바꿀 때 고칠 위치:** 이 절과 `../../src/ui/range.tsx` 의 클래스 문자열 한 줄.

### 3. 기존 폼 컴포넌트와 맞춘 값

| 축        | `input.tsx:11`                            | 이 파일                      |
| --------- | ----------------------------------------- | ---------------------------- |
| 높이      | `h-8` = 32px                              | 같다                         |
| 폭        | `w-full`                                  | 같다                         |
| 반경      | `rounded-lg` = 10px                       | 같다 — 초점 링의 모서리다    |
| 포커스 링 | `focus-visible:ring-3 ring-ring/50`       | 같다                         |
| 오류      | `aria-invalid:ring-3 ring-destructive/20` | 같다 (다크 알파 40%)         |
| 비활성    | `disabled:opacity-50`                     | 같다 + `pointer-events-none` |

**테두리를 두지 않는다.** `Input` 은 `border border-input` 을 갖지만 슬라이더는 글자를 담는 칸이
아니라 트랙이다. **이유:** 트랙 둘레에 테두리를 그으면 트랙이 입력 칸으로 읽혀 그 안을 눌러
글자를 넣으려 하게 된다.

## props

| 이름         | 타입                            | 필수 | 기본값  | 의미                                      |
| ------------ | ------------------------------- | ---- | ------- | ----------------------------------------- |
| id           | `string`                        | X    | —       | 라벨이 가리킬 `id`                        |
| min          | `number`                        | X    | `0`     | 하한. 브라우저 기본값이 0 이다            |
| max          | `number`                        | X    | `100`   | 상한. 브라우저 기본값이 100 이다          |
| step         | `number`                        | X    | `1`     | 한 칸의 크기. 화살표 키가 이만큼 움직인다 |
| value        | `number`                        | X    | —       | 제어로 쓸 때의 값                         |
| defaultValue | `number`                        | X    | —       | 비제어로 쓸 때의 처음 값                  |
| onChange     | `(e) => void`                   | X    | —       | 값이 바뀔 때                              |
| disabled     | `boolean`                       | X    | `false` | 조작 무시 + 불투명도 50%                  |
| aria-invalid | `boolean`                       | X    | `false` | 오류 표시. 아래 `## states` 참조          |
| (그 밖)      | `React.ComponentProps<"input">` | X    | —       | `className` 만 빼고 그대로 받는다         |

**`min`·`max`·`step` 의 기본값을 이 컴포넌트가 정하지 않는다.** 위 표의 값은 브라우저 기본값이다.
**이유:** 우리가 정하면 화면에 0번 나온 값이 기본값으로 굳는다. 필요한 범위는 쓰는 자리가 안다.

**`className` 을 받지 않는다.**
**이유:** 폭은 `w-full` 로 부모가 정하고 높이·반경·링은 한 벌뿐이다.

**값을 글자로 보여 주는 기능을 넣지 마라** — `showValue` 같은 prop.
**이유:** 값의 단위와 자릿수는 쓰는 자리가 안다(`768px`, `40%`, `12시간`).
컴포넌트가 정하면 화면마다 다른 형식이 필요해질 때 덮어쓸 구멍부터 열게 된다.
값을 보여야 하면 [`Field.md`](Field.md) 의 `description` 이나 라벨 옆 `<output>` 이 맡는다.

**값이 둘인 범위 슬라이더를 만들지 마라.**
**이유:** `<input type="range">` 하나는 값 하나다. 둘을 겹쳐 놓으면 손잡이가 서로 넘어가는 처리와
초점 순서를 직접 만들어야 하고 `"use client"` 가 붙는다. 이 저장소에 쓰는 곳이 0곳이다.

## states

| state         | 트리거         | 시각 변화                                                                                                                                                                                                                                                 |
| ------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| default       | —              | 높이 32px · 폭 `w-full` 의 상자 안에 엔진이 그린 트랙과 손잡이. 채운 쪽이 `--primary`. 커서 `pointer`. 배경·테두리 없음                                                                                                                                   |
| hover         | 없음           | `hover:` 가 0건이다. **hover 색을 만들지 마라 — 이유:** 손잡이의 hover 를 칠하려면 벤더 가상 요소로 돌아가야 하고, 상자 전체를 칠하면 트랙 바깥의 빈 자리가 함께 칠해진다                                                                                 |
| focus-visible | 키보드 초점    | `focus-visible:ring-3 focus-visible:ring-ring/50` — 32px 상자 둘레에 3px 링이 알파 50% 로 깔린다. **네이티브 슬라이더에도 그림자 링이 실제로 그려지는지 `range.stories.tsx` 의 `Focused` 가 `getComputedStyle` 로 확인한다**                              |
| pressed       | 없음           | `active:` 가 0건이다. **`active:scale-97` 을 붙이지 마라 — 이유:** 누르는 동안 값이 계속 바뀌는 컨트롤이라 크기까지 움직이면 손잡이의 위치를 눈으로 따라갈 수 없다                                                                                        |
| disabled      | `disabled`     | `disabled:pointer-events-none disabled:cursor-not-allowed disabled:opacity-50`. 대비 하한 **3:1**(WCAG 1.4.11). 트랙과 손잡이가 함께 흐려진다                                                                                                             |
| loading       | 없음           | 스스로 비동기 동작을 하지 않는다. 저장 중은 `disabled` 를 주고 표시는 부르는 쪽이 한다 — **트랙 위에 스피너를 얹지 마라. 이유:** 손잡이와 겹쳐 지금 값이 어디인지 판정할 수 없다                                                                          |
| empty         | 없음           | 빈 값이 없다. `value` 를 주지 않으면 브라우저가 `(min + max) / 2` 에 손잡이를 둔다. **"고르지 않음" 을 표현할 수 없다 — 이유:** 슬라이더는 항상 어딘가를 가리킨다. 고르지 않은 상태가 필요하면 [`Radio.md`](Radio.md) 나 [`Select.md`](Select.md) 를 쓴다 |
| error         | `aria-invalid` | `aria-invalid:ring-3 aria-invalid:ring-destructive/20`(다크는 알파 40%). 링만 바뀌고 채운 색은 `--primary` 로 남는다 — **`accent-color` 를 상태별로 바꾸지 마라. 이유:** 지금 가리키는 값이 잘못된 값으로 읽힌다                                          |

**전이를 넣지 않는다.** 색이 바뀌는 상태가 focus-visible 과 error 둘뿐이고 그 둘은 링
(그림자)이다. `transition-*` 이 0건이라 `motion-reduce:transition-none` 도 필요 없다.
**손잡이가 움직이는 것에 전이를 걸지 마라 — 이유:** 손잡이는 포인터를 따라가는 것이지
상태가 바뀌는 것이 아니다. 전이를 걸면 손가락보다 늦게 따라온다.

## a11y

- a11y:label — `<label htmlFor>` 가 **필수**다. **`aria-label` 로 대신하지 마라 — 이유:** 라벨을 눌러 초점을 옮기는 동작이 사라지고, 음성 조작 사용자가 말할 대상이 화면에 없게 된다. 근거는 [`Input.md`](Input.md) 의 같은 항목. 값의 단위가 숫자만으로 전해지지 않으면 `aria-valuetext` 를 준다 — 화면 낭독기는 기본적으로 `40` 만 읽지 `40%` 라고 읽지 않는다
- a11y:focus — 초점 대상이 **1개**다. 초점 순서는 DOM 순서와 같고 `disabled` 슬라이더는 초점을 받지 않는다. 링은 `ring-3` 한 벌이고 [`Checkbox.md`](Checkbox.md) 의 `a11y:focus` 가 정한 "폼 5종은 `ring-3`" 을 따른다. **값 조작은 화살표 키다** — 브라우저가 하고 우리가 코드를 쓰지 않는다. `Home`·`End` 로 양 끝, `PageUp`·`PageDown` 으로 큰 칸도 브라우저가 준다. **그 동작을 직접 만들지 마라 — 이유:** 이미 있고, 만들면 `"use client"` 가 붙는다. **화살표 키로 값이 실제로 바뀌는지는 이 저장소의 스토리 테스트로 확인하지 못했다 — 확인 불가.** 합성 키 이벤트가 네이티브 슬라이더의 값을 움직이지 않아 그 단언을 뺐다(`range.stories.tsx` 의 `Focused`)
- a11y:contrast — **자기 글자가 없다.** 라벨과 설명의 대비는 [`Label.md`](Label.md) · [`Field.md`](Field.md) 가 갖는다. **채운 트랙 `--primary` / 빈 트랙 쌍과 손잡이 색은 미측정이다** — 트랙은 글자가 아니라 하한이 **3:1**(WCAG 1.4.11)이고, 빈 트랙과 손잡이 색은 엔진 기본값이라 우리 토큰으로 계산되지 않는다. 구현 뒤 렌더 화면에서 `getComputedStyle` 로 재서 [`../tokens.md`](../tokens.md) 에 한 줄을 추가한다
- a11y:target — 상자 높이 **32px** · 폭 `w-full` 이라 24x24 최소를 넘는다. **`h-8` 을 낮추지 마라 — 이유:** 손잡이 자체는 엔진이 그린 16px 남짓이고, 32px 상자가 그 위아래 여백까지 눌리는 영역으로 만든다. 그 상자를 줄이면 손잡이만 남아 기준 아래로 떨어진다. 슬라이더를 세로로 쌓을 때 간격 8px 이상을 둔다
- a11y:role — `slider` (`<input type="range">` 의 암묵 역할). `aria-valuenow` · `aria-valuemin` · `aria-valuemax` 를 브라우저가 관리한다. **그 셋을 직접 주지 마라 — 이유:** 값이 바뀔 때마다 손으로 갱신해야 하고 실제 값과 어긋날 자리가 생긴다. **이 셋은 접근성 트리에만 있고 DOM 속성으로 나오지 않는다** — `range.stories.tsx` 의 `CustomRange` 가 `aria-valuemin` 대신 `min`·`max` 속성을 보는 이유다. **`role` 을 지정하지 마라** — 암묵 역할이 이미 맞다

## responsive

- 브레이크포인트 분기가 **0건**이다. 모든 폭에서 높이 32px 이다.
  **`text-base md:text-sm` 분기를 넣지 마라 — 이유:** 그 분기는 [`Input.md`](Input.md) 이 적은
  대로 iOS Safari 의 확대를 피하려는 것이고, 그 확대는 **글자를 넣는 필드**에만 일어난다.
  슬라이더에는 글자가 없다
- 폭은 `w-full` 이라 부모가 정한다. `min-w-*` 를 붙이지 마라 —
  **이유:** 375px 에서 슬라이더 폭은 335px 이고(375 − `px-5` 20px×2), 하한을 두면 그보다 좁은
  자리에서 부모를 밀어낸다
- **`step` 이 작고 범위가 넓으면 좁은 화면에서 한 칸이 1px 아래로 내려간다.** 335px 폭에
  `min=0 max=1000 step=1` 이면 한 칸이 0.335px 이라 포인터로는 그 값을 집을 수 없다.
  **그 조합을 쓰지 마라 — 대신** `step` 을 키우거나 정확한 값이 필요하면
  [`Input.md`](Input.md) 의 `type="text" inputMode="numeric"` 을 쓴다.
  화살표 키로는 여전히 한 칸씩 갈 수 있지만 포인터 사용자에게는 닿지 않는 값이 생긴다
- 슬라이더를 가로로 두 개 놓지 마라. **이유:** 375px 에서 각 167px 이 되고, 위 한 칸 계산이
  그만큼 더 나빠진다
- `lg` 이상을 넣지 마라. 페이지 폭이 `max-w-5xl`(1024px)에서 멈춘다

## 상호작용

- focus-visible / disabled / error 정의. hover 와 pressed 는 없다
- 값 조작은 포인터 끌기와 화살표 키다. 둘 다 브라우저가 하고 이 파일에 코드가 없다
