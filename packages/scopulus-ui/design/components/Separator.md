# component: Separator

purpose: 블록과 블록 사이에 가로줄 하나를 긋고 위아래 여백을 함께 갖는다

## 근거 — 화면에 4번 나온다

```bash
grep -rn 'border-t' apps/handwork/src --include='*.tsx'
```

| 파일                                        | 줄  | 여백 조합         | 위 / 아래 |
| ------------------------------------------- | --- | ----------------- | --------- |
| `apps/handwork/src/views/case-index.tsx`    | 15  | `mt-8` + `pt-8`   | 32 / 32   |
| `apps/handwork/src/views/lab-index.tsx`     | 16  | `mt-8` + `pt-8`   | 32 / 32   |
| `apps/handwork/src/views/case-detail.tsx`   | 52  | `mt-12` + `pt-6`  | 48 / 24   |
| `apps/handwork/src/widgets/site-footer.tsx` | 7   | 없음(안쪽 `py-8`) | 0 / 32    |

선 자체는 네 자리 모두 같다 — `border-t border-border`, 즉 1px `--border`.

## 확정 — 여백을 하나로 통일한다

**위 32px · 아래 32px.** 클래스로는 `my-8`(= 화면에서 쓰던 `mt-8` + `pt-8` 과 같은 값).

화면에는 32/32 두 곳, 48/24 한 곳, 0/32 한 곳이 있었다. **값은 다른데 의미가 같다 —
"여기서 한 덩어리가 끝나고 다음이 시작한다".** 이럴 때는 나누지 않고 하나로 통일한다
([`../tokens.md`](../tokens.md) 머리의 토큰 판정표).

32/32 를 고르는 근거는 최다 사용(2/4)이고, 위아래가 같아야 선이 두 덩어리의 가운데에 놓인다.
48/24 는 선이 위쪽 덩어리에서 멀고 아래쪽에 붙어 있어, 선이 아래 블록의 머리 장식으로 읽힌다.

**바꿀 때 고칠 위치:** `apps/handwork/src/views/case-detail.tsx:52`.
그 자리는 선이 `<nav>` 자신의 `className` 에 붙어 있어, Separator 로 바꾸려면 `<nav>` 에서
`mt-12 border-t border-border pt-6` 을 떼고 `<nav>` **앞**에 Separator 를 놓아야 한다.

**푸터는 Separator 를 쓰지 않는다.** `widgets/site-footer.tsx:7` 의 `border-t` 는 `<footer>` 자신의
테두리다.
**이유:** 그 선은 두 블록 사이가 아니라 페이지와 푸터의 경계이고, 본문이 짧을 때도 화면 아래에
붙어 있어야 한다. Separator 로 바꾸면 `<footer>` 밖으로 나가 본문 흐름 안에 끼게 된다.

## props

| 이름 | 타입 | 필수 | 기본값 | 의미                                             |
| ---- | ---- | ---- | ------ | ------------------------------------------------ |
| 없음 | —    | —    | —      | 값을 받지 않는다. 선 하나와 고정 여백만 렌더한다 |

**`orientation` prop 을 두지 않는다.** 세로 선은 없다.
**이유:** 화면에 세로 구분선이 0번 나온다. 화면 5개가 전부 한 열이고, 2열이 되는 곳(목록 `md:grid-cols-2`)은
카드 테두리가 이미 칸을 가른다.

**`spacing` prop 을 두지 않는다.**
**이유:** 위에서 값을 하나로 통일했다. 고를 수 있게 만들면 통일이 권고가 되고, 다시 세 값으로 나뉜다.

**`className` 을 받지 않는다.**
**이유:** 여백을 덧붙일 구멍이다. PageShell 과 같은 판단이다.

| error         | 없음   | 상태를 갖지 않아 실패할 동작이 없다                                                                                                                                                                                                       |

**다크에서 선이 옅어지는 것은 의도다.** `--border` 의 다크 값이 흰색 10% 알파다(`../tokens.md`).
값을 올리지 마라 — 이유: 그 문서가 "알파 위 실제 색은 배경에 따라 달라져 고정 쌍으로 계산되지
않는다" 며 대비 검증에서 제외했다. 선의 세기를 손보려면 `../tokens.md` 의 `--border` 행부터 고친다.

**그림자로 대신하지 마라.** 이 사이트는 고도를 쓰지 않는다 — 근거는 [`../tokens.md`](../tokens.md) 의
`## 고도` 절이고, 화면에 그림자가 0번 나온다.

## a11y

- a11y:label — 해당 없음. 글자가 없다. `aria-label` 을 붙이지 마라 — 이유: 이름이 있으면 스크린리더가 구분선마다 그 이름을 읽는다
- a11y:focus — 포커스 대상이 0개다. 포커스 순서에 끼어들지 않는다. 앞 블록의 마지막 포커스 대상 다음이 곧 뒤 블록의 첫 포커스 대상이다
- a11y:contrast — 해당 없음. 글자가 아니라 1px 선이다. `../tokens.md` 가 정했다 — "면과 면의 구분은 이 목록에 넣지 않는다. 글자 대비 기준을 면 구분에 적용하면 통과할 수 없는 검사를 만든다"
- a11y:target — 해당 없음. 클릭 대상이 아니다
- a11y:role — `separator` (`<hr>` 의 암묵 역할). `<div className="border-t">` 로 그리지 마라 — 이유: 그러면 구조 정보가 시각에만 남아 스크린리더가 덩어리의 경계를 알지 못한다. `role="separator"` 를 손으로 쓰지도 마라 — 요소가 이미 그 역할을 가진다. `aria-hidden` 을 붙이지 마라 — 이유: 이 선은 장식이 아니라 "여기서 한 덩어리가 끝난다" 는 구조 정보다

## responsive

- 모든 폭에서 동일하다. 브레이크포인트 분기가 0건이다
- 폭은 부모를 꽉 채운다. `max-w-*` 를 붙이지 마라 — 이유: 상세 화면에서 선의 폭은 `mx-auto max-w-[68ch]` 를 가진 부모가 정한다(`views/case-detail.tsx:52`). 선이 스스로 폭을 정하면 본문과 어긋난다
- 여백 32px 은 모든 폭에서 같다. 화면 세로 여백(`py-10 md:py-16`)과 달리 분기하지 않는다 — 이유: 화면에 나온 네 자리 중 브레이크포인트가 붙은 곳이 0곳이다

## 상호작용

- 없음. hover / focus-visible 대상이 아니다
