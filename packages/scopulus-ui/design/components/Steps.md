# component: Steps

purpose: 순서가 있는 단계를 세로로 세우고 지금 어디에 있는지를 글자와 모양 둘로 말한다

## 근거 — daisyUI 의 마크업 구조만 옮겼다

### 1. 출처

| 항목      | 값                                                       |
| --------- | -------------------------------------------------------- |
| 참고한 곳 | daisyUI <https://daisyui.com/components/steps/>          |
| 확인 날짜 | **2026-09-12**                                           |
| 옮긴 것   | 마크업 구조뿐이다. 클래스 이름은 한 글자도 옮기지 않았다 |
| 소스      | [`../../src/ui/steps.tsx`](../../src/ui/steps.tsx)       |

**daisyUI 문서에서 확인한 것**(2026-09-12): 바깥이 `<ul class="steps">` 이고 각 단계가
`<li class="step">` 이다. 방향은 `steps-vertical` · `steps-horizontal` 두 클래스로 가른다.
상태는 `step-primary` · `step-neutral` 같은 **색 클래스 하나로만** 말한다. 번호는 자동으로 붙고
`data-content` 나 `<span class="step-icon">` 으로 바꿀 수 있다.
**문서에 aria 속성이나 접근성 안내가 없다.** 그래서 아래 `## a11y` 의 값은 옮긴 것이 아니라
**이 스펙이 정한 것이다.**

shadcn/ui 에는 이것에 해당하는 컴포넌트가 없다. 참고한 곳은 daisyUI 하나뿐이다.

### 2. 화면 사용처: 0곳

handwork 에도 scopulus-ui 문서 사이트에도 쓰인 적이 없다. **이 문서에는 `파일:줄` 이 없다.**
값의 출처는 위 URL 과 [`../tokens.md`](../tokens.md) 둘뿐이다.

### 3. daisyUI 와 다르게 한 것

| 무엇      | daisyUI                          | 여기                         | 이유                                                                                  |
| --------- | -------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------- |
| 목록 태그 | `<ul>`                           | `<ol>`                       | 순서가 뜻을 갖는다. 순서를 바꾸면 다른 절차가 된다                                    |
| 상태 표현 | 색 클래스 하나                   | `sr-only` 글자 + 속성 + 모양 | 색만으로 말하면 색을 못 보는 사람에게 세 상태가 전부 같다                             |
| 지금 자리 | 표시 없음                        | `aria-current="step"`        | "지금" 은 나머지 둘과 종류가 다른 정보다. 속성이 그것을 말한다                        |
| 방향      | `steps-vertical` / `-horizontal` | **세로 하나**                | 가로 한 줄은 375px 에서 라벨을 줄이거나 옆으로 밀어야 한다. 아래 `## responsive` 참고 |
| 상태 입력 | 단계마다 색 클래스               | `current` 숫자 하나          | 단계마다 상태를 받으면 "지금" 이 둘인 상태를 타입이 막지 못한다                       |
| 번호      | 자동. `data-content` 로 바꾼다   | `i + 1` 고정, `aria-hidden`  | 몇 번째인지는 `<ol>` 이 이미 읽어 준다. 화면 번호는 눈으로 세지 않게 하는 장치다      |
| 색 종류   | `primary` 등 7종                 | **없다**                     | [`../tokens.md`](../tokens.md) 가 "강조색을 하나만 쓴다" 로 정했다                    |

## props

| 이름    | 타입       | 필수 | 기본값 | 의미                             |
| ------- | ---------- | ---- | ------ | -------------------------------- |
| steps   | `string[]` | O    | —      | 단계 이름. 순서가 곧 화면 순서다 |
| current | `number`   | O    | —      | 지금 있는 단계의 0부터 센 자리   |

상태는 받지 않고 `current` 에서 계산한다.

| 조건            | 상태      | 읽히는 글자 |
| --------------- | --------- | ----------- |
| `i < current`   | `done`    | `완료`      |
| `i === current` | `current` | `지금 단계` |
| `i > current`   | `todo`    | `남은 단계` |

**`current` 를 범위 밖으로 줘도 막지 않는다.** 음수면 전부 `todo`, `steps.length - 1` 보다 크면
전부 `done` 이다. 마지막 단계를 끝낸 뒤를 그렇게 표현한다.
**이유:** 범위를 막으면 "다 끝났다" 를 표현할 방법이 사라진다.

**`className` 을 받지 않는다.**
**이유:** 절차 표시는 한 벌이다. 여백을 바깥에서 받으면 화면마다 다른 값이 생긴다.

**단계마다 상태를 넘기는 prop 을 두지 마라.** 건너뛴 단계·실패한 단계 같은 네 번째 상태가
필요해지면 그때는 축이 둘(상태 · 방향)이 되므로 `cva` 로 다시 쓴다.
**고칠 위치:** [`../../src/ui/steps.tsx`](../../src/ui/steps.tsx) 의 `state` 계산 한 줄과 이 표다.

**아이콘을 받지 않는다.** 완료에 체크 표시를 넣지 않는다.
**이유:** 아이콘을 열면 단계마다 다른 그림이 들어와 번호 자리의 뜻이 화면마다 달라진다.
이 라이브러리에 아이콘 컴포넌트가 없어 부르는 쪽이 무엇을 넣을지도 정해지지 않는다.

## states

아래 여덟 줄은 단계 하나에 대한 것이다.

| state         | 트리거             | 시각 변화                                                                                                                                                                                                                                                                    |
| ------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| default       | —                  | 세 갈래다. `done`: 번호 원이 `--primary` 로 채워지고 글자 `--primary-foreground`, 라벨 `--muted-foreground`. `current`: 원이 `--ring` 2px 테두리, 번호 `--foreground`, 라벨 `font-medium` `--foreground`. `todo`: 원이 `--border` 1px 테두리, 번호·라벨 `--muted-foreground` |
| hover         | 없다               | 상호작용 요소가 아니다. `steps.tsx` 에 `hover:` 가 0건이다. 단계를 눌러 이동하게 하려면 그것은 `Menu` 다                                                                                                                                                                     |
| focus-visible | 없다               | 포커스를 받지 않는다. `tabindex` 를 주지 마라 — 이유: 읽기만 하는 목록이 포커스 순서에 끼면 키보드 이동 횟수만 늘어난다                                                                                                                                                      |
| pressed       | 없다               | 누를 수 없다                                                                                                                                                                                                                                                                 |
| disabled      | 없다               | 비활성 개념이 없다. 아직 안 온 단계는 `todo` 이지 비활성이 아니다                                                                                                                                                                                                            |
| loading       | 없다               | 스스로 데이터를 불러오지 않는다. `current` 는 부르는 쪽이 이미 갖고 있는 값이다                                                                                                                                                                                              |
| empty         | `steps` 가 빈 배열 | 빈 `<ol>` 만 남는다. **빈 배열을 넘기지 마라** — 이유: 항목 0개짜리 목록이 읽히고 그것이 실패로 보인다                                                                                                                                                                       |
| error         | 없다               | 실패한 단계를 표현하지 않는다. 필요하면 위 `## props` 의 네 번째 상태 항목을 따라 다시 쓴다                                                                                                                                                                                  |

**전이를 넣지 않는다.** `steps.tsx` 에 `transition-*` 이 0건이다.
**이유:** `current` 가 바뀌면 여러 단계의 원과 라벨이 한꺼번에 바뀐다. 거기에 전이를 걸면
어느 것이 새로 바뀐 것인지 화면에서 구별되지 않는다.

**`rounded-full` 은 반경 스케일의 네 번째 단계가 아니다.** [`../tokens.md`](../tokens.md)
`## 형태` 의 세 단계는 모서리 값이고, 이것은 **원**이라는 모양이다. `Badge` 의 상태 점도 같은
이유로 `rounded-full` 을 쓴다(`badge.tsx` 의 `size-1.5 rounded-full`).

## a11y

- a11y:label — 단계 이름이 그 자체로 읽히는 글자다. `aria-label` 로 덮지 마라. **상태는 라벨 앞의 `sr-only` 글자가 말한다** — `완료,` · `지금 단계,` · `남은 단계,` 다. 쉼표는 낭독기가 한 박자 쉬게 한다. **번호 원과 연결선에는 `aria-hidden` 이 붙는다** — 번호는 `<ol>` 이 이미 읽고, 선은 이어져 있다는 것을 그림으로 말할 뿐이다. `<ol>` 자체에는 이름을 붙이지 않는다 — 이유: 절차가 무엇에 대한 것인지는 앞선 제목이 말한다. 이름이 필요하면 그것은 이 컴포넌트가 아니라 감싸는 영역의 일이다
- a11y:focus — 포커스 대상이 **0개**다. 링크도 버튼도 없다. 포커스 순서에 아무것도 더하지 않는다
- a11y:contrast — 세 쌍 전부 [`../tokens.md`](../tokens.md) `## 대비 검증` 에 이미 있다. `done` 번호 fg=`--primary-foreground` / bg=`--primary` 라이트 **15.82** · 다크 **16.13**. `current` 번호와 라벨 fg=`--foreground` / bg=`--background` 라이트 **15.82** · 다크 **16.13**. `todo`·`done` 라벨 fg=`--muted-foreground` / bg=`--background` 라이트 **5.28** · 다크 **7.97**. 셋 다 4.5:1 을 넘는다. **새 대비 쌍이 생기지 않는다.** `current` 원의 테두리 `--ring` 과 `todo` 원의 테두리 `--border` 는 글자가 아니라 선이라 글자 대비 기준을 적용하지 않는다 — 같은 문서가 면과 면의 구분에 대해 이미 같은 판단을 내렸다
- a11y:target — 클릭 대상이 **0개**라 24x24 규칙이 걸리지 않는다. 번호 원은 28px 이지만 누를 수 없다. **단계를 누를 수 있게 만들지 마라** — 이유: 그 순간 이것은 절차 표시가 아니라 이동 목록이 되고, `Menu` 와 하는 일이 겹친다
- a11y:role — `<ol>` 에 `role="list"` 를 붙인다 — 이유: Tailwind preflight 가 `list-style:none` 을 걸고 Safari 는 그 조건에서 목록 의미를 떼어 낸다. `<li>` 는 `listitem` 을 그대로 쓴다. **지금 단계의 `<li>` 에 `aria-current="step"` 이 붙는다.** `page` 가 아니라 `step` 이다 — 이유: `page` 는 "지금 보고 있는 화면" 이고 이것은 "지금 있는 단계" 다. `role="progressbar"` 를 쓰지 마라 — 이유: 그것은 이름 붙은 단계가 아니라 숫자 하나를 말하는 역할이고, 그 자리는 `Progress` 다

## responsive

- 브레이크포인트 분기가 **0건**이다. 375px 에서 1920px 까지 같은 클래스다
- **가로 배치를 만들지 않았다.** 가로 한 줄은 단계 넷이면 375px 에서 단계당 90px 남짓이라 라벨을 줄이거나 옆으로 미는 스크롤을 붙여야 한다. 둘 다 읽기를 해친다. 세로는 어느 폭에서나 같게 읽히고 브레이크포인트가 필요 없다. **가로가 필요해지면 축이 둘(상태 · 방향)이 되므로 `cva` 로 다시 쓴다** — 고칠 위치는 [`../../src/ui/steps.tsx`](../../src/ui/steps.tsx) 전체와 이 절이다
- 폭은 부모가 정한다. `max-w-*` 를 걸지 마라 — 이유: 페이지 폭은 [`PageShell.md`](PageShell.md) 가 정한다
- 단계 하나의 높이는 번호 원 28px + 아래 여백 `pb-6`(24px) = **52px** 이다. 마지막 단계에는 `pb-6` 이 없다. 라벨이 두 줄이 되면 그만큼 늘어나고 연결선도 함께 늘어난다 — 선이 `absolute top-8 bottom-0` 이라 `<li>` 높이를 따라간다
- 375px 기준 라벨에 쓸 수 있는 폭은 375 − 40([`PageShell.md`](PageShell.md) 의 `px-5` 두 번) − 28(번호 원) − 12(`gap-3`) = **295px** 이다

## 상호작용

- 없다. hover / focus-visible / active 대상이 아니다
- 포인터에 반응하지 않고 탭 순서에 들어가지 않는다. 읽기 전용 표시다
