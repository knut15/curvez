# component: Timeline

purpose: 시간 순으로 일어난 일을 위에서 아래로 세운다. 선과 점은 장식이고 읽히는 것은 시각과 내용이다

## 근거 — daisyUI 에서 구조만 옮기고 변형을 잘라 냈다

### 1. 이 값은 화면에서 센 값이 아니다

**handwork 화면 사용처: 0곳.** 화면에 한 번도 나온 적이 없다.
기존 9종의 `## 근거` 에 있는 `파일:줄` 표가 이 문서에는 **없다.** 지어낼 수 없어서 비운 것이다.
값의 출처는 아래 벤더 한 곳과 [`../tokens.md`](../tokens.md) 뿐이다.

| 항목           | 값                                                            |
| -------------- | ------------------------------------------------------------- |
| 참고한 곳      | daisyUI Timeline — <https://daisyui.com/components/timeline/> |
| 옮긴 날짜      | **2026-09-12**                                                |
| 옮긴 것        | 목록 요소(`<ul>`→`<ol>`)와 "점 + 선 + 내용" 세 조각의 배치    |
| 옮기지 않은 것 | 클래스 이름 전부, 가로·양쪽 변형, `<hr>` 로 선을 그리는 방식  |

**클래스는 우리 토큰으로 다시 썼다. 새 대비 쌍을 만들지 않았다.** 선은 `--border`,
점은 `--muted-foreground`, 시각 글자는 `--muted-foreground`, 내용은 상속받은 `--foreground` 다.

### 2. daisyUI 와 다르게 정한 것

| 갈래      | daisyUI                                               | 우리                                                  |
| --------- | ----------------------------------------------------- | ----------------------------------------------------- |
| 목록 요소 | `<ul>`                                                | **`<ol>`**                                            |
| 방향      | 세로 · 가로 · 양쪽 번갈아                             | **세로 하나**                                         |
| 조각      | `timeline-start` · `timeline-middle` · `timeline-end` | 시각과 내용 둘 (양쪽이 없으니 start/end 가 필요 없다) |
| 선        | `<hr>` 요소                                           | `aria-hidden` 인 빈 `<span>`                          |
| 시각      | 그냥 글자                                             | **`<time datetime>`**                                 |

**`<ul>` 을 `<ol>` 로 바꿨다. 이유:** 시간 순이 이 목록의 뜻이다. `<ul>` 은 순서가 상관없다는
뜻이라 항목을 섞어도 같은 목록이 된다. 스크린리더가 몇 번째인지 읽어 주는 것도 `<ol>` 뿐이다.

**`<hr>` 로 선을 그리지 않는다. 이유:** [`Separator.md`](Separator.md) 가 `<hr>` 을
"여기서 한 덩어리가 끝난다" 는 **정보**로 쓴다. 같은 요소를 여기서 장식으로 쓰면 한 요소가
두 뜻을 갖는다. 이 선은 항목 사이의 단절이 아니라 이어짐의 그림이라 `aria-hidden` 인 빈 칸이 맞다.

**가로·양쪽 변형을 만들지 않았다. 이유:** 쓸 자리가 0곳이다. 양쪽 번갈아 놓는 변형은 좁은
화면에서 읽는 순서가 지그재그가 되어 daisyUI 자신도 `timeline-compact` 로 한쪽에 모은다.
처음부터 한쪽이면 그 분기가 필요 없다.

### 3. 선과 점의 기하 (`../../src/ui/timeline.tsx`)

점은 8px(`size-2`) 원이고 위에서 4px(`mt-1`) 내려와 있다. 시각 글자가 `text-xs`(12px)에
줄 높이 16px 이라 그 가운데가 8px 이고, 점의 가운데도 4 + 4 = 8px 다. **둘이 같은 높이에 선다.**

선은 항목 칸의 위에서 아래까지 1px 로 서고 점이 그 위를 덮는다. 양 끝만 다르다.

| 항목        | 선이 서는 구간                | 클래스                                  |
| ----------- | ----------------------------- | --------------------------------------- |
| 첫 번째     | 점 위(4px)부터 아래까지       | `group-first:top-1`                     |
| 가운데      | 위에서 아래까지               | (기본값 `top-0 bottom-0`)               |
| 마지막      | 위에서 점까지(8px)            | `group-last:bottom-auto group-last:h-2` |
| 하나뿐일 때 | 4px~12px — 점에 완전히 가린다 | 위 둘이 함께 걸린다                     |

**항목 사이 여백(`pb-6`, 24px)이 내용 쪽에 붙어 있다. 이유:** `<li>` 에 걸면 그 여백이
flex 컨테이너 밖이 되어 선이 거기서 끊긴다. 내용 칸 안에 두면 선이 여백을 가로질러 이어진다.

## props

### Timeline

| 이름     | 타입              | 필수 | 기본값 | 의미              |
| -------- | ----------------- | ---- | ------ | ----------------- |
| children | `React.ReactNode` | O    | —      | `TimelineItem` 들 |

**`TimelineItem` 외의 것을 넣지 마라.** 타입으로 막지 않는다 — 이유: `React.ReactNode` 를
좁히면 `map` 이나 조건부 렌더가 막힌다. 대신 `<ol>` 의 직계 자식은 `<li>` 여야 한다는
HTML 규칙이 그대로 적용된다.

### TimelineItem

| 이름     | 타입              | 필수 | 기본값 | 의미                                                   |
| -------- | ----------------- | ---- | ------ | ------------------------------------------------------ |
| time     | `string`          | O    | —      | 화면에 보이는 시각. `2026-09-12` · `사흘 전`           |
| dateTime | `string`          | O    | —      | 기계가 읽는 시각. `<time datetime>` 에 그대로 들어간다 |
| children | `React.ReactNode` | O    | —      | 그때 무슨 일이 있었는지                                |

**`dateTime` 이 선택이 아니다.**
**이유:** 선택으로 두면 빠진 항목이 생긴다. `datetime` 이 없는 `<time>` 은 자기 글자를 날짜로
읽으려 하는데 `사흘 전` 은 날짜가 아니다. 그러면 그 항목만 기계가 시각을 알 수 없다.
형식은 HTML 의 유효한 날짜 문자열이다 — `2026-09-12` · `2026-09` · `2026-09-12T14:30`.

**점 색·선 색을 받는 prop 을 두지 마라.**
**이유:** 상태를 색으로 가르고 싶어지는 자리인데, [`../tokens.md`](../tokens.md) 의 랜딩 팔레트 절이
"강조색을 하나만 쓴다" 를 정했다. 항목의 성격이 다르면 색이 아니라 `children` 의 글이 말한다.

**`className` 을 받지 않는다.**
**이유:** 점과 선의 자리는 `w-2` 칸과 `mt-1` 이 함께 맞춘 값이다. 바깥에서 여백을 덧대면
선이 점에서 어긋나고, 그 어긋남은 항목이 여럿일 때만 보인다.

## states

| state         | 트리거 | 시각 변화                                                                                                                                            |
| ------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| default       | —      | 8px 점 + 1px 세로선(`--border`), 오른쪽 16px(`gap-4`) 떨어져 시각(12px · `--muted-foreground`)과 내용(14px)이 선다                                   |
| hover         | 없다   | 상호작용 요소가 아니다. `timeline.tsx` 에 `hover:` 가 0건이다. 항목이 어딘가로 가야 하면 `children` 안에 `AppLink` 를 넣고 hover 는 그 링크가 갖는다 |
| focus-visible | 없다   | 목록도 항목도 포커스를 받지 않는다. `tabindex` 를 주지 마라 — 이유: 읽기만 하는 항목이 포커스 순서에 끼면 링크에 닿기까지 누르는 횟수만 늘어난다     |
| pressed       | 없다   | 누를 수 없다                                                                                                                                         |
| disabled      | 없다   | 비활성 개념이 없다. 일어난 일은 끌 수 없다                                                                                                           |
| loading       | 없다   | 스스로 데이터를 불러오지 않는다. 불러오는 중을 보여야 하면 목록 자리에 [`Skeleton.md`](Skeleton.md) 를 놓는다                                        |
| empty         | 없다   | 항목이 0개면 빈 `<ol>` 이 남는다. **빈 목록을 렌더하지 마라 — 이유:** 아무것도 없는 자리가 실패처럼 보인다. "아직 없다" 는 글은 부르는 쪽이 쓴다     |
| error         | 없다   | 상태를 갖지 않아 실패할 동작이 없다                                                                                                                  |

**전이를 넣지 마라.** `timeline.tsx` 에 `transition-*` 이 0건이다.
**이유:** 항목이 늘어나는 것 말고 바뀌는 것이 없다. 새 항목이 미끄러져 들어오게 만들면
[`../tokens.md`](../tokens.md) 의 `motion-reduce:` 짝 규칙과 그 항목만의 상태가 함께 생긴다.

## a11y

- a11y:label — 목록에 `aria-label` 을 붙이지 않는다. **이유:** 이 목록이 무엇의 시간 순인지는 바로 위의 제목이 말한다. 라벨을 붙이면 제목과 두 번 읽힌다. 여러 시간 순 목록이 한 화면에 있으면 그때 각각에 `aria-labelledby` 로 제목을 가리키게 하는 것이 맞고, 그 값은 화면이 정한다. 선과 점에는 `aria-hidden` 이 붙는다 — 이유: 이어짐이라는 뜻은 목록이라는 사실이 이미 말한다
- a11y:focus — 포커스 대상이 **0개**다. `children` 안에 링크나 버튼을 넣으면 그것만 포커스를 받고, 순서는 DOM 순서 그대로 위에서 아래다
- a11y:contrast — 시각 fg=`--muted-foreground` / bg=`--background` 라이트 5.28 · 다크 7.97, 내용 fg=`--foreground` / bg=`--background` 라이트 15.82 · 다크 16.13 ([`../tokens.md`](../tokens.md) `## 대비 검증` 의 대비값, 4.5:1 통과). 점과 선은 글자가 아니고 `aria-hidden` 인 장식이라 이 기준의 대상이 아니다 — 같은 문서가 카드 테두리에 대해 이미 같은 판단을 내렸다. **새 쌍을 만들지 않았다**
- a11y:target — 클릭 대상이 **아니다.** 24x24 규칙(WCAG 2.5.8)이 걸리지 않는다. `children` 안의 링크는 그 컴포넌트의 규칙을 받는다
- a11y:role — `<ol>` 이 `list`, `<li>` 가 `listitem`, 시각이 `time` 이다. **`role` 을 덧붙이지 않았다 — 이유:** 요소가 이미 그 역할을 가진다. **확인하지 못한 것:** Tailwind preflight 가 목록의 `list-style` 을 지우는데, 그 상태에서 Safari + VoiceOver 가 목록 역할을 잃는다고 알려져 있다. 이 조합을 실제 기기에서 재지 못했다. 재서 잃는 것이 확인되면 `<ol>` 에 `role="list"` 를 더한다 — 고칠 곳은 `timeline.tsx` 의 `<ol>` 한 줄이다

## responsive

- **브레이크포인트 분기 0건.** `timeline.tsx` 에 `sm:` · `md:` 가 하나도 없다. 375px 에서나 1024px 에서나 배치가 같다
- 왼쪽 칸이 `w-2`(8px) 고정이고 `shrink-0` 이라 화면이 좁아져도 점이 눌리지 않는다. 내용 칸이 남은 폭을 전부 쓰고, 글이 길면 줄이 늘어난다
- 폭을 정하지 않는다. **`Timeline` 에 `max-w-*` 를 걸지 마라 — 이유:** 읽기 폭은 [`../tokens.md`](../tokens.md) 의 `max-w-[68ch]` 가 정하고, 두 곳이 폭을 정하면 어느 값이 적용되는지 화면에서만 드러난다
- 가로 변형이 없으므로 폭이 넓어져도 방향이 바뀌지 않는다

## 상호작용

- 없다. hover / focus-visible / active 대상이 아니다
- `children` 안에 링크를 넣으면 그 링크가 자기 규칙(hover 는 `--brand-accent`, focus 는 4조각 한 벌)을 따른다
