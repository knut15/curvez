# 디자인 토큰 — handwork

**이 문서 하나가 handwork 디자인 시스템의 값 전부를 갖는다.** 색 · 랜딩 팔레트 · 형태 · 폭 ·
간격 · 타이포 · 상태 · 고도, 그리고 문서 끝의 대비 검증 목록까지다. 값을 찾으려고 이 문서 밖으로
나갈 일이 없어야 한다.

**색의 실제 출처는 `../tokens.css` 다.** 아래 표는 그 파일의 `oklch()` 값을
읽기 쉬운 hex 로 옮긴 사본이고 값이 서로 다르면 CSS 를 따른다. 둘이 어긋나면
`node packages/scopulus-ui/scripts/check-contrast.mjs` 의 동기 검사가 잡는다 — 사람이 눈으로 대조하지 않는다.

**간격 · 타이포 · 상태 · 고도는 화면에서 쓰던 것이다.** `apps/handwork/src` 의 `*.tsx` · `*.ts` 를
세어서 나왔고, 재현 명령이 각 절에 붙어 있다. **세지 않은 값을 이 문서에 적지 마라.**

**새 토큰을 만들지 마라.** 값이 더 필요하면 이 문서에 먼저 적고 코드에서 그 이름으로 부른다.
**이유:** 코드에만 있는 값은 문서에 남지 않는다. 다음 사람이 스펙을 읽고 만든 화면과 실제 화면이
달라지고 어느 쪽이 맞는지 판정할 근거가 사라진다.

토큰을 늘릴지는 값이 아니라 **의미가 몇 개인가**로 판정한다.

| 상황                                  | 판단                                           |
| ------------------------------------- | ---------------------------------------------- |
| 기존 토큰과 명도 차 5% 미만           | 기존 것을 쓴다                                 |
| 같은 새 값이 서로 다른 컴포넌트 3곳에 | 토큰으로 승격한다                              |
| 한 곳에서만 쓰인다                    | 만들지 않는다. 컴포넌트 스펙에 리터럴로 적는다 |
| 값은 같은데 의미가 다르다             | 나눈다                                         |
| 값은 다른데 의미가 같다               | 나누지 않는다. 하나로 통일하고 이유를 남긴다   |

## 이름 규칙 — shadcn 이 정한 이름을 그대로 쓴다

토큰 이름은 `--background`, `--muted-foreground` 처럼 shadcn 이 정한 것을 그대로 쓴다.

**이유:** 이 이름들을 Tailwind 테마와 shadcn 컴포넌트가 직접 참조한다(`bg-background`,
`text-muted-foreground`). 이름을 바꾸면 `shadcn add` 로 받은 컴포넌트가 전부 동작하지 않아,
컴포넌트를 받을 때마다 손으로 고쳐야 한다.

**값을 이름에 넣지 마라** — `--color-blue-500` 같은 것.
**이유:** 다크에서 그 토큰이 밝은 색이 되면 이름이 거짓말을 한다. 구현자는 이름을 믿고 잘못 쓴다.
shadcn 이름은 이미 그 규칙을 지킨다 — `--muted-foreground` 는 역할 이름이지 색 이름이 아니다.

**라이트와 다크를 같은 행에서 동시에 정한다. 한 칸도 비우지 마라.**
**이유:** 색은 배경과의 쌍으로만 의미가 있다. 라이트만 정한 토큰은 절반의 값이 아니라
**검증되지 않은 값**이다. 다크를 나중에 맞추려고 글자 색을 밝히는 순간 라이트에서 이미 통과했던
조합이 깨지고, 그때는 컴포넌트가 라이트 값을 하드코딩한 뒤라 되돌리는 비용이 훨씬 크다.

**중립 스케일은 무채색이 아니라 브랜드 색조(green-grey)를 띤다.** shadcn 기본값을 그대로 쓰면
헤더 바(`--brand-canvas`)와 본문 배경이 서로 다른 팔레트로 읽혀 서브 페이지마다 이음매가 보인다.
명도는 기본값과 거의 같게 두고 채도만 얹었다.

**`--foreground` 와 `--brand-ink`, `--ring` 과 `--brand-accent` 는 값이 같다. 토큰은 합치지 않는다.**
**이유:** 하나는 사이트 전역의 역할이고 하나는 랜딩 전용이다. 지금 값이 같다고 합치면 랜딩 색을
조정할 때 서브 페이지 본문 색까지 함께 움직인다.

**다크의 `--border` 는 알파값이다.** hex 로 옮길 수 없어 rgba 로 적었다. 대비 검증에서 제외한다 —
알파 위 실제 색은 배경에 따라 달라져 고정 쌍으로 계산되지 않는다.

## 랜딩 팔레트 — 홈에만 쓴다

레퍼런스 포스터의 **느낌**(굵은 기하 무늬 · 단일 강조색 · 딱딱한 그리드)만 가져오고 색은 바꾼다.
라이트는 teal, 다크는 mint 다. 면과 무늬로는 홈(`/`)에서만 쓴다.

**상호작용 색은 사이트 전역에서 이 강조색 하나다.** 링크 hover 와 포커스 링이 전부 여기로 모인다.
**이유:** 화면마다 hover 색이 다르면 "여기를 누를 수 있다" 를 색으로 배울 수 없다. 강조색을
하나로 잠가야 나머지 색이 전부 중립으로 읽힌다.

| 토큰           | 라이트  | 다크    | 용도                                        |
| -------------- | ------- | ------- | ------------------------------------------- |
| --brand-accent | #0B6B63 | #5EEAD4 | 단일 강조색. 제목·무늬·채운 면              |
| --brand-canvas | #E4E8E7 | #101514 | 랜딩 바탕. shadcn 의 --background 와 다르다 |
| --brand-ink    | #14201E | #E6EDEA | 랜딩 본문·설명                              |

**강조색을 하나만 쓴다.** 두 번째 색을 들이지 않는다.
**이유:** 이 스타일이 성립하는 근거가 색 대비가 아니라 형태 대비(면·줄·원)다. 색이 둘이 되는 순간
무늬가 장식으로 읽히고, 강조가 어디에 있는지 판정할 수 없게 된다.

**무늬는 이미지가 아니라 CSS 그라디언트와 인라인 SVG 로 그린다.**
**이유:** 벡터라 어느 해상도에서도 선명하고 색이 토큰을 따라가 다크에서 자동으로 뒤집힌다.
비트맵으로 두면 테마마다 파일을 두 벌 관리해야 하고 그 둘이 조용히 어긋난다.

대비는 라이트 5.15 · 다크 12.46 로 **큰 글자 전용 제약이 없다.** 강조색을 본문에 써도 통과한다 —
다만 그렇게 쓰지 않는다. 위의 "강조색 하나" 규칙이 형태로 강조하라는 뜻이다.

## 형태 — 반경 스케일 하나만 쓴다

한 화면에 둥근 버튼과 각진 카드가 섞이면 어느 쪽이 의도인지 판정할 수 없다. 단계를 셋으로 못박는다.

| 대상                           | 클래스       | 값                |
| ------------------------------ | ------------ | ----------------- |
| 카드 · 코드 블록               | `rounded-lg` | 10px (`--radius`) |
| 아이콘 버튼 · 포커스 링 모서리 | `rounded-md` | 8px               |
| 태그 칩 · 인라인 코드          | `rounded-sm` | 6px               |

**스케일 밖의 `rounded`(4px)를 쓰지 않는다.** Tailwind 기본값이라 손에 먼저 잡히지만
`--radius` 를 따라가지 않아 반경을 조정할 때 혼자 남는다.

## 폭 — 고정된 두 값

간격 스케일과 달리 이 둘은 Tailwind 스텝이 아니라 읽기 폭이다.

| 대상      | 값                   | 근거                                                    |
| --------- | -------------------- | ------------------------------------------------------- |
| 페이지 폭 | `max-w-5xl` (1024px) | 목록·상세의 바깥 컨테이너. 화면에 6번 나온다            |
| 본문 폭   | `max-w-[68ch]`       | 읽기 폭. 상세 화면의 머리·본문·이웃 내비게이션에만 적용 |

**`max-w-5xl` 위로 레이아웃이 더 바뀌지 않는다.** 그래서 `lg` 이상 브레이크포인트가 없다.

**설명 문단은 `max-w-[65ch]` 다.** 근거와 통일 사유는 [`components/PageTitle.md`](components/PageTitle.md) 에 있다.

## 간격

Tailwind 4 의 기본 스케일을 쓴다. 1스텝 = `0.25rem` = 4px.

```bash
grep -rhoE '\b(p[xytblr]?|m[xytblr]?|gap)-[0-9.]+\b' apps/handwork/src --include='*.tsx' --include='*.ts' \
  | sed -E 's/^[a-z]+-//' | sort -g | uniq -c
```

### 금지

- **임의값 간격을 쓰지 마라** — `p-[13px]`, `gap-[18px]` 같은 것.
  **이유:** 화면에 0번 나온다. 하나가 들어오면 스케일 밖의 값이 맞는지 틀린지 판정할 기준이 사라진다.
- **스텝 7 · 9 · 11 · 14 · 20 을 쓰지 마라.**
  **이유:** 위 12단계 밖이다. 4pt 그리드 위에 있어도 쓰이지 않는 단계를 늘리면 "28px 인가 32px 인가" 가
  매번 판단 대상이 된다.
- **`gap-8`(32px)은 아직 쓰이지 않는다. 그러나 지우지 않는다.**
  **이유:** 세 단계(`gap-2`/`gap-4`/`gap-8`)는 상한 규칙이고 화면에 0번 나온 것은 아직 그 상한까지 간 자리가
  없다는 뜻이다. 쓰이지 않는 것과 금지된 것은 다르다. 자세한 것은 아래 `이전 표와 어긋난 곳` 절에 있다.

### 브레이크포인트

Tailwind 4 기본값을 그대로 쓴다. 화면에서 쓰던 것은 둘뿐이다 — `sm` 1회, `md` 15회.

| 접두 | 최소 폭 | 화면에 나온 횟수 | 쓰이는 자리                                           |
| ---- | ------- | ---------------: | ----------------------------------------------------- |
| `sm` | 640px   |                1 | 헤더 태그라인 접기 `hidden sm:inline`                 |
| `md` | 768px   |               15 | 좌우·세로 여백 8회+5회, 목록 2열 `md:grid-cols-2` 2회 |

**`lg`·`xl`·`2xl` 을 쓰지 마라.**
**이유:** 페이지 폭이 `max-w-5xl`(1024px)에서 멈춘다. 1024px 위에서는 레이아웃이 더 바뀌지 않으므로
분기를 늘려도 화면이 달라지지 않는다.

## 타이포 스케일

```bash
grep -rhoE '\b(text|font|tracking|leading)-[a-z0-9[\]().,%-]+' apps/handwork/src \
  --include='*.tsx' --include='*.ts' | sort | uniq -c | sort -rn
```

### 크기 — 8단계

| 단계           | 클래스                            |         px | 화면에 나온 횟수 | 쓰이는 자리                               |
| -------------- | --------------------------------- | ---------: | ---------------: | ----------------------------------------- |
| 워드마크       | `text-[clamp(2.1rem,9vw,6.6rem)]` | 33.6~105.6 |                1 | 랜딩 h1 (`views/home.tsx:103`)            |
| h1             | `text-4xl`                        |         36 |                5 | 모든 화면 제목                            |
| h2             | `text-2xl`                        |         24 |                1 | Prose h2 (`shared/ui/prose.ts:8`)         |
| h3 · 카드 제목 | `text-lg`                         |         18 |                3 | Prose h3, CaseCard·LabCard 제목           |
| 본문           | (클래스 없음 = `1rem`)            |         16 |                0 | `body` 기본값을 상속한다                  |
| 보조           | `text-sm`                         |         14 |                5 | 상세 메타 줄, 카드 요약, 이웃 링크        |
| 메타           | `text-xs`                         |         12 |                4 | 태그 칩, 카드 날짜 줄                     |
| 모노 라벨      | `text-[0.7rem]`                   |       11.2 |                4 | 헤더 링크·워드마크, 푸터, LabCard 상태 줄 |

**본문에 `text-base` 를 붙이지 마라.** 화면에 0번 나온다. `body` 가 이미 16px 이고 붙이면 "붙은 곳과
안 붙은 곳 중 어느 쪽이 의도인가" 가 생긴다.

**`text-[0.6em]` 은 스케일이 아니다.** 헤더 워드마크의 `®` 첨자 하나(`widgets/site-header.tsx:26`)이고
부모 글자에 상대적이다. 단계로 승격하지 않는다 — 이유: 한 자리에서만 쓰인다.

### 굵기 — 5단계

| 클래스          |  값 | 화면에 나온 횟수 | 쓰이는 자리                          |
| --------------- | --: | ---------------: | ------------------------------------ |
| `font-black`    | 900 |                1 | 랜딩 워드마크 (`views/home.tsx:103`) |
| `font-bold`     | 700 |                5 | 모든 h1                              |
| `font-semibold` | 600 |                1 | Prose h2                             |
| `font-medium`   | 500 |                3 | 카드 제목 2, Prose h3 1              |
| (클래스 없음)   | 400 |                — | 본문·보조·메타 전부                  |

**600 과 700 사이에 단계를 넣지 마라.** 화면에서 h1 은 전부 700, h2 는 600 하나다. 단계를 늘리면
어느 굵기가 어느 층인지 화면에서 구분되지 않는다.

### 서체 — 2종

| 클래스      | 실체                         | 화면에 나온 횟수 | 쓰이는 자리                                           |
| ----------- | ---------------------------- | ---------------: | ----------------------------------------------------- |
| (기본)      | Pretendard Variable (45~920) |                — | `html` 에 `font-sans` 가 걸려 있다                    |
| `font-mono` | Geist Mono                   |                4 | 헤더 링크·푸터·LabCard 상태 줄의 대문자 라벨          |
| `font-sans` | Pretendard 로 되돌림         |                1 | `entities/lab/ui/lab-card.tsx:27` — 모노 줄 안의 한글 |

**한글에 `font-mono` 를 걸지 마라.**
**이유:** Geist Mono 에 한글 글립이 없어 폰트가 대체되고 같은 줄에서 서체가 달라진다. 실제로 그 자리에서
`font-sans tracking-normal normal-case` 로 되돌리고 있다(`lab-card.tsx:27`). 그것이 이 규칙을 화면에서 쓰던 증거다.

### 자간 — 7단계

| 클래스                | 값       | 화면에 나온 횟수 | 쓰이는 자리                     |
| --------------------- | -------- | ---------------: | ------------------------------- |
| `tracking-[-0.03em]`  | -0.03em  |                1 | 랜딩 워드마크                   |
| `tracking-[-0.02em]`  | -0.02em  |                5 | 모든 h1                         |
| `tracking-[-0.015em]` | -0.015em |                1 | Prose h2                        |
| (없음)                | 0        |                — | 본문                            |
| `tracking-normal`     | 0        |                1 | 모노 줄 안에서 한글로 되돌릴 때 |
| `tracking-wide`       | 0.025em  |                2 | 상세 화면 메타 줄               |
| `tracking-widest`     | 0.1em    |                3 | 모노 대문자 라벨                |
| `tracking-[0.22em]`   | 0.22em   |                1 | 헤더 워드마크 `handwork®`       |

**글자가 클수록 음수, 작고 대문자일수록 양수다.** 이 방향을 뒤집지 마라 — 이유: 큰 글자는 기본 자간이
벌어져 보이고 작은 대문자는 붙어 보인다.

### 행간 — 3단계

| 클래스            | 값    | 화면에 나온 횟수 | 쓰이는 자리                       |
| ----------------- | ----- | ---------------: | --------------------------------- |
| `leading-[0.82]`  | 0.82  |                1 | 랜딩 워드마크                     |
| `leading-[1.15]`  | 1.15  |                2 | 상세 화면 h1 (두 줄이 될 수 있다) |
| `leading-relaxed` | 1.625 |                3 | 본문·설명 문단                    |

**목록 화면 h1 에는 `leading` 을 걸지 않는다.** 화면에서 `case-index.tsx:9` · `lab-index.tsx:7` ·
`not-found.tsx:11` 셋 다 없다. 한 줄로 끝나는 제목이라 행간이 화면에 드러나지 않는다.

### 줄 수 제한

| 클래스         | 화면에 나온 횟수 | 쓰이는 자리            |
| -------------- | ---------------: | ---------------------- |
| `line-clamp-2` |                2 | 카드 제목 (Case · Lab) |
| `line-clamp-3` |                2 | 카드 요약 (Case · Lab) |

**카드 높이를 `h-*` 로 고정하지 마라.** 줄 수 제한이 높이를 맞춘다 — 이유: 고정 높이는 글자 크기가
바뀌면 잘리고, 줄 수 제한은 따라 늘어난다.

## 이전 표와 어긋난 곳 — 화면에서 쓰던 것을 따른다

이 문서에는 원래 "Tailwind 기본 스케일을 그대로 쓴다. 값을 고정할 자리만 못박는다" 는 짧은 표가
있었다. 위의 간격·타이포 절이 그것을 화면에서 쓰던 것으로 대체했다. **네 곳이 어긋난다. 조용히 지우지 않고
어디가 어떻게 달랐는지 남긴다.**

| 이전 표가 말한 것                            | 화면에서 쓰던 것                                            | 어느 쪽을 쓰나                 |
| -------------------------------------------- | ----------------------------------------------------------- | ------------------------------ |
| 요소 간 간격 `gap-2`/`gap-4`/`gap-8` 세 단계 | `gap-2` 8회 · `gap-4` 5회 · **`gap-8` 0회**                 | 세 단계를 유지한다 (아래 참조) |
| 제목 `text-4xl`/`text-2xl`/`text-lg` 세 단계 | 크기 **8단계**. 제목 셋 + 본문·보조·메타·모노 라벨·워드마크 | 8단계. 이전 표는 제목만 다뤘다 |
| 제목 자간 셋 (h1·h2·본문)                    | 자간 **7단계**. 모노 라벨의 양수 자간이 빠져 있었다         | 7단계                          |
| 본문 행간 `leading-relaxed` 하나             | 행간 **3단계**. 워드마크 0.82, 상세 h1 1.15 가 빠져 있었다  | 3단계                          |

**`gap-8` 은 화면에 0번 나왔는데도 지우지 않는다.**
**이유:** 세 단계는 "요소 간 간격을 이 셋 밖에서 고르지 마라" 는 상한 규칙이고 화면에 0번 나온 것은 아직
그 상한까지 간 자리가 없다는 뜻이다. 쓰이지 않는 것과 금지된 것은 다르다. 네 번째 단계를
쓰고 싶어지면 그때가 이 표를 고칠 때다.

**나머지 셋은 화면에서 쓰던 것을 따른다.**
**이유:** 이전 표는 "제목" 만 다루고 본문·보조·메타를 비워 둔 부분 목록이었다. 부분 목록을 전체
규칙으로 읽으면 목록에 없는 자리에서 구현자가 값을 지어낸다.

## 상태

기존 코드에 이미 굳어 있는 조합이다. **이것을 정본으로 고정한다.**

```bash
grep -rhoE '(hover|focus-visible|active|disabled|motion-reduce):[a-z0-9:[\]/._-]+' apps/handwork/src \
  --include='*.tsx' --include='*.ts' | sort | uniq -c | sort -rn
```

### 전이 — 모든 상태 변화에 같은 값

| 조각                                            | 값                               | 화면에 나온 횟수 | 비고                                     |
| ----------------------------------------------- | -------------------------------- | ---------------: | ---------------------------------------- |
| `transition-colors`                             | 색 속성만                        |                8 | 기본값                                   |
| `transition-[color,background-color,transform]` | 위 + transform                   |                1 | ThemeToggle 하나 (`theme-toggle.tsx:21`) |
| `duration-150`                                  | 150ms                            |                9 | 전이가 있는 모든 자리                    |
| `ease-out`                                      | `cubic-bezier(0.23, 1, 0.32, 1)` |                9 | `globals.css:10` 의 `--ease-out` 이 정본 |
| `motion-reduce:transition-none`                 | 전이 끔                          |                8 | 전이가 있는 모든 자리                    |

**전이를 넣으면 `motion-reduce:transition-none` 을 같은 줄에 넣는다.** 화면에 8:8 로 이미 1:1 이다.
**이유:** 나중에 붙이려면 전이가 있는 줄을 전부 다시 찾아야 하고, 빠진 곳은 화면에서만 드러난다.

**`transition-all` 을 쓰지 마라.** 화면에 0번 나온다.
**이유:** 레이아웃 속성까지 애니메이션되어 스크롤 중에 프레임이 떨어진다.

### hover

| 대상         | 바뀌는 것                                      | 화면에 나온 횟수 | 근거 줄                                                                                          |
| ------------ | ---------------------------------------------- | ---------------: | ------------------------------------------------------------------------------------------------ |
| 링크(텍스트) | fg → `--brand-accent`                          |                6 | `not-found.tsx:17` `case-index.tsx:19` `case-detail.tsx:10` `site-header.tsx:15,24` `prose.ts:8` |
| 면(카드)     | bg → `--accent`. 테두리 유지, 이동·그림자 없음 |                3 | `case-card.tsx:16` `lab-card.tsx:16` (+`theme-toggle.tsx:21`)                                    |
| 아이콘 버튼  | bg → `--accent`, fg → `--accent-foreground`    |                1 | `theme-toggle.tsx:21`                                                                            |

**hover 색은 사이트 전역에서 `--brand-accent` 하나다.** 위 `랜딩 팔레트` 절이 정했다:
"상호작용 색은 사이트 전역에서 이 강조색 하나다. 링크 hover 와 포커스 링이 전부 여기로 모인다."
**이유:** 화면마다 hover 색이 다르면 "여기를 누를 수 있다" 를 색으로 배울 수 없다.

**hover 에서 위치를 옮기지 마라** — `translate`, `-translate-y-*`, `scale` 금지. 화면에 0번 나온다.
**이유:** 포인터가 요소 경계에 있을 때 요소가 포인터 밑에서 빠져나가 hover 가 깜빡인다.

### focus-visible

**네 조각이 한 벌이다. 하나만 쓰지 마라.**

| 조각                             | 값                            | 화면에 나온 횟수 |
| -------------------------------- | ----------------------------- | ---------------: |
| `focus-visible:outline-2`        | 2px                           |                8 |
| `focus-visible:outline-offset-2` | 2px 띄움                      |                8 |
| `focus-visible:outline-ring`     | `--ring` (= `--brand-accent`) |                8 |
| `focus-visible:rounded-sm`       | 6px — **인라인 링크에만**     |                5 |

`focus-visible:rounded-sm` 이 5건인 이유: 이미 반경을 가진 것(카드 `rounded-lg` 2건, 토글
`rounded-md` 1건)에는 필요 없다. 반경 없는 인라인 링크 5곳에만 붙는다 —
`not-found.tsx:17` `case-index.tsx:19` `case-detail.tsx:10` `site-header.tsx:15` `site-header.tsx:24`.

**`focus:` 를 쓰지 말고 `focus-visible:` 만 쓴다.** 화면에 `focus:` 가 0번 나온다.
**이유:** 마우스로 누른 뒤에도 링이 남아, 키보드 사용자에게만 의미 있어야 할 신호가 소음이 된다.

**`outline-none` 을 쓰지 마라.** 화면에 0번 나온다.

### active(눌림)

| 대상        | 바뀌는 것               | 화면에 나온 횟수 | 근거 줄               |
| ----------- | ----------------------- | ---------------: | --------------------- |
| 아이콘 버튼 | `active:scale-97` (97%) |                1 | `theme-toggle.tsx:21` |
| 그 밖 전부  | **시각 변화 없음**      |                — | 화면에 0번 나온다     |

`motion-reduce:active:scale-100` 을 같은 줄에 함께 둔다 (`theme-toggle.tsx:21`).

**링크에 눌림 상태를 만들지 마라.**
**이유:** 누르면 주소가 바뀌어 화면이 통째로 교체된다. 그 사이 100ms 를 표시해도 읽히지 않는다.

**제자리에서 상태가 뒤집히는 버튼에만 `active:scale-97` 을 쓴다.**
**이유:** 축소는 "지금 여기서 무언가 일어났다" 는 신호다. 화면을 떠나는 동작에 붙이면 거짓말이 된다.

### disabled

**현재 화면에 0번 나온다.** 화면에 비활성 요소가 없다 — 링크는 항상 유효하고 폼이 없다.

값이 필요해질 때를 위해 조합만 고정한다. **이 값을 쓰기 전에 이 문서 끝의 대비 검증 목록에
해당 쌍을 먼저 추가한다.**

| 조각                           | 값                                           |
| ------------------------------ | -------------------------------------------- |
| `disabled:opacity-50`          | 50%                                          |
| `disabled:pointer-events-none` | 포인터 무시                                  |
| 대비 하한                      | **3:1** (WCAG 1.4.11 — 본문 4.5:1 이 아니다) |

**`disabled` 를 색 하나로만 표현하지 마라.** `aria-disabled` 또는 `disabled` 속성을 함께 준다.
**이유:** 대비를 낮춘 것과 그냥 흐린 글자를 스크린리더는 구분하지 못한다.

## 고도(elevation)

**쓰지 않는다. 그림자 토큰을 만들지 않는다.**

```bash
grep -rnE 'shadow|drop-shadow|elevation' apps/handwork/src --include='*.tsx' --include='*.ts' --include='*.css'
```

**화면에 0번 나온다.** `*.tsx` · `*.ts` · `*.css` 전체에서 그림자를 쓰는 곳이 하나도 없다.

**이유 셋.**

1. **면을 가르는 것이 이 사이트에서는 그림자가 아니라 테두리 1px 이다.** 이 문서 끝의 대비 검증 절이
   적었다 — 카드와 캔버스의 대비가 라이트 1.06 · 다크 1.09 이고, 그것을 가르는 것은 색이 아니라 테두리 1px 이다.
   그림자를 얹으면 같은 경계를 두 방식으로 그리게 되고, 둘의 세기가 어긋나면 카드가 떠 보이는 정도가
   화면마다 달라진다.
2. **다크에서 그림자가 사라진다.** 배경이 `--background`(거의 검정)라 검은 그림자가 보이지 않는다.
   보이게 하려면 다크 전용 그림자 값을 따로 둬야 하고, 그 순간 라이트·다크 두 벌을 손으로 맞춰야 한다.
3. **떠 있어야 하는 것이 없다.** 화면 5개에 모달·드롭다운·토스트·팝오버가 0개다. 겹치는 층이 없으면
   고도는 표현할 깊이가 없다.

**그림자가 필요해지는 조건은 하나다 — 화면 위에 떠서 아래를 가리는 요소가 생길 때.**
그때 이 절을 다시 연다. 지금 값을 지어 두면 쓰이지 않는 토큰이 남고, 처음 쓰는 사람이 그 값이
검증된 것인지 아닌지 알 수 없다.

**바꿀 때 고칠 위치:** 이 절과 `../tokens.css` 의 `@theme inline` 블록 두 곳.
