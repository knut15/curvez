# 되돌리기 어려운 행동은 승인을 받는다

**팀 구성, 커밋·push·머지, 규약 수정처럼 되돌리기 어려운 행동은 사용자의 명시적 승인이 있을 때만 한다.**

**이유:** 워커는 격리된 컨텍스트에서 돌고 중간에 사람에게 되물을 수 없다. 틀린 채로 시작하면 여러 명분의
토큰을 쓰고 나서야 드러나고, 이력에 남은 커밋과 push 는 지워도 흔적이 남는다. 승인은 되돌리기 비용이
가장 싼 지점이다.

**패턴:**

- 팀 구성은 워커를 띄우기 전에 보고하고 승인받는다. 같은 구성의 재실행만 예외다
- `curvez-git` 은 사용자가 "커밋해줘", "머지까지 해줘" 라고 말했을 때만 띄우고, 요청 원문을 그대로 넘긴다
- 회고가 낸 규약 수정안은 사용자가 승인한 것만 반영한다
- 사용자의 확인 질문이나 계획 문서에 적혀 있다는 사실은 승인이 아니다
- 자율 권한: `.curvez/grant.md` 에 사용자 원문으로 적힌 범위의 팀 구성과 머지는 승인으로 본다. 유효한지는
  `scripts/check-grant.mjs` 가 판정한다. 머지는 리뷰어·QA·교차 리뷰어 핸드오프가 있어야 열린다. 의존성·curvez 자체·배포 워크플로 변경과 강제 push·원격 브랜치 삭제는
  권한이 있어도 멈춘다

**판정 질문:** 이 행동을 하라는 사용자 원문을 인용할 수 있는가?

**더 읽을 곳:** `agents/curvez-orchestrator.md` 의 `### 승인 절차`.
