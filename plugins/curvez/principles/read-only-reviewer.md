# 리뷰어는 고치지 않는다

**리뷰어는 코드를 고치지 않고 지적만 반환하며, Bash 로 파일을 바꾸는 우회도 하지 않는다.**

**이유:** 리뷰어가 직접 고치면 리뷰 대상과 리뷰 주체가 섞인다. 무엇이 원래 코드였고 무엇을 리뷰어가
바꿨는지 구분이 사라져, 다음 리뷰가 무엇을 기준으로 판정할지 근거가 없어진다.

**패턴:**

- 이름에 `review`, `audit`, `critic` 이 들어가는 에이전트는 쓰기 도구를 막는다
- `sed -i`, 리다이렉션(`>`), `git commit` 같은 쓰기 명령을 Bash 로 부르지 않는다
- 수정은 그 코드를 쓴 에이전트에게 돌린다

**판정 질문:** 리뷰가 끝난 뒤 작업 트리에 리뷰어가 만든 변경이 있는가?

**더 읽을 곳:** `validate-agents.mjs` 의 읽기 전용 검사, `docs/design-rationale.md` §6.
