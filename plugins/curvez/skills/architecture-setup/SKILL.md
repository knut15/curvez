아키텍처 확정은 설계가 아니라 **선택과 기록**이다. DDD 프리셋을 기준으로 팀 용어에 맞춰 몇 군데만 바꾸고,
기계가 검사할 수 있는 금지 import 표로 굳힌다. 산출물은 `.curvez/architecture.md` 한 파일이다.
이 표는 `quality-gate` 의 경계 검사가 위반을 판정하는 유일한 근거다.

## 언제 쓰지 않는가

- `.curvez/` 와 `profile.json` 이 아직 없다 → `bootstrap` 을 먼저 쓴다. 이 스킬은 `profile.json` 이 있다는 전제로 시작한다
- 이미 있는 코드에서 경계 위반을 찾는다 → `quality-gate` 를 쓴다. 이 스킬은 기준을 만들고, 그 기준으로 코드를 판정하는 것은 `quality-gate` 다

## 1. 입력을 확인한다

```bash
test -f .curvez/profile.json && echo "profile OK" || echo "profile MISSING"
test -f .curvez/architecture.md && echo "재실행" || echo "최초 실행"
```

- `profile.json` 이 없으면 멈추고 `bootstrap` 을 먼저 실행하라고 알린다. 스택을 추측해 만든 레이어 매핑과 금지 import 는 전부 무효다
- `profile.json` 의 `stack` 이 `nextjs`·`monorepo` 가 아니면 멈추고 실제 값을 그대로 보고한다. 비슷한 값으로 바꿔 읽지 않는다
- `architecture.md` 가 이미 있으면 재실행이다. 6단계를 먼저 읽는다

## 2. 프리셋을 확인한다

curvez 는 **DDD 하나만** 제공한다. 다른 구조를 쓰고 싶다는 요청이 없으면 되묻지 않고 DDD 로 진행한다.

프리셋 본문은 `$CLAUDE_PLUGIN_ROOT/presets/architecture/ddd.md` 에 있다. 이 파일이 없어도 멈추지 않는다.
아래 폴백 레이어로 진행하고 `## 결정 로그` 에 "프리셋 파일 부재로 내장 폴백 사용" 을 남긴다.

| 프리셋 | 폴백 레이어 (안쪽 → 바깥쪽) |
|---|---|
| `ddd` | `domain` → `application` → `infrastructure` / `presentation` |

규모가 작으면 레이어를 줄인다. 라우트(화면) 12개 미만이고 도메인 엔티티 8개 미만이면 `application` 을 두지 않는다.
둘 중 하나라도 넘으면 둔다. 규모가 작을 때 레이어를 더 두면 경계는 안 생기고 파일 수만 는다.

### DDD 를 쓰지 않기로 했을 때

사용자가 다른 구조를 명시적으로 요청했을 때만 해당한다. 3단계 인터뷰를 아래 5문으로 바꿔 구조를 처음부터 정한다.

| # | 묻는 것 | 확정되는 것 |
|---|---|---|
| 1 | 어떤 구조인가. 가장 안쪽(가장 오래 사는) 층은 무엇인가 | `## 레이어 정의` 첫 행 |
| 2 | 층을 안쪽에서 바깥쪽 순서로 나열하면 | `## 레이어 정의`, `## 의존 방향` |
| 3 | 어느 층이 어느 층을 참조하면 안 되는가 | `## 금지 import` 후보 |
| 4 | 가장 안쪽 층이 프레임워크를 참조해도 되는가 | 아래 참조 |
| 5 | 각 층이 실제로 어느 디렉터리인가 | `## 폴더 구조`, 검사 경로 |

4번 답이 "된다" 여도 그대로 받아 적는다. 다만 그 결정으로 무엇을 포기하는지 한 번 말한다.
프레임워크를 바꿀 때 그 층을 다시 써야 하고, monorepo 에서 웹과 앱이 같은 로직을 공유할 수 없다.
설득하지 않고 `## 결정 로그` 에 남긴다. 산출물 형식은 DDD 와 같다.

## 3. 인터뷰한다 — 3문 이상 5문 이하

인터뷰는 **레이어 이름과 경계 규칙만** 조정한다. 아래에서 3~5개를 골라 **한 번에** 묻고 한 번에 받는다.

1. 레이어 이름을 팀 용어로 바꿀 것인가 (예: `application` → `usecase`) — 항상
2. 공유 코드(`shared`/`common`)를 어느 레이어에 두고 무엇까지 넣을 것인가 — 항상
3. 경계 예외를 허용할 지점이 있는가. 있다면 어디까지인가 — 예외가 필요해 보일 때
4. 앱 간 공유 경계를 패키지로 자를 것인가, 폴더로 자를 것인가 — `stack: monorepo` 일 때
5. 서버/클라이언트 경계를 어느 레이어에서만 넘을 것인가

묻지 않는 것: 어떤 기능을 만드는지, 어떤 라이브러리를 쓰는지, 화면 모양, 폴더 이름의 단복수·대소문자.
도메인이 프레임워크를 참조해도 되는지도 묻지 않는다. DDD 에서는 항상 금지다.

**5문을 넘기지 않는다.** 6문째부터는 처음부터 설계하는 것과 같아지고, 사용자가 근거 없이 답을 지어내기 시작한다.
못 정한 항목은 프리셋 기본값으로 정하고 `## 결정 로그` 에 되돌릴 위치를 남긴다.

인터뷰 답이 프리셋 전제와 부딪히면(예: 도메인에서 프레임워크를 쓰겠다) 그대로 반영하지 않는다.
부딪히는 지점을 사용자에게 알리고 프리셋 기본값으로 쓴다.

## 4. `.curvez/architecture.md` 를 쓴다

헤딩 7개를 **이 문자열 그대로** 쓴다. 헤딩이 고정이어야 결정 로그의 되돌릴 위치와 5단계 grep 이 동작한다.

| 헤딩 | 형식 | 없으면 |
|---|---|---|
| `## 레이어 정의` | 표: `레이어 / 책임 / 여기 들어가는 것 / 여기 들어가면 안 되는 것` | 파일을 어디 둘지 매번 다르게 판단한다 |
| `## 의존 방향` | 단방향 화살표 목록(`presentation → application → domain`)과 역방향 금지 | 순환 의존을 잡을 기준이 없다 |
| `## 금지 import` | 표: `규칙 ID \| 검사 경로 \| 금지 패턴 (ERE) \| 이유`. **최소 3건** | 위반을 검사할 수 없다 |
| `## 폴더 구조` | 코드블록 안 디렉터리 트리. 실제 경로 접두사(`src/`, `apps/web/src/`) 포함 | 같은 레이어가 다른 경로에 생겨 grep 이 빗나간다 |
| `## 스택 매핑` | `stack` 값별 레이어 대응. `monorepo` 면 웹과 공유 도메인 패키지 둘 다 | 자기 스택의 경계를 모른다 |
| `## 예외` | 표: `대상 / 허용 범위 / 만료 조건`. 없으면 "없음" | 만료 없는 예외가 새 기본값이 된다 |
| `## 결정 로그` | 표: `무엇을 / 왜 / 되돌릴 위치`. 되돌릴 위치는 `.curvez/architecture.md:<헤딩>` | 재실행 때 같은 질문을 다시 묻는다 |

`## 금지 import` 표의 세 번째 열은 `grep -E` 에 그대로 들어간다. 행 형식은 정확히 이렇게 쓴다.

```
| ARCH-001 | src/domain/ | from ['\"](next\|next/.*\|react\|react-dom) | 도메인은 프레임워크 교체에서 분리돼야 한다 |
| ARCH-002 | src/app/ | from ['\"](\.\./)*domain/ | 화면은 애플리케이션을 거쳐 도메인에 닿는다 |
| ARCH-003 | src/domain/ | from ['\"](\.\./)*infrastructure/ | 의존은 안쪽으로만 흐른다 |
```

- ID 는 `ARCH-001` 부터 이어 붙인다
- 검사 경로는 한 행에 하나만 쓴다. `quality-gate` 는 2열 전체를 경로 하나로 읽기 때문에, 공백으로 여러 경로를 적으면 "경로 없음" 으로 건너뛴다. 경로가 여럿이면 행을 나눈다
- 패턴 안의 `|` 는 반드시 `\|` 로 쓴다. 그대로 두면 마크다운이 열 구분자로 읽어 표가 깨지고, 5단계 awk 도 3열을 그 자리에서 자른다
- 파이프 양쪽에 공백을 정확히 하나씩 둔다. 5단계 awk 의 구분자가 `' | '` 라서 공백이 없거나 둘이면 열이 밀린다
- 정규식으로 표현할 수 없는 규칙은 `## 권고` 에 따로 적는다. 검사할 수 없는 규칙은 어겨도 아무 일이 없다

규칙과 개발 속도가 부딪히면 규칙을 지킨다. 정말 못 지키면 `## 예외` 에 만료 조건과 함께 남긴다.

파일은 **Write 로 전체를 다시 쓴다.** 부분 수정은 레이어 정의만 바뀌고 금지 import 표는 그대로인 문서를 만든다.

## 5. 검증한다

문서를 쓴 직후 아래를 실제로 실행하고 출력을 그대로 보고한다.

```bash
ARCH=.curvez/architecture.md
test -f "$ARCH" || { echo "FAIL: $ARCH 없음"; exit 1; }

# (1) 필수 헤딩 7개
for h in "레이어 정의" "의존 방향" "금지 import" "폴더 구조" "스택 매핑" "예외" "결정 로그"; do
  grep -q "^## $h" "$ARCH" && echo "OK      $h" || echo "MISSING $h"
done

# (2) 금지 import 규칙 개수
grep -cE '^\| ARCH-[0-9]{3} \|' "$ARCH"

# (3) 3열 ERE 가 grep -E 에서 도는지. 표의 `\|` 를 되돌린 뒤 검사한다
awk -F' \\| ' '/^\| ARCH-[0-9]{3} \|/ { p=$3; gsub(/\\\|/,"|",p); print p }' "$ARCH" |
while IFS= read -r re; do
  grep -Eq "$re" /dev/null 2>/dev/null; st=$?
  if [ "$st" -le 1 ]; then echo "REGEX-OK  $re"; else echo "REGEX-BAD $re"; fi
done

# (4) 의존 방향에 역방향 화살표가 섞였는지 (domain 이 바깥을 가리키면 위반)
grep -nE '^[-*[:space:]]*domain +→' "$ARCH" | wc -l
```

| 출력 | 통과값 | 실패했을 때 |
|---|---|---|
| (1) | `MISSING` 0건 | 빠진 헤딩을 채우고 다시 실행한다 |
| (2) | 3 이상 | 규칙을 더한다 |
| (3) | `REGEX-BAD` 0건, 줄 수가 (2) 와 같다 | 거의 항상 `\|` 누락이다. 출력이 한 줄도 없으면 파이프 양쪽 공백을 본다 |
| (4) | 0 | 화살표 방향을 고친다 |

실제 위반 건수는 `quality-gate` 가 센다. 소스가 아직 없어 검사 대상이 0개여도 실패가 아니다.

## 6. 재실행 — `architecture.md` 가 이미 있을 때

**본문은 덮어쓰고 `## 결정 로그` 는 보존한다.**

1. 기존 파일을 먼저 Read 한다. 읽지 않고 쓰면 결정 로그가 사라진다
2. 결정 로그의 기존 행을 한 줄도 지우지 않고 옮긴다
3. 이번 결정은 그 아래에 더한다. 앞선 결정을 뒤집었으면 지우지 말고 "ARCH-002 를 폐기하고 …로 교체" 처럼 새 행에 적는다
4. 인터뷰는 결정 로그에 답이 이미 있는 문항을 빼고 묻는다

본문은 반대로 쌓으면 안 된다. 낡은 규칙과 새 규칙이 함께 남으면 어느 쪽을 따를지 판정할 수 없다.

## 완료 기준

- [ ] 인터뷰가 3~5문이다. 건너뛴 문항은 결정 로그에 기본값과 되돌릴 위치가 있다
- [ ] 5단계 (1)~(4) 가 모두 통과값이다
- [ ] 결정 로그의 모든 행에 되돌릴 위치가 `.curvez/architecture.md:<헤딩>` 형식으로 있다
- [ ] 재실행이면 이전 결정 로그 행이 전부 남아 있다
