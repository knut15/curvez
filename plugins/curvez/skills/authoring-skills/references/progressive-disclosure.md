# 본문과 references 를 나누는 기준

`SKILL.md` 절차 5단계에서 문서가 길어졌을 때 읽는다.

---

## 상한

| 대상 | 상한 | 검증기 반응 |
|---|---|---|
| SKILL.md 전체 | 500줄 | 오류 |
| 단일 `##` 섹션 | 120줄 | 경고 |

상한은 목표가 아니라 경계다. 300줄에서 이미 뒷부분이 옅어진다.

**이유:** 문서가 길수록 주의가 얇게 퍼져 뒤쪽 지시가 실행될 확률이 떨어진다. 절차형 스킬에서는
특히 치명적이다. 앞의 참고 자료가 뒤의 실행 단계를 밀어낸다.

---

## 무엇을 내리는가

### 반드시 내린다

| 대상 | 왜 |
|---|---|
| **도메인 분기** | Next.js 실행에서는 React Native 상세가 전부 낭비다. 분기마다 파일을 나눈다 |
| **조건부 상세** | 특정 조건에서만 필요한 절차. 조건이 안 걸리면 읽힐 이유가 없다 |
| **긴 예시 모음** | 좋은 예/나쁜 예 나열. 규칙 자체가 아니라 규칙의 예시다 |
| **필드별 레퍼런스** | 스키마의 각 필드 상세. 막혔을 때만 필요하다 |

### 본문에 남긴다

| 대상 | 왜 |
|---|---|
| **모든 실행이 거치는 절차** | 내리면 포인터를 따라가야 하고, 따라가지 않으면 절차가 끊긴다 |
| **트리거 경계** | 호출 판정 직후에 읽혀야 한다 |
| **금지 규칙과 이유** | 규칙이 본문에 없으면 위반이 일어난 뒤에야 참조된다 |
| **완료 기준** | 마지막에 반드시 읽혀야 한다 |

### 판정 질문

**모든 실행이 이것을 읽어야 하는가?**
그렇다면 본문. 일부 실행만이라면 references.

---

## 포인터 쓰는 법

내린 뒤에는 본문에 포인터를 남긴다. 포인터의 문구가 도달 여부를 결정한다.

### 약한 포인터

```markdown
자세한 내용은 [references/field-reference.md](references/field-reference.md) 참고.
```

"참고" 는 조건이 아니다. 읽어도 되고 안 읽어도 되는 것으로 읽힌다.

### 강한 포인터

```markdown
필드별 상세와 실제 예시는 [references/field-reference.md](references/field-reference.md) 를 읽는다.
```

```markdown
대상 스택이 React Native 라면 [references/react-native.md](references/react-native.md) 를 먼저 읽는다.
```

포인터에 **언제 읽는지**를 넣는다. 조건이 있으면 그 조건이 걸릴 때 실제로 도달한다.

**이유:** 포인터는 그 자체가 실행 지시다. 조건 없는 링크는 "존재한다" 만 알릴 뿐
"지금 읽어라" 를 말하지 않는다.

## 나누는 축

### 도메인으로 나눈다

```
skills/quality-gate/
├─ SKILL.md                    # 모든 스택 공통 절차
└─ references/
   ├─ nextjs.md                # Next.js 전용 검사
   └─ react-native.md          # RN 전용 검사
```

### 단계로 나눈다

절차가 길고 뒤 단계가 앞 단계의 완료를 재촉할 때 나눈다.

**이유:** 남은 단계가 눈에 보이면 앞 단계를 서둘러 끝내려는 압력이 생긴다.
"3단계 남았다" 가 보이는 상태에서 1단계의 완료 조건이 모호하면 대충 끝내고 넘어간다.
다만 이 분리는 컨텍스트 경계를 실제로 넘을 때만 효과가 있다 — 서브에이전트에게 넘기거나
핸드오프로 끊을 때다. 같은 컨텍스트에서 파일만 나누면 뒤 단계가 여전히 보인다.

### 깊이로 나눈다

규칙은 본문, 규칙의 근거·예시·예외는 references.

## 고아 참조를 만들지 마라

`references/` 에 있는데 본문 어디서도 가리키지 않는 파일은 도달하지 않는다.
검증기가 경고한다.

**이유:** 참조 파일은 포인터로만 도달한다. 포인터가 없으면 그 파일은 존재하지 않는 것과 같고,
거기 적힌 규칙은 지켜지지 않은 채 문서만 늘어난다.

포인터를 붙일 자리가 없다면 그 파일은 필요 없다. 지운다.

## 나눈 뒤 점검

- [ ] SKILL.md 만 읽고도 기본 경로의 작업을 끝낼 수 있는가
- [ ] references 파일마다 본문에 조건이 붙은 포인터가 있는가
- [ ] 같은 규칙이 본문과 references 양쪽에 있지 않은가
- [ ] `node scripts/validate-skills.mjs <디렉터리>` 가 오류 0개인가
