# 버그 수정 (bug-fix)

**고치기 전에 재현한다. 증상이 아니라 원인이 있는 곳을 고친다.**

1. 보고된 결함을 같은 환경에서 직접 재현한다. 재현 명령과 실제 출력을 남긴다. 재현하지 못하면 멈추고 재현 조건을 묻는다 (원칙: `principles/blocked-over-guessing.md`)
2. 재현을 실패하는 테스트로 만든다(`curvez-qa`). 그 테스트가 지금 실패하는 것을 출력으로 확인한다
3. 원인을 좁힌다. 언제부터 깨졌는지(`git log`, `git bisect`), 어디에서 잘못된 값이 처음 생기는지 찾는다. 원인을 한 문장으로 적는다
4. 수정을 담당 구현 에이전트에게 지시서로 넘긴다. `SCOPE` 는 원인이 있는 파일로 좁히고, `ACCEPTANCE` 에 2번 테스트 이름을 넣는다
5. 2번 테스트가 실패에서 통과로 바뀐 출력을 받고, `quality-gate` 를 모두 돌린다 (원칙: `principles/numbers-not-adjectives.md`)
6. 리뷰 라운드를 연다. 구성은 `feature` 플레이북 6번과 같다
7. `shipping` 플레이북으로 넘어간다

보고: 재현 명령과 출력, 원인 한 문장, 실패에서 통과로 바뀐 테스트 출력, 게이트별 수치, 남은 지적
