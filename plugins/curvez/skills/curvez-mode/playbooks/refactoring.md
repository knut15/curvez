# 리팩터링 (refactoring)

**동작은 그대로 두고 구조만 바꾼다. 동작을 먼저 고정하고, 나아졌는지 숫자로 본다.**

1. 동작을 고정한다. 바꿀 코드의 지금 동작을 덮는 테스트가 있는지 보고, 없으면 먼저 쓴다(`curvez-qa`). 모든 테스트가 통과하는 상태에서 시작한다
2. `curvez-structure-reviewer` 로 지금의 구조 지표(중복, 순환, 경계 위반 수)를 잰다
3. 목표 구조를 적는다. 무엇을 어디로 옮기고 무엇을 없애는가. 레이어 경계가 바뀌면 `curvez-architect` 라운드를 연다
4. 먼저 뺀다. 쓰이지 않는 코드와 중복을 걷어낸 뒤에 옮긴다
5. 작은 단계로 옮긴다. 단계마다 1번 테스트가 모두 통과해야 다음 단계로 간다. 구현은 지시서로 넘긴다
6. 1번 테스트 전부와 `quality-gate` 를 돌린다
7. 2번과 같은 방법으로 구조 지표를 다시 잰다. 나아지지 않았으면 되돌리고 그 사실을 보고한다
8. `shipping` 플레이북으로 넘어간다

보고: 전후 구조 지표, 테스트 수치, 되돌린 단계와 이유
