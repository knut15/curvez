디자인 스킬은 서로 겹친다. supanova 4종과 taste 13종은 폰트·간격·그림자·금지 목록을 각자 소유하고,
둘 다 "랜딩을 만든다"를 자기 일이라고 말한다. 어느 쪽이 뜰지는 발화 문구에 달려 있어 예측할 수 없다.

이 스킬은 그림을 그리지 않는다. **누가 그릴지와 무엇이 값의 정본인지만 정한다.**

## 언제 이 스킬을 쓰는가

- 디자인·UI 작업 지시를 받았는데 어느 스킬이 맡을지 갈릴 때
- supanova 와 taste 가 같은 발화에 반응할 때
- 스킬의 기본값(폰트·아이콘·모션 강도)이 프로젝트에 이미 정해진 값과 부딪힐 때
- 리디자인 요청이 들어왔는데 대상이 단독 HTML 인지 앱 화면인지 불분명할 때
- 이미지·모션·토큰 중 무엇부터 정해야 하는지 순서가 안 잡힐 때

## 언제 쓰지 않는가

- 화면 구조·토큰·컴포넌트 스펙을 **값으로 확정**할 때 → `wireframe-spec` 을 쓴다. 이 스킬은 담당만 정한다
- 확정된 스펙으로 코드를 쓸 때 → `nextjs-implementation` 을 쓴다
- 이징·지속 시간 등 모션 값을 정할 때 → `motion-standards` 를 쓴다
- 레이어 경계·폴더 구조를 정할 때 → `architecture-setup` 을 쓴다
- 담당이 이미 명백할 때 — 사용자가 스킬 이름을 직접 불렀고 그 스킬의 출력 형태가 프로젝트와 맞으면 그냥 그것을 쓴다

**이유:** 이 스킬까지 매번 거치면 판정 한 줄을 얻으려고 문서 하나를 더 읽는다. 갈리지 않는 일에는
비용만 든다. 갈리는 순간에만 부른다.

## 1. 출력 형태로 먼저 가른다 — 가장 강한 판정자

**다른 어떤 신호보다 이것이 먼저다.** 스킬이 전제하는 산출물이 프로젝트와 다르면 그 스킬의 규칙은
절반이 무효가 된다.

| 만들 것                                           | 담당                            |
| ------------------------------------------------- | ------------------------------- |
| 빌드 없이 브라우저로 여는 **단독 HTML 한 장**     | `supanova-design-engine`        |
| 프레임워크 앱 안의 화면(`.tsx`, 라우트, 컴포넌트) | `design-taste-frontend` (taste) |
| claude.ai 에 올리는 **아티팩트**                  | `artifact-design` (내장)        |
| 값만 확정하는 **문서**(`.curvez/design/`)         | `wireframe-spec`                |
| 이미지·영상 **생성**                              | `higgsfield-*`                  |

**supanova 를 앱 코드에 쓰지 마라.**
**이유:** 그 스킬은 "All output is standalone HTML. No build tools, no bundlers, no frameworks" 를
전제로 CDN Tailwind·Iconify Solar·picsum 플레이스홀더를 지시한다. Next.js 앱에 그대로 들어오면
번들러가 있는 프로젝트에 CDN 스크립트가 섞이고, shadcn 이 이미 쓰는 아이콘 세트와 충돌하고,
실제 자산이 있는 자리에 더미 이미지가 들어간다. 구조만 뽑아 쓰기도 어렵다 — 그 전제가 문서 전반에 깔려 있다.

**taste 를 단독 HTML 한 장에 쓰지 못할 이유는 없다.** 프레임워크를 전제하지 않는다. 다만 supanova 는
그 형태를 위해 만들어졌으므로 단독 HTML 이면 supanova 가 먼저다.

## 2. 작업 성격으로 두 번째로 가른다

출력 형태가 같을 때만 본다.

| 성격                        | 단독 HTML                  | 앱 화면                              |
| --------------------------- | -------------------------- | ------------------------------------ |
| 새로 만든다                 | `supanova-design-engine`   | `design-taste-frontend`              |
| 이미 있는 것을 끌어올린다   | `supanova-redesign-engine` | `redesign-existing-projects` (taste) |
| 시안 이미지를 코드로 옮긴다 | `image-to-code` (taste)    | `image-to-code` (taste)              |
| 스타일 방향이 정해져 있다   | 아래 3절                   | 아래 3절                             |

**리디자인은 반드시 감사부터 한다.** 두 리디자인 스킬 모두 "audit-first" 를 요구한다. 감사 없이
고치면 무엇이 원래 의도였고 무엇이 사고였는지 구분하지 못한 채 둘 다 지운다.

## 3. 스타일 프리셋은 요청이 있을 때만 얹는다

taste 는 스타일별 스킬을 따로 갖는다. **부르지 않았으면 얹지 마라.**

| 사용자가 말한 것                  | 얹을 것                   |
| --------------------------------- | ------------------------- |
| "브루탈리즘", "raw", "industrial" | `industrial-brutalist-ui` |
| "미니멀", "editorial", "정갈하게" | `minimalist-ui`           |
| "부드럽게", "soft", "따뜻하게"    | `soft` 계열               |
| 아무 말 없음                      | **아무것도 얹지 않는다**  |

**이유:** 프리셋은 팔레트·타이포·모션을 통째로 바꾼다. 요청 없이 얹으면 프로젝트가 이미 확정한
토큰과 정면으로 부딪히고, 그 충돌은 화면에서만 드러난다.

## 4. 값의 정본 — 스킬은 값을 만들지 않는다

충돌이 나면 위에서부터 이긴다. 예외 없다.

1. `.curvez/design/tokens.md` — 프로젝트가 확정한 값
2. 프로젝트 코드의 실제 값 (`globals.css` 의 CSS 변수, `components.json`)
3. `.curvez/architecture.md` 의 경계 규칙
4. 스킬의 기본값

구체적으로 갈리는 지점은 아래가 전부다.

| 항목        | 스킬이 요구하는 것                             | 프로젝트에 값이 있으면               |
| ----------- | ---------------------------------------------- | ------------------------------------ |
| 폰트        | supanova: Pretendard 고정 · taste: 브리프 기반 | 프로젝트 폰트를 쓴다                 |
| 아이콘      | supanova: Iconify Solar 전용                   | 이미 쓰는 세트를 쓴다(shadcn=lucide) |
| 이미지      | supanova: picsum 플레이스홀더                  | 실제 자산. 없으면 `higgsfield-*`     |
| 색·간격     | 각 스킬의 팔레트·스케일                        | `tokens.md` 의 토큰 이름으로만       |
| 모션 강도   | supanova: `MOTION_INTENSITY: 6`                | `motion-standards` 의 빈도 관문      |
| 출력 완결성 | 양쪽에 같은 스킬이 있다                        | 아래 5절                             |

**스킬이 새 토큰을 만들려 하면 멈춘다.** 값이 필요하면 `wireframe-spec` 으로 돌아가 `tokens.md` 에
먼저 적고, 코드에서는 그 이름으로 참조한다.
**이유:** 스킬이 만든 값은 문서에 남지 않는다. 다음 사람이 스펙을 읽고 만든 화면과 실제 화면이
갈라지고, 어느 쪽이 맞는지 판정할 근거가 사라진다.

## 5. 중복 스킬은 한쪽만 쓴다

같은 일을 하는 스킬이 양쪽에 있다. **둘 다 부르지 마라** — 지시가 두 벌 들어와 서로를 덮는다.

| 하는 일        | supanova                     | taste                        | 쓸 것                  |
| -------------- | ---------------------------- | ---------------------------- | ---------------------- |
| 출력 잘림 방지 | `supanova-full-output`       | `full-output-enforcement`    | **taste** 쪽           |
| 고급 시각 규칙 | `supanova-premium-aesthetic` | `high-end-visual-design`     | 1절에서 고른 계열의 것 |
| 리디자인       | `supanova-redesign-engine`   | `redesign-existing-projects` | 1절에서 고른 계열의 것 |

**출력 잘림 방지만 taste 로 고정하는 이유:** 그것 하나는 출력 형태와 무관한 규칙이라 계열을 따를
이유가 없다. taste 쪽은 플러그인이라 `claude plugin update` 로 갱신되고, supanova 쪽은 로컬 사본이라
낡아도 알 방법이 없다.

## 6. 판정 절차

1. **출력 형태를 확인한다.** 단독 HTML 인가, 앱 코드인가, 아티팩트인가, 문서인가. 모르면 묻는다 — 추측하지 않는다
2. **1절 표에서 담당을 고른다.** 여기서 계열(supanova / taste)이 정해진다
3. **2절로 성격을 가른다.** 새로 만들기인가 리디자인인가
4. **사용자가 스타일을 말했으면** 3절에서 프리셋 하나를 얹는다. 안 말했으면 얹지 않는다
5. **4절 우선순위를 선언한다.** 프로젝트에 이미 있는 값 목록을 한 줄로 적고 시작한다
6. **판정 결과를 한 줄로 남긴다.** "단독 HTML · 새로 만들기 · 프리셋 없음 → supanova-design-engine, 값은 프로젝트 토큰 우선"

**판정 없이 두 계열을 섞지 마라.**
**이유:** 두 스킬의 금지 목록이 서로를 부정한다. supanova 는 `ease-in-out` 을 금지하고 Iconify 를
강제하는데, 그 규칙이 lucide 를 쓰는 앱에 들어오면 지킬 수도 어길 수도 없는 지시가 된다.
어느 쪽도 만족시키지 못하는 결과가 나온다.

## 7. 이 프로젝트에서 이미 확정된 것

`handwork` 기준이다. 다른 프로젝트에서는 그 프로젝트의 `.curvez/` 를 읽는다.

|           | 값                                                                |
| --------- | ----------------------------------------------------------------- |
| 출력 형태 | Next.js 앱 → **taste 계열**                                       |
| 폰트      | Pretendard 가변 (`next/font/local`)                               |
| 아이콘    | shadcn 기본 lucide                                                |
| 색·반경   | `globals.css` 의 shadcn 토큰 + `--brand-*`                        |
| 모션      | `motion-standards` (빈도 관문 → 이징 → 지속 시간)                 |
| 이미지    | `public/brand/` 의 실제 자산. 새로 필요하면 `higgsfield-generate` |

## 완료 기준

- [ ] 출력 형태를 확인했고, 모르면 묻고 시작했다. 추측 0건
- [ ] 계열을 하나만 골랐다. supanova 와 taste 를 같은 작업에 섞은 곳 0곳
- [ ] 스타일 프리셋은 사용자가 말했을 때만 얹었다
- [ ] 값의 출처를 선언했고, 스킬 기본값이 프로젝트 값을 덮은 곳 0곳
- [ ] 새로 만든 토큰이 있으면 `tokens.md` 에 먼저 적혔다
- [ ] 판정 결과 한 줄이 작업 시작 전에 남았다
