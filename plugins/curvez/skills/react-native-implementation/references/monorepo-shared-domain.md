# monorepo 에서 도메인을 웹과 공유할 때

`SKILL.md` 5단계에서 `profile.json` 의 `stack` 이 `monorepo` 일 때 코드를 쓰기 전에 읽는다.
`stack` 이 `react-native` 면 읽지 않아도 된다 — 공유 소비자가 없어 아래 충돌이 생기지 않는다.

시그니처 변경 시 `blocked_on` 에 `who: curvez-orchestrator` 로 넘긴다는 규칙 자체는 `SKILL.md` 에 있다.
여기는 **넘기지 않고 진행해도 되는 범위**와 **배치 방법**만 다룬다.

---

## 넘기는가 진행하는가

| 상황                                                            | 판단                                                                                                            |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 도메인 타입·함수의 시그니처를 바꿔야 한다 (인자·반환 타입·이름) | 코드를 쓰지 말고 `blocked_on` → `who: curvez-orchestrator`                                                      |
| 도메인에 새 export 를 **추가**해야 한다                         | 그것도 시그니처 변경이다. 같은 방식으로 넘긴다                                                                  |
| 도메인이 노출한 것을 그대로 쓰기만 한다                         | 진행한다. 읽기는 충돌하지 않는다                                                                                |
| 도메인이 플랫폼 API 를 필요로 한다                              | 도메인은 포트만 두고 어댑터를 `paths.mobile` 에 둔다 (아래 참조). 포트가 아직 없으면 시그니처 추가이므로 넘긴다 |
| 웹과 모바일에서 동작이 갈리는 로직이다                          | 공유하지 않는다. 각 스택에 따로 둔다                                                                            |

**동작이 갈리는 로직을 억지로 공유하지 마라.**
**이유:** 공유하려면 분기 조건이 도메인 안으로 들어가야 하고, 그 순간 도메인이 "어느 플랫폼에서 실행 중인가"를
알게 된다. 도메인을 프레임워크에서 분리한 효과가 사라지고, 이후 분기 하나가 추가될 때마다 도메인이 두 스택의
UI 사정을 따라다닌다.

---

## 포트와 어댑터 배치

도메인은 **인터페이스만** 선언하고 구현체는 각 스택이 갖는다.

```
packages/domain/            (paths.domain — 소유자 없음, 읽기만)
  ports/TokenStore.ts       인터페이스만. import 는 타입뿐

apps/mobile/                (paths.mobile — 이 스킬의 쓰기 범위)
  infrastructure/ExpoTokenStore.ts   expo-secure-store 구현체
```

- 어댑터는 `paths.mobile` 아래에 둔다. 도메인 쪽에 두면 도메인이 `expo-*` 를 참조하게 된다
- 주입은 화면이 아니라 앱 진입점(프로바이더·컨테이너)에서 한 번 한다. 화면마다 주입하면 테스트에서 화면 수만큼 목을 만들어야 한다
- 어댑터 파일명에 플랫폼을 드러낸다(`Expo*`, `Native*`). 웹 어댑터와 이름이 같으면 import 를 잘못 바꿔도 타입이 통과한다

## 공유 코드에서 금지되는 것

`paths.domain` 아래 코드가 참조하면 안 되는 것들이다. 검증은 `SKILL.md` 의 `## 금지 import` 파싱이 담당한다.

| 금지                                              | 이유                                                        |
| ------------------------------------------------- | ----------------------------------------------------------- |
| `react-native`, `expo-*`, `@react-navigation/*`   | Next.js 서버 번들에 네이티브 모듈이 들어가 웹 빌드가 깨진다 |
| `window`, `document`, `localStorage`, `navigator` | RN 런타임에 없다. 타입은 통과하고 앱 실행 중에 크래시한다   |
| `next/*`, `next/navigation` 등                    | 모바일 번들에 웹 프레임워크가 끌려 들어간다                 |
| Node 전용 모듈 (`fs`, `path`)                     | Metro 번들러가 해석하지 못한다                              |

**웹 전역 참조가 특히 위험한 이유:** `window` 는 타입 정의가 `lib.dom.d.ts` 에서 전역으로 오므로
모노레포 tsconfig 하나에 `dom` 이 들어 있으면 도메인 코드에서 써도 **타입 체크가 통과한다.**
검출 지점이 컴파일이 아니라 실기기 실행이라 발견이 가장 늦고, 그때는 이미 여러 화면이 그 코드를 쓰고 있다.

## 빌드가 깨질 때

공유 패키지는 트랜스파일 대상에 포함돼야 한다. 빌드 설정(트랜스파일 목록·번들러 alias·tsconfig paths)을
임의로 고치지 말고 `blocked_on` 에 `who: curvez-architect` 로 넘긴다.

**이유:** 빌드 설정은 두 스택이 함께 쓰는 파일이라 소유자가 이 스킬이 아니다.
한쪽 사정으로 고치면 다른 스택의 빌드가 다음 실행에서 깨지고, 원인이 자기 변경이 아닌 것처럼 보인다.
