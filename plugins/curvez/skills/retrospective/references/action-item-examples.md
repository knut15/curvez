# 고칠 위치 지목 예시

`SKILL.md` 5단계에서 "이 정도면 고칠 위치로 인정되나" 가 갈릴 때 읽는다.

기준은 하나다 — **다음 담당자가 이 문장만 보고 파일을 열어 그 자리를 바로 고칠 수 있는가.**
파일 경로 + 섹션 헤딩 + 그 섹션에서 무엇이 되는지, 셋이 다 있어야 인정된다.

---

## 인정되지 않는 것

| 쓴 것                                                    | 왜 안 되나                                                                   |
| -------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **고칠 위치:** 핸드오프 규약                             | 파일이 없다. `agent-contract` 스킬인지 스키마 JSON 인지 정의 파일인지 모른다 |
| **고칠 위치:** `curvez-qa.md`                            | 경로가 없고 섹션이 없다. 500줄 문서에서 어디를 고칠지 다시 찾아야 한다       |
| **고칠 위치:** `plugins/curvez/agents/curvez-qa.md` 전반 | "전반" 은 위치가 아니다                                                      |
| **고칠 위치:** 팀 전체의 검증 문화                       | 파일이 아니다. 이런 항목은 액션 아이템이 아니라 `## 어긋난 지점` 에 남긴다   |

**이유:** 위치가 흐리면 오케스트레이터가 승인 요청을 만들 때 "무엇을 고치는지" 를 사용자에게
설명할 수 없다. 설명 못 하는 항목은 승인되지 않고, 승인되지 않은 액션 아이템은 다음 라운드에
그대로 재발한다.

## 인정되는 것

```markdown
- **고칠 위치:** `plugins/curvez/agents/curvez-qa.md` 의 `## 품질 자체 검증`
- **고칠 위치:** `plugins/curvez/skills/quality-gate/SKILL.md` 의 `## 완료 기준`
- **고칠 위치:** `plugins/curvez/agents/curvez-orchestrator.md` 의 `## 팀 통신 프로토콜` 표
```

지목 직후에 실재를 확인한다. 확인 없이 쓴 경로는 검증 명령에서 `MISSING` 으로 잡힌다.

```bash
grep -n '^## 품질 자체 검증' plugins/curvez/agents/curvez-qa.md
```

**지목한 파일이 실재하지 않으면 그 항목을 액션 아이템에서 내린다.** 비슷한 이름의 다른 파일로
바꿔 달지 마라. `## 확인 불가` 에 "지목 대상 파일 없음: `<경로>`" 로 남긴다.
**이유:** 존재하지 않는 위치를 지목한 항목은 실행 단계에서 조용히 버려진다. 회고에는 7건이
올라갔는데 실제로 고쳐진 것은 5건이고, 그 차이가 어디서 생겼는지 아무도 모른 채 다음 회고가
같은 항목을 다시 올린다.

---

## 어떻게 고치나 — 세 유형

5단계 판정표의 세 결과가 각각 다른 수정 형태로 간다.

### 공백 → 문장을 추가한다

```markdown
- **왜 어긋났나:** 두 워커가 같은 파일을 소유한 상태로 병렬 실행됐는데,
  소유권이 겹칠 때 무엇을 하라는 문장이 정의에 없다
- **고칠 위치:** `plugins/curvez/agents/curvez-orchestrator.md` 의 `## 판단 기준`
- **어떻게 고치나:** 병렬 판정표에 "소유 경로가 겹치면 병렬을 포기하고 순차로 강등한다" 행을 추가한다
```

### 모호함 → 서술을 조건문으로 바꾼다

문장이 있는데 그 상황에 적용된다는 것이 읽는 즉시 안 보였을 때다.
서술문("검증을 충실히 한다")을 조건문("`verification` 이 비면 `done` 을 쓸 수 없다")으로 교체한다.

```markdown
- **어떻게 고치나:** `## 입출력 프로토콜` 의 "검증 결과를 남긴다" 를
  "`verification[].result` 가 수치·개수가 아니면 `status` 를 `partial` 로 낮춘다" 로 교체한다
```

**이유:** 서술문은 읽는 쪽이 "나는 충실히 했다" 고 판정할 여지를 남긴다. 조건문은 판정 주체를
문서로 옮긴다.

### 무력함 → 검증 명령을 추가한다

규약이 명확했는데 안 지켜진 것이 반복될 때다. **문장을 한 번 더 쓰지 마라.**

```markdown
- **고칠 위치:** `plugins/curvez/agents/curvez-qa.md` 의 `## 품질 자체 검증`
- **어떻게 고치나:** `grep -L '"verification"' .curvez/handoff/*.json` 로
  verification 이 빠진 핸드오프를 세는 명령과 "출력 0건" 체크박스를 추가한다
- **검증 방법:** 다음 라운드 종료 후 같은 명령의 출력이 0건인지 본다
```

**이유:** 지켜지지 않는 규칙에 같은 규칙을 다시 쓰는 것은 아무것도 바꾸지 않는다.
사람이 읽고 지키는 규칙과 기계가 잡는 규칙은 강제력이 다르다.

## 반복성 판정이 갈리는 사례

| 관찰                                                                            | 판정          | 근거                                                                                                          |
| ------------------------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------- |
| `curvez-nextjs` 와 `curvez-react-native` 가 같은 토큰 파일이 없다고 각각 막혔다 | 반복          | 서로 다른 에이전트가 같은 지점에서 막혔다. 개인이 아니라 규약이 공통 원인이다                                 |
| 한 에이전트가 `verification` 을 빼먹은 핸드오프 1건                             | 일회성        | 규약에 이미 있고 1건이다. 기록만 하고 다음 회고에서 재발하면 승격한다                                         |
| 설계 결정이 구현 중 뒤집혔고 후행 3개 산출물이 그 위에 쌓였다                   | 반복으로 취급 | 1건이지만 재발 시 되돌리기 비용이 산출물 전체다. 빈도가 아니라 기댓값으로 판정한다                            |
| WebFetch 403 으로 조사 1건 실패                                                 | 일회성        | 외부 요인. 규약으로 막을 수 없다. 재시도 상한이 정의에 없었다면 그것만 액션 아이템                            |
| 이전 회고의 A3 과 같은 항목이 또 났다                                           | 반복 + 승격   | 우선순위를 한 단계 올리고, 이전에 지목한 위치가 왜 효과가 없었는지를 쓴다. **같은 위치를 다시 지목하지 마라** |

마지막 행의 **이유:** 같은 위치를 다시 지목했다는 것은 그 위치가 원인이 아니었다는 뜻이다.
효과 없던 수정을 반복하면 회고가 두 번 돌아도 실패는 세 번째로 이어진다.
