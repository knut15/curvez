# 플랫폼별로 값을 확정하는 법

`SKILL.md` 절차 4단계에서 읽는다. `stack` 이 `monorepo` 이거나, 한 화면·컴포넌트의 값이
웹과 모바일에서 갈릴 때 필요하다. `stack` 이 한쪽뿐이고 갈리는 줄이 없으면 읽지 않아도 된다.

두 플랫폼의 **차이 항목 목록과 그 이유**는 `plugins/curvez/agents/curvez-designer.md` 의
`### Next.js 와 React Native 차이` 표가 정본이다. 여기는 **그 차이를 스펙 문서에 어떻게 배치할지**만 다룬다.

---

## `platform:` 값을 고른다

값은 `both` / `nextjs` / `rn` 세 개뿐이다. `react-native` 로 쓰지 마라.

| `profile.json` 의 `stack` | 쓸 수 있는 `platform:` 값                                              |
| ------------------------- | ---------------------------------------------------------------------- |
| `nextjs`                  | `nextjs` 만                                                            |
| `react-native`            | `rn` 만                                                                |
| `monorepo`                | `both` 가 기본. 한쪽에만 존재하는 화면·컴포넌트에만 `nextjs` 또는 `rn` |

`monorepo` 에서 `both` 를 기본으로 두는 이유: 처음부터 둘로 나눠 쓰면 공통이어야 할 것까지
갈라지고, 나중에 합칠 때 어느 쪽이 원본인지 판정할 근거가 없다.

---

## 파일을 나눌 것인가, 줄을 나눌 것인가

| 상황                                                                     | 판단                                                                                                                         |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 영역 구성·순서·목표가 같고 값만 다르다 (간격, 브레이크포인트, 호버 유무) | **한 파일**. `platform: both` 로 두고 `## responsive` 와 `## platform-diff` 에서 갈리는 줄만 `nextjs:` / `rn:` 접두로 나눈다 |
| 영역 자체가 다르다 (웹은 사이드바 + 본문, 모바일은 하단 탭 + 단일 열)    | **파일을 나눈다**. `<screen-id>.web.md` / `<screen-id>.native.md` 가 아니라 화면 ID 자체를 다르게 준다                       |
| 한쪽 플랫폼에만 존재하는 화면                                            | **파일 하나**, `platform:` 을 `nextjs` 또는 `rn` 으로 고정                                                                   |

**같은 줄을 두 플랫폼에 복사해 쓰지 마라.**
**이유:** 복사된 줄은 한쪽만 고쳐진다. 그 순간 두 플랫폼이 서로 다른 값을 정본이라고 주장하고,
스펙만 봐서는 어느 쪽이 최신인지 알 수 없다. 갈리지 않는 값은 `both` 줄 한 개로만 존재해야 한다.

---

## `nextjs` 에서 값으로 확정할 것

체크리스트다. 하나라도 비면 구현자가 그 자리에서 만들어 낸다.

- [ ] `route(nextjs)` — 실제 파일 라우트 경로. 동적 구간은 `[id]` 형태로 (예: `/orders/[id]`)
- [ ] 브레이크포인트 **숫자** — "모바일/데스크톱" 이 아니라 `640` / `768` / `1024` 처럼 값으로. 각 구간에서 열 수와 비율까지
- [ ] `hover` 상태 — 정의 필수. 색은 토큰 접미사로 (`--color-accent-primary-hover`)
- [ ] `focus-visible` 링 — 두께·offset·색 토큰. 브라우저 기본에 맡기지 마라
- [ ] 터치 타깃 — **24x24 CSS px** 이상 + 인접 요소와 8px 간격
- [ ] 폰트 단위 — `rem` (루트 16px 기준)
- [ ] 스크롤 — 문서 스크롤인지 컨테이너 스크롤인지
- [ ] 다크 모드 진입 — `prefers-color-scheme` 만인지, 사용자 토글도 두는지
- [ ] 뒤로가기 — 브라우저 히스토리에 맡길 것인지, 화면 안에 뒤로 버튼을 둘 것인지

---

## `rn` 에서 값으로 확정할 것

- [ ] `route(rn)` — 네비게이터에 등록할 **화면 이름**(예: `OrderDetail`). URL 경로가 아니다
- [ ] 네비게이터 종류 — 스택인지 탭인지, 헤더 좌측 back 유무, 뒤로 제스처 허용 여부
- [ ] 터치 타깃 — **44x44 pt 이상, 예외 없음**
- [ ] `hover` 를 정의하지 않는다. 대신 `pressed` 를 정의한다
  - **이유:** RN 에는 포인터 호버가 없다. `hover` 가 적힌 스펙을 받으면 구현자는 존재하지 않는 상태를 만들려다 결국 임의로 해석한다
- [ ] 포커스 링 대신 **스크린리더 포커스 순서**만 정의한다 (`focus-order` 는 그대로 쓴다)
- [ ] 폰트 단위 — 단위 없는 숫자(dp/pt). `allowFontScaling` 을 켤지 끌지 명시
- [ ] 안전 영역 — 상단 notch, 하단 홈 인디케이터를 어느 영역이 흡수하는가
- [ ] 가로 모드 — 지원 여부를 명시한다. "미지원" 도 확정값이다
- [ ] 스크롤 컨테이너 — `ScrollView` 인지 `FlatList` 인지. 무한 스크롤이면 페이지 크기 숫자까지
- [ ] 다크 모드 진입 — OS `Appearance` 를 따를지, 앱 내 토글이 있는지 (요구사항에서 확인)

**브레이크포인트를 쓰지 마라.**
**이유:** RN 화면 폭은 기기별로 연속이라 임계값이 의미를 갖지 못한다. 웹 브레이크포인트를
그대로 가져오면 특정 기기에서만 레이아웃이 튀고, 재현 조건을 아무도 특정하지 못한다.

---

## `monorepo` 에서 토큰은 한 벌만 둔다

`tokens.md` 는 **하나만** 만든다. 플랫폼별 토큰 파일을 나누지 않는다.

- 색·radius·타이포 스케일은 그대로 공유한다
- 간격 값은 숫자를 공유하고 단위만 플랫폼에서 해석한다 (`--space-2 = 8` → web `8px`, RN `8`)
- 플랫폼 한쪽에만 있는 토큰(예: `--color-focus-ring`)도 같은 표에 두고 `용도` 칸에 `nextjs 전용` 이라고 적는다

**이유:** 토큰 표를 둘로 나누면 같은 이름이 양쪽에서 다른 값을 갖는 순간을 아무도 못 잡는다.
표가 하나면 그 충돌이 같은 행에서 눈에 보인다.

## 자주 나오는 실패

| 증상                                          | 원인                                                                                   | 고칠 곳                                                                                   |
| --------------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| RN 구현자가 `hover` 를 구현하려 한다          | 컴포넌트 스펙이 `platform: both` 인데 `## states` 에 `hover` 만 있고 `pressed` 가 없다 | `## states` 에 `pressed` 행 추가, `hover` 행에 `(nextjs 전용)` 표기                       |
| 데스크톱 버튼이 과하게 크다                   | 44pt 규칙을 웹에도 적용했다                                                            | `a11y:target` 을 플랫폼별로 나눈다 (web 24px, rn 44pt)                                    |
| 모바일에서 하단 CTA 가 홈 인디케이터에 가린다 | 안전 영역이 스펙에 없다                                                                | `## responsive` 의 `rn:` 줄에 하단 안전 영역 패딩 명시                                    |
| 웹과 모바일 화면 이름이 어긋난다              | `route(nextjs)` 만 적고 `route(rn)` 을 비웠다                                          | 두 줄 모두 채운다. 한쪽에만 있는 화면이면 `platform:` 을 고정하고 없는 줄에 사유를 적는다 |
